**Customermates n’est pas un CRM open source au sens de l’OSI : il est source-available.** Le code est public, sous Sustainable Use License (fair-code) : l’usage interne, non commercial ou personnel est gratuit, la revente et l’hébergement pour des tiers ne sont pas permis. Si vous cherchez un CRM open source, des alternatives sont comparées plus bas.

Customermates est un CRM pour les petites équipes : contacts, organisations, affaires et tâches dans des listes que vous configurez vous-même, avec REST, des webhooks et MCP pour les agents IA. Le code est public sur GitHub. Démarrez dans le cloud géré avec un essai Pro gratuit et sans carte bancaire, ou exploitez la Community Edition gratuite en auto-hébergement avec Docker Compose et PostgreSQL.

**Pourquoi la relance est une fonction du cloud.** Le travail de relance, les conversations LinkedIn et e-mail sur chaque client et les réponses rédigées par Mate, tourne sur Customermates Cloud dès Pro. Le cœur auto-hébergé est le même CRM, avec enregistrements, vues, REST, webhooks et MCP pour votre propre client IA, sans boîte de réception et sans Mate. Essayez d’abord le cloud si ce sont les relances rédigées qui vous intéressent, et auto-hébergez quand le contrôle de l’endroit où tournent les données compte davantage.

## Customermates est-il open source ?

Non, pas au sens de l’Open Source Initiative (OSI) : une licence open source ne peut pas limiter l’usage, et la Sustainable Use License le fait. Le code de Customermates en dehors de `ee/` est publié sous Sustainable Use License 1.0, la licence que n8n utilise aussi. Ce modèle s’appelle « fair-code » : le code source est lisible, mais l’usage commercial est limité.

Ce que vous pouvez faire : utiliser et modifier le code pour les besoins internes de votre entreprise, auto-héberger la Community Edition gratuite, l’utiliser pour les clients de votre propre agence (ils reçoivent des résultats, pas un accès) et la redistribuer gratuitement, sans but commercial. Ce que vous ne pouvez pas faire : la revendre, l’héberger comme service pour des tiers, ou retirer les mentions de licence et la marque. Facturer à un client une instance déployée pour lui demande une licence Enterprise ; l’intégration dans un autre produit et la marque blanche se font par accord, la marque Customermates restant visible.

Le code de `ee/` relève de la Customermates Commercial License et n’est pas sous la Sustainable Use License. Les conditions exactes figurent dans [`LICENSE.md`](https://github.com/customermates/customermates/blob/main/LICENSE.md), [`ee/LICENSE.md`](https://github.com/customermates/customermates/blob/main/ee/LICENSE.md) et la FAQ [`LICENSING.md`](https://github.com/customermates/customermates/blob/main/LICENSING.md). Lisez ces fichiers avant de modifier ou de redistribuer le code (informations de licence vérifiées le 16 novembre 2026).

Le CRM lui-même fonctionne de la même façon dans les deux cas : des listes pour les personnes, les organisations, les affaires ou les tâches, des champs personnalisés, des vues tableau, Kanban et calendrier, des tableaux de bord, des rôles et un journal d’activité. Les clients IA externes comme Claude ou ChatGPT passent par le [serveur MCP](/docs/mcp), avec les permissions de l’utilisateur sous lequel ils sont connectés.

Le cloud convient si vous voulez travailler dès aujourd’hui avec de vrais clients sans exploiter de serveurs. La base de données de production principale est configurée dans la région AWS de Francfort ; c’est un paramètre choisi, pas une certification ni une garantie de résidence des données. La région, les fournisseurs et les garanties sont détaillés sur la page [CRM cloud](/features/cloud-crm).

L’auto-hébergement convient si votre équipe sait exploiter Docker et PostgreSQL et si les fonctions de Starter suffisent. Ce qui fonctionne exactement et ce qui manque est décrit sur la page [CRM auto-hébergé](/features/self-hosted).

## Comment exploiter Customermates en auto-hébergement

Le [guide d’auto-hébergement](/docs/self-hosting) décrit la marche à suivre pas à pas : récupérez `docker-compose.yml` et `.env` depuis le dépôt avec `curl`, renseignez le mot de passe, le secret, `BASE_URL` et l’envoi des e-mails, puis lancez `docker compose up -d`. L’image est construite pour `linux/amd64` et `linux/arm64` et applique les migrations de base de données en attente à chaque démarrage.

Une instance auto-hébergée accueille autant d’espaces de travail que vous voulez, ne compte aucun siège et ne facture rien. En contrepartie, les mises à jour, les sauvegardes, les restaurations testées, TLS et la supervision vous incombent. L’auto-hébergement ne rend pas à lui seul un CRM conforme au RGPD : la configuration, les fournisseurs connectés, les contrats et l’exploitation restent sous votre responsabilité.

## Ce pour quoi Customermates n’est pas conçu

Customermates est un CRM ciblé, pas une suite de gestion. Il n’y a ni devis ni factures, ni séquences ni e-mails de masse, ni téléphonie ni SMS, ni applications mobiles natives, ni certification de conformité. Le SSO et la marque blanche ne sont pas développés. Si vous avez besoin d’un ERP, de comptabilité ou d’automatisation marketing dans le même système, une suite plus large vous conviendra mieux.

Si vous comparez plusieurs CRM open source côte à côte, notre [comparatif des CRM open source](/blog/open-source-crm) donne des critères sur la licence, le déploiement et l’effort d’exploitation. Des comparaisons directes couvrent [SuiteCRM](/compare/suitecrm-alternative), [EspoCRM](/compare/espocrm-alternative) et [Twenty](/compare/twenty-alternative).

## Questions fréquentes

<Faq>
<FaqItem question="Customermates est-il un CRM open source gratuit ?">
Pas au sens de l’OSI : il est source-available. L’auto-hébergement de la Community Edition est gratuit pour votre usage interne, Customermates ne facture rien ; vous ne payez que votre propre infrastructure, vos fournisseurs et votre temps d’exploitation. Le cloud géré coûte à partir de [[commercial.price.starter.monthly]] par utilisateur et par mois, facturé mensuellement, et commence par un essai gratuit de [[commercial.trial.days]] jours.
</FaqItem>

<FaqItem question="Ai-je besoin d’une carte bancaire pour l’essai ?">
Non. L’essai démarre avec votre premier espace de travail cloud et inclut les fonctions Pro. La facturation ne commence qu’à la validation du paiement.
</FaqItem>

<FaqItem question="Quelle est la différence entre un CRM open source et un CRM auto-hébergé ?">
Open source décrit une licence approuvée par l’OSI : vous pouvez utiliser, modifier et redistribuer le code sans limite d’usage. Auto-hébergé décrit l’exploitation : l’application et la base de données tournent sur votre infrastructure. Customermates est auto-hébergeable sans être open source : son code est source-available, sous Sustainable Use License. Vous l’utilisez gratuitement en interne, vous pouvez aussi choisir le cloud géré, mais vous ne pouvez pas le revendre ni l’héberger pour des tiers.
</FaqItem>

<FaqItem question="Puis-je utiliser l’IA avec le CRM auto-hébergé ?">
Oui, via [MCP](/docs/mcp) avec un client IA externe et un fournisseur que vous choisissez et payez. Mate, les crédits IA hébergés et la configuration IA sont réservés au cloud.
</FaqItem>

<FaqItem question="Puis-je passer plus tard du cloud à l’auto-hébergement ?">
Oui, les enregistrements passent sous forme de classeurs XLSX, une liste à la fois. Pour les pièces jointes ou des volumes plus importants, prévoyez une migration via l’API REST. Il n’existe pas de transfert du compte complet.
</FaqItem>
</Faq>
