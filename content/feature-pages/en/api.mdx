Customermates is a CRM with an open REST API on every plan, from Starter at [[commercial.price.starter.monthly]] per user per month, and in the free self-hosted edition. You authenticate with an API key in the `x-api-key` header, the full schema is an OpenAPI 3.1 document at `/api/v1/openapi`, and [[derived.webhooks.events.total]] webhook events tell your systems when something changes. There is no separate developer plan and no paid API add-on.

Customermates is an open-source, AI-native CRM built in Germany for small client-facing teams. The API matters to two kinds of readers: a developer who wants to sync the CRM with another system, and a team that wants an AI client such as Claude or ChatGPT to update records. The first uses REST and webhooks. The second uses the MCP endpoint, which sits on the same permissions.

## What the REST API covers

The REST API works on the five record types of the CRM: contacts, organizations, deals, services and tasks. Each one has the same set of routes, so code written for contacts works for deals with a different path segment.

| Goal | Method and path |
|---|---|
| Create one record | `POST /api/v1/<type>` |
| Create up to 100 records | `POST /api/v1/<type>/many` |
| Read one record | `GET /api/v1/<type>/{id}` |
| Search, filter, sort and page | `POST /api/v1/<type>/search` |
| Update one record | `PUT /api/v1/<type>/{id}` |
| Update up to 100 records | `PUT /api/v1/<type>/many` |
| Delete one or up to 100 records | `DELETE /api/v1/<type>/{id}` or `DELETE /api/v1/<type>/many` with `ids` |
| Read the custom columns, options and filterable fields | `GET /api/v1/<type>/configuration` |

`<type>` is `contacts`, `organizations`, `deals`, `services` or `tasks`. The base URL is the address you open Customermates at, in the cloud and on your own server. Further routes cover users (`/api/v1/users/me`, `/api/v1/users/search`), webhooks, and the inbox: threads, drafts, sending email and chat messages, activities and read-only calendars.

A few details save time on the first day:

- **Custom fields are part of the record.** Custom columns come back under `customFieldValues` as `columnId` and `value` pairs. Call `/configuration` once to map column ids to names and to see the options of a single-select column such as your deal stage.
- **Search uses a JSON body.** `POST /search` takes `searchTerm`, `filters`, `sortDescriptor` and `pagination`. `pageSize` is 5, 10, 25 or 100. Filters use the [filter syntax](/docs/filter-syntax) shared with the app and MCP.
- **Relations are arrays of ids.** Sending `[]` or `null` for `organizationIds` on a contact removes every link of that kind. Leave the field out to keep the links.
- **Bulk writes run in one transaction.** A `/many` request writes its batch together, so you split a migration of 2,000 contacts into 20 requests.

## Webhooks: let the CRM call you

A webhook sends a JSON `POST` to your URL when a subscribed event happens. Admins, and members whose role has **Manage** on **API & Webhooks**, add one under **My Company → Webhooks**: URL, events, an optional secret, optional custom headers and an optional body template. The [webhooks reference](/docs/webhooks) lists every event and payload.

- **Events:** [[derived.webhooks.events.records]] record events (created, updated and deleted for each of the five record types) plus [[derived.webhooks.events.messaging]] inbox and calendar events.
- **Changes included:** an `*.updated` payload carries the full record plus a `changes` object with the previous and current value of each field that moved. A write that changes nothing sends no event.
- **Signatures:** with a secret set, every delivery is signed with HMAC-SHA256 over the raw body.
- **Retries:** a timeout, network error, 5xx, 408, 425 or 429 is retried up to 5 times. Other 4xx answers are not retried, because a repeat would fail the same way. Each delivery has a 5 second timeout.
- **Delivery log:** **My Company → Recent Deliveries** shows status code and response message for every delivery, with a resend button.
- **Body templates:** a template replaces the standard envelope, so a chat tool or automation endpoint that expects its own JSON shape can take deliveries without middleware.

Deliveries are not strictly ordered. Two updates to the same contact a few milliseconds apart can arrive in reverse order, so key your handler on `entityId` and use the payload `timestamp`.

## How to make your first API call

<Steps>
  <Step title="Create a key">Open **My Profile → API & Connectors**, press **Add**, choose **Standard API key**, give it a name such as `ERP sync, production`, and copy the key. It is shown once. The [API keys guide](/docs/api-keys) covers expiry and rotation.</Step>
  <Step title="Read the schema">Fetch `/api/v1/openapi` from your workspace address and import it into Postman, Insomnia or a client generator. Then call `GET /api/v1/deals/configuration` to see your deal stage options and custom columns.</Step>
  <Step title="Search">Send `POST /api/v1/deals/search` with the header `x-api-key` and a body such as `{"filters":[{"field":"updatedAt","operator":"inLastDays","value":7}],"pagination":{"page":1,"pageSize":25}}` to list deals changed in the last week.</Step>
  <Step title="Write">Update one deal with `PUT /api/v1/deals/{id}`. If your user can do it in the app, the key can do it over the API.</Step>
  <Step title="Subscribe">Add a webhook for `deal.updated` with a secret, point it at your endpoint, and check the first delivery under **Recent Deliveries**.</Step>
</Steps>

A wrong, expired or deleted key gets HTTP `401`. A key whose owner was set to **Inactive** gets `403`.

## API keys and permissions

Keys belong to the user who created them and act with that user's current role. There are no separate API users and no per-key scopes, so a key cannot be limited to read-only. If an integration should only read deals, create its key under a member whose role allows only that. In Customermates Cloud that member is a paid seat like any other.

Creating keys needs **Manage** on the **API & Webhooks** row of a role. A new custom role starts without it, so out of the box only admins create keys. The same permission also opens every webhook in the workspace, which is worth knowing before you hand it out. To stop all keys of someone who leaves, set the member to **Inactive**; taking the permission away hides the page but does not stop keys that already exist.

## MCP: the API for AI clients

The MCP endpoint at `/api/v1/mcp` gives an external AI client [[derived.mcp.tools.total]] tools over the same records, inbox and webhooks. Claude and ChatGPT connect through OAuth as a custom connector; Claude Code, Codex, Cursor and Gemini use an API key. The client, its model and its subscription stay yours, and MCP calls use no Customermates hosted AI credits. The [MCP guide](/docs/mcp) lists every tool.

Mate, the assistant inside Customermates Cloud, is a separate feature. It runs on hosted AI credits and needs no API key. Self-hosted installations have MCP but no Mate.

## What the API does not do

- **No PATCH.** Updates use `PUT` on one record or on `/many`.
- **No cursor pagination and no OR across filter rules.** Page with `page` and `pageSize`. For OR, run two searches or use the `in` operator on one field.
- **No file uploads to records.** Records have no file attachments; notes hold rich text.
- **No published request quota and no rate-limit headers.** Split bulk jobs into batches of 100.
- **No CSV export endpoint and no whole-account export.** The app imports and exports XLSX, one record type at a time. Anything larger runs through your own API script.
- **No inbox and no Mate when self-hosted.** The REST record routes, webhooks and MCP work there; the messaging routes need Customermates Cloud on Pro or higher.

No backward-compatibility period is promised beyond the `/api/v1` path, so treat the current OpenAPI document as the contract and test against it.

## How other CRMs meter API access

Customermates publishes this page. The figures below come from each vendor's own documentation, checked on 8 October 2026; they change, so follow the links before you plan around them.

| CRM | API on the free or entry plan | How usage is limited |
|---|---|---|
| [HubSpot](https://developers.hubspot.com/docs/developer-tooling/platform/usage-guidelines) | Yes | Private apps on Free and Starter: 100 requests per 10 seconds and 250,000 per day per account; higher on Professional and Enterprise |
| [Pipedrive](https://www.pipedrive.com/en/features/crm-api) | Every plan includes an API token | [Daily token budget](https://pipedrive.readme.io/docs/core-api-concepts-rate-limiting): 30,000 base tokens times a plan multiplier times seats |
| [Zoho CRM](https://www.zoho.com/crm/developer/docs/api/v8/api-limits.html) | Yes, Free edition included | Credits per 24 hours: 5,000 on Free, more per user on paid editions |
| [EspoCRM](https://docs.espocrm.com/development/api/) | Yes, including the [free self-hosted edition](https://www.espocrm.com/) | API key, HMAC or basic auth through dedicated API users whose roles set what they can do |
| Customermates | Every plan and self-hosted | No published quota; bulk routes take 100 records per request |

Choose HubSpot or Zoho CRM if you want a free hosted plan with API access and your integration fits within their published call limits. Choose Pipedrive if a daily budget that grows with plan and seats suits your volume. Choose EspoCRM if you want a self-hosted open-source CRM with separate API users and their own roles. Customermates fits a small team that wants the record API, webhooks and an MCP endpoint for AI clients at the price of the CRM itself, with an AGPL core it can self-host. It does not fit if you need per-key scopes or, in Customermates Cloud, an API user that does not take a paid seat.

## What it costs

API access has no surcharge. A three-person team on Starter pays [[commercial.price.starter.monthly.seats.3]] per month and gets REST, webhooks and MCP. The same team on Pro pays [[commercial.price.pro.monthly.seats.3]] and adds the [unified inbox](/features/unified-inbox) and its messaging routes. Self-hosting the open-source edition costs nothing in licence fees; you run the server. Billing is monthly, see [pricing](/pricing). If you build flows in n8n, n8n is a separate product with its own plans; the [n8n guide](/docs/n8n) shows the HTTP Request setup.

<Faq>
<FaqItem question="What is an API in a CRM?">
It is the programmatic way into the CRM's data. Another program sends HTTP requests to read, create, update or delete contacts, deals and other records, instead of a person clicking through the screens. Webhooks are the other direction: the CRM calls your program when data changes.
</FaqItem>
<FaqItem question="Which CRM has the best API?">
There is no single answer. Check four things against your project: whether the API is on the plan you will actually buy, how calls are metered, whether webhooks include what changed, and whether there is a machine-readable spec. For a small team, an API on the entry plan with an OpenAPI document and signed webhooks usually matters more than the size of the endpoint catalog.
</FaqItem>
<FaqItem question="What is the best free CRM with API integration?">
HubSpot and Zoho CRM both have free hosted plans with metered API access, and EspoCRM offers a free self-hosted edition with a REST API. The self-hosted edition of Customermates is free open source and includes the REST API, webhooks and MCP, but no inbox and no Mate, and you run the server yourself. See [self-hosting](/features/self-hosted).
</FaqItem>
<FaqItem question="Can I limit an API key to read-only?">
No. A key has exactly the permissions of the user who owns it. Create the key under a member with a restricted role if an integration should only read.
</FaqItem>
<FaqItem question="Does the API include the inbox?">
Yes, in Customermates Cloud on Pro or higher, where users connect email, LinkedIn, WhatsApp, Instagram or Telegram. Routes cover threads, drafts, sending email and chat messages, and activities. Each request sends one message; there is no bulk send.
</FaqItem>
<FaqItem question="Do I need n8n or Zapier to use the API?">
No. Any language that can send HTTPS requests works. n8n is optional and runs separately; the [integrations overview](/features/integrations) compares REST, webhooks, MCP and n8n.
</FaqItem>
</Faq>
