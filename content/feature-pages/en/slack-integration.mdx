## What This Page Does and Does Not Claim

Customermates does not ship a Slack integration. There is no Slack app to install, no Slack settings screen in the product, and no Slack option in the connected-accounts list. The unified inbox covers email, LinkedIn, WhatsApp, Instagram, and Telegram; Slack is not one of its channels.

What Customermates does ship is the machinery an external automation tool needs to talk to Slack on your behalf: outbound webhooks on [[derived.webhooks.events.total]] record and messaging events, a versioned REST API, and an MCP endpoint. Wire those to [n8n](/docs/n8n), Make, or Zapier, add that tool's Slack node, and you get the behavior described below. The Slack side runs in your automation tool, not in Customermates.

We would rather write that down than let the page imply a product we have not built.

## What You Need

- A Customermates workspace on any tier. Webhooks and the REST API are available from Starter.
- An automation tool that can receive an HTTP request and post to Slack. [n8n](https://n8n.io/) is the one we document, self-hosted or on n8n's own cloud. It is a separate product with its own pricing; nothing about it is bundled with a Customermates subscription.
- A Slack workspace where you can authorize that tool.

## CRM-to-Slack Notifications

The pattern is always the same: Customermates fires a webhook, your automation tool receives it, formats a message, and posts it to Slack. Create the webhook under **Company → Webhooks → New** and choose the events you care about. The payload shape is documented at [Webhooks](/docs/webhooks).

**Deal change notifications.** Subscribe to `record.created` and `record.updated` for the Deals record type and post to a channel when a deal changes. Stage is a configured select field, so your workflow reads its field value from the record payload and branches on it. The same pattern works for customer-created types.

**New lead alerts.** Subscribe to `record.created` for the Contacts record type and notify the team when a record lands. Include the fields you care about and a link back to the record.

**Pipeline summary reports.** Webhooks are event-driven, so a digest is a scheduled job in your automation tool: run on a cron, query a configured measure with `POST /api/v2/reports/query`, and post the summary. The REST API is documented in the [OpenAPI spec](/docs/openapi).

**Messaging alerts.** Subscribe to `messaging.message.received` or `messaging.email.received` to route new inbound conversations into Slack. These events require the unified inbox, which is available in Customermates Cloud from Pro; Starter and self-hosted installations have no messaging events.

## Slack-to-CRM Actions

The reverse direction runs through the REST API or MCP, again driven by your automation tool.

**Create records from Slack.** A Slack shortcut or slash command triggers your workflow, which discovers the type and field IDs with `POST /api/v2/model/discover`, then calls `POST /api/v2/records/mutate` with a create mutation and an `x-api-key` header. The same contract works for the five starter types and customer-created types.

**Update records from Slack.** Call `POST /api/v2/records/mutate` with an update mutation and the record's current version. Use its link or unlink mutation to change a relationship. The MCP equivalent is `mutate_crm_record`.

**Log notes from Slack.** Update the record's configured Notes field through the same mutation API or `mutate_crm_record` MCP tool.

**Let an agent do it.** Instead of hand-building each call, point an MCP-speaking agent at `/api/v1/mcp` and let it interpret the Slack message. That is the same [[derived.mcp.tools.total]]-tool surface Claude, ChatGPT, and Gemini use.

## What This Is Not

**It is not a one-click install.** You are building and maintaining workflows in a separate tool. That is real setup work, and it is honest to say so.

**It is not included in your subscription.** Customermates does not resell, host, or bundle n8n. If your automation tool costs money, that cost is yours.

**It is not a Slack inbox.** Slack conversations do not appear in the unified inbox and are not stored as CRM messages. What you get is notifications out and API calls in.

**Nothing is rate-limit-free.** Slack, your automation tool, and the Customermates API each apply their own limits. See [messaging rate limits](/docs/messaging-rate-limits) for the parts we control.

## Why Build It This Way

**No lock-in to one integration.** The same webhook and REST surface that drives Slack drives Microsoft Teams, Discord, a data warehouse, or an internal service. We did not have to ship a Slack integration for you to have one.

**You control the signal.** Which events fire, which channels receive them, and what each message contains are decisions in your workflow, not toggles we guessed at.

**The core is inspectable.** The AGPL core CRM, webhook payloads, REST contract, and MCP tool definitions are in the repository. Self-hosting runs the core application and PostgreSQL with the Starter feature set; Slack and n8n remain external.

## Frequently Asked Questions

<Faq>
<FaqItem question="Does Customermates have a native Slack integration?">
No. There is no Slack app, no Slack channel in the unified inbox, and no Slack screen in the product. Everything on this page is built with an external automation tool against the webhook and REST surfaces.
</FaqItem>

<FaqItem question="Is n8n included with Customermates?">
No. n8n is a separate open-source product. You self-host it or subscribe to n8n's cloud. Customermates publishes a [community node](https://github.com/customermates/n8n-nodes-crm) for it and documents the [integration patterns](/docs/n8n), and that is the extent of the relationship.
</FaqItem>

<FaqItem question="Can I use Zapier or Make instead?">
Yes. Nothing in the webhook or REST surface is n8n-specific. Any tool that can receive an HTTP POST and call an HTTP API will work.
</FaqItem>

<FaqItem question="Which events can I subscribe to?">
[[derived.webhooks.events.total]] events across records and messaging. The full list is at [Webhooks](/docs/webhooks).
</FaqItem>

<FaqItem question="Can I post CRM data into Slack without writing code?">
Yes, in the sense that n8n, Make, and Zapier are visual builders. You still design the workflow yourself; there is no preconfigured Customermates-to-Slack template shipped by us.
</FaqItem>

<FaqItem question="Will there ever be a native Slack integration?">
It is not on the roadmap as a committed item, and we will not list it here until it exists.
</FaqItem>
</Faq>

## Get Started

Read [Webhooks](/docs/webhooks) for the event payloads and [n8n](/docs/n8n) for the wiring patterns. Create a webhook in **Company → Webhooks**, filter `record.updated` to the Deals type, point it at your automation tool, and send your first deal update into a Slack channel. From there, the same pattern works for other record types and events.
