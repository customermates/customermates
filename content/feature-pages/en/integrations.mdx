A CRM integration moves data or triggers between your CRM and another system, so nobody copies a deal from one screen into another. Customermates does this through four open interfaces instead of an app marketplace: a REST API, outgoing webhooks, an MCP endpoint for AI clients, and a community node for n8n. They are available on every plan, including self-hosted installations.

That choice has a cost you should know up front. There is no catalog of one-click apps. If you want Customermates to talk to Slack, your accounting tool or a form builder, you either point a webhook at that tool, call the API from your own code, or build the flow in an automation tool such as n8n, Make or Zapier.

## The five connection types at a glance

| Connection | Direction | What it is for | Plan |
|---|---|---|---|
| Webhooks | CRM to your system | Push an event when a contact, organization, deal, service or task is created, updated or deleted, or when an inbox message arrives | Every plan, self-hosted included |
| REST API | Your system to CRM | Create, read, search, update and delete records from code or an automation tool | Every plan, self-hosted included |
| MCP | AI client to CRM | Let Claude, ChatGPT, Cursor, Codex or Gemini CLI read and write records in conversation | Every plan, self-hosted included |
| n8n community node | Both | Dedicated Customermates nodes in a separately run n8n instance | Every plan; n8n is billed by n8n |
| Unified inbox | Channels to CRM | Gmail, Outlook, IMAP, LinkedIn, WhatsApp, Instagram and Telegram conversations next to the record, plus read-only Google and Microsoft calendars | Customermates Cloud, Pro or higher |

Webhooks, REST and MCP come with Starter at [[commercial.price.starter.monthly]] per user per month. The [unified inbox](/features/unified-inbox) starts with Pro at [[commercial.price.pro.monthly]] per user per month and includes [[commercial.entitlement.pro.includedAccountsPerUser]] connected account per user; Business includes [[commercial.entitlement.business.includedAccountsPerUser]] per user and shared accounts. Self-hosted installations get REST, webhooks and MCP but no inbox, so messaging events never fire there.

## Which route fits which job

| If you want to… | Use | Why |
|---|---|---|
| Post a message to one Slack channel when a deal is created | A webhook with a body template, sent to a Slack incoming webhook | No automation tool needed |
| Hand won deals to your accounting software | n8n, Make or Zapier on a `deal.updated` webhook | Those tools check the stage value and call the accounting tool's API |
| Create contacts from your website form | The form tool or n8n calls `POST /api/v1/contacts` | Customermates has no embeddable form of its own |
| Mirror records into a data warehouse | Webhooks, idempotent by `entityId` | Near real time, no polling |
| Ask an AI to update five deals after a call | MCP from Claude, ChatGPT or another client | The client discovers the tools and does the calls |
| Move a spreadsheet of existing clients in | XLSX import, one record type at a time | Faster than an API script for a one-off move |

## Webhooks

Create a webhook under **My Company → Webhooks → Add**, paste the receiving URL, and pick events. You can choose from [[derived.webhooks.events.total]] events: [[derived.webhooks.events.records]] record events (created, updated and deleted for contacts, organizations, deals, services and tasks) and [[derived.webhooks.events.messaging]] messaging events, such as a received message or email and a changed calendar event.

The details that matter when you build on them:

- **Signatures.** Set a secret and every delivery carries an HMAC-SHA256 signature over the request body, so the receiver can reject forged calls.
- **Retries.** Timeouts, network errors, 5xx responses and 408, 425 and 429 are retried automatically, up to 5 times. Other 4xx responses are not.
- **Delivery log.** **My Company → Recent Deliveries** shows every delivery with status code and payload, and you can resend one from there.
- **Custom headers and body templates.** Headers let you authenticate against the receiver. A body template replaces the standard JSON envelope with the shape the receiver expects, using placeholders such as `{{event}}` and `{{data.payload.name}}`.
- **Changes only.** An `*.updated` event includes a `changes` object with the previous and current value of each field that moved, and a write that changes nothing sends no event.

Deliveries are not strictly ordered, so treat them as idempotent messages keyed by `entityId` and order by the payload `timestamp`. The full catalog and payload shapes are in the [webhooks documentation](/docs/webhooks).

## REST API

The API is versioned under `/api/v1`, authenticated with an `x-api-key` header, and described by an OpenAPI document. Contacts, organizations, deals, services and tasks each support create, read, search, update and delete, plus `/many` endpoints for batches of up to 100 records per request. A `GET /api/v1/<type>/configuration` call returns your workspace's custom columns and options, which you need because deal stage is a configurable single-select column, not a fixed field.

An API key inherits the permissions of the user who created it. There is no per-key scope, so create keys from a user whose role fits the integration. More detail on the [API feature page](/features/api).

## MCP for AI clients

MCP (Model Context Protocol) is an [open standard for connecting AI applications to external systems](https://modelcontextprotocol.io/docs/getting-started/intro). Customermates runs one MCP endpoint at `/api/v1/mcp` with [[derived.mcp.tools.total]] tools. Claude and ChatGPT connect as a custom connector with OAuth sign-in, as described in [connecting Claude and ChatGPT](/docs/connect-custom-connector). Claude Code, Codex, Cursor and Gemini CLI connect with an API key.

The client and its model are yours. Your AI provider bills its own usage, and MCP calls use no Customermates hosted AI credits. Messaging, calendar and social tools need a Cloud plan with the inbox. The [MCP reference](/docs/mcp) lists every tool.

Inside Customermates Cloud there is also Mate, the hosted assistant, which uses hosted AI credits. Mate can create and edit webhooks for you, and its [routines](/docs/app-routines) can run a saved instruction when a record changes. That covers work that needs reading and judgment; fixed rules belong in webhooks and n8n.

## n8n, Make or Zapier

None of these is bundled with Customermates. You run or subscribe to them separately, and they bring the large connector catalogs. Customermates documents the n8n patterns and publishes a [community node](https://github.com/customermates/n8n-nodes-crm); Make and Zapier work through their generic webhook and HTTP steps. Customermates publishes this page; the table below describes each tool's billing model from its own pricing page, checked on 8 October 2026.

| Tool | How it bills | Free option |
|---|---|---|
| [n8n](https://n8n.io/pricing/) | Cloud plans by workflow executions; a whole run counts as one execution | Self-hosted Community Edition |
| [Make](https://www.make.com/en/pricing) | Credits; most module actions use one credit | Free plan with a monthly credit allowance |
| [Zapier](https://zapier.com/pricing) | Tasks; each successfully completed action step counts, triggers do not | Free plan, limited to two-step Zaps |

n8n is fair-code under the [Sustainable Use License](https://github.com/n8n-io/n8n): n8n describes its source as available and self-hostable. That is a different licence from the AGPL that covers the Customermates core.

If you already pay for one of them, use it. If you start from zero and have someone who can run a container, self-hosted n8n keeps both the CRM and the automation on your own servers. The [n8n setup guide](/docs/n8n) shows the webhook trigger, the HTTP Request calls and the `x-api-key` credential.

## Slack: two routes, no native app

Customermates has no Slack app, no Slack channel in the inbox and no Slack settings screen. Slack is reachable through webhooks or n8n.

**Route 1, webhook only.** Slack's [incoming webhooks](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/) accept a JSON POST such as `{"text": "Hello"}` and post it into one channel. A Customermates body template produces exactly that:

<Steps>
  <Step title="Create the Slack incoming webhook">In Slack, create an app, turn on incoming webhooks, add a webhook to your workspace and pick the channel. Copy the URL and keep it secret.</Step>
  <Step title="Add the Customermates webhook">Under **My Company → Webhooks → Add**, paste the Slack URL and select `deal.created`.</Step>
  <Step title="Write the body template">Enter `{"text": "New deal: {{data.payload.name}}"}`. For `deal.updated` events the record sits one level deeper, so use `{{data.payload.deal.name}}`.</Step>
  <Step title="Test and check the log">Create a test deal and open **Recent Deliveries**. A 2xx status code means Slack accepted it.</Step>
</Steps>

**Route 2, n8n.** Use n8n when the message needs logic: alert only when the stage column reaches a certain value, post a weekly pipeline digest from a scheduled `POST /api/v1/deals/search`, or turn a Slack shortcut into a new contact through the API. Slack conversations never appear in the Customermates inbox either way.

## What is not included

<AcquisitionCallout title="Limits to know before you plan an integration" variant="boundary">
  No app marketplace and no one-click connectors. No native Slack, Microsoft Teams, accounting or calendar-booking integration. Calendars are read-only. No embeddable web forms. Data transfer by file is XLSX only, one record type at a time, with no whole-account export. n8n, Make and Zapier are separate products with separate bills.
</AcquisitionCallout>

If your team needs hundreds of prebuilt, vendor-maintained connectors that a non-technical person switches on in a settings screen, a CRM with its own app marketplace fits better. Customermates fits teams that are happy to wire a webhook or let an AI client do the calls, and that want the same interfaces whether they use the cloud or self-host. ERP links follow the same pattern; the [CRM and ERP integration guide](/blog/crm-erp-integration) walks through it.

## Frequently asked questions

<Faq>
<FaqItem question="What are CRM integrations?">
Connections that move data or triggers between a CRM and other software, for example a new deal creating a project in a project tool or a form submission creating a contact. They run through an API, webhooks, an automation tool or a vendor-built connector. Customermates offers the first three plus MCP for AI clients.
</FaqItem>

<FaqItem question="Does Customermates have an open API and webhooks?">
Yes, on every plan and in self-hosted installations. The REST API is documented with OpenAPI and uses an `x-api-key` header. Webhooks cover [[derived.webhooks.events.total]] events, with HMAC signatures, automatic retries and a delivery log.
</FaqItem>

<FaqItem question="Is there a native Slack integration?">
No. Send CRM events to Slack with a webhook and body template pointed at a Slack incoming webhook, or build the flow in n8n. Creating CRM records from Slack also runs through n8n and the REST API.
</FaqItem>

<FaqItem question="Is n8n included in the subscription?">
No. n8n is a separate product. You self-host the free Community Edition or subscribe to n8n's cloud. Customermates provides the community node, webhooks and API it connects to.
</FaqItem>

<FaqItem question="Can I connect Zapier or Make instead of n8n?">
Yes. Any tool that can receive an HTTP POST and send HTTP requests with a custom header works. There is no dedicated Customermates app in their catalogs, so you use their generic webhook and HTTP steps.
</FaqItem>

<FaqItem question="What is the difference between an API and a CRM?">
The CRM is the system that stores your contacts, deals and conversations. An API is the doorway other software uses to read and change that data. In Customermates the REST API and the MCP endpoint are two such doorways, one for programs and one for AI clients.
</FaqItem>
</Faq>
