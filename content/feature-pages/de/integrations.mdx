CRM-Integration heißt: Daten und Auslöser fließen zwischen dem CRM und Ihren anderen Systemen, ohne dass jemand einen Deal von einem Fenster ins nächste abtippt. Customermates setzt dafür auf vier offene Schnittstellen statt auf einen App-Marktplatz: eine REST-API, ausgehende Webhooks, einen MCP-Endpunkt für KI-Clients und eine Community-Node für n8n. Alle vier stehen in jedem Tarif zur Verfügung, auch in selbst gehosteten Installationen.

Das hat eine Kehrseite, die Sie vorher kennen sollten. Es gibt keinen Katalog mit Ein-Klick-Apps. Soll Customermates mit Slack, Ihrer Buchhaltung oder einem Formular-Tool sprechen, richten Sie einen Webhook auf dieses Tool, rufen die API aus eigenem Code auf oder bauen den Ablauf in einem Automatisierungstool wie n8n, Make oder Zapier.

## Die fünf Anbindungswege im Überblick

| Anbindung | Richtung | Wofür | Tarif |
|---|---|---|---|
| Webhooks | CRM an Ihr System | Ein Ereignis senden, wenn ein Kontakt, eine Organisation, ein Deal, eine Leistung oder eine Aufgabe angelegt, geändert oder gelöscht wird oder eine Nachricht im Posteingang eingeht | Jeder Tarif, auch selbst gehostet |
| REST-API | Ihr System an CRM | Datensätze aus Code oder einem Automatisierungstool anlegen, lesen, suchen, ändern und löschen | Jeder Tarif, auch selbst gehostet |
| MCP | KI-Client an CRM | Claude, ChatGPT, Cursor, Codex oder Gemini CLI lesen und schreiben Datensätze im Gespräch | Jeder Tarif, auch selbst gehostet |
| n8n-Community-Node | Beide | Eigene Customermates-Nodes in einer separat betriebenen n8n-Instanz | Jeder Tarif; Kosten für n8n separat |
| Einheitlicher Posteingang | Kanäle an CRM | Gespräche aus Gmail, Outlook, IMAP, LinkedIn, WhatsApp, Instagram und Telegram direkt am Datensatz, dazu Google- und Microsoft-Kalender nur lesend | Customermates Cloud, ab Pro |

Webhooks, REST und MCP sind ab Starter für [[commercial.price.starter.monthly]] pro Nutzer und Monat enthalten. Der [einheitliche Posteingang](/features/unified-inbox) beginnt mit Pro für [[commercial.price.pro.monthly]] pro Nutzer und Monat, mit [[commercial.entitlement.pro.includedAccountsPerUser]] verbundenem Konto pro Nutzer; Business enthält [[commercial.entitlement.business.includedAccountsPerUser]] Konten pro Nutzer und geteilte Konten. Selbst gehostete Installationen erhalten REST, Webhooks und MCP, aber keinen Posteingang. Messaging-Ereignisse werden dort also nie ausgelöst.

## Welcher Weg passt zu welcher Aufgabe

| Wenn Sie … | nutzen Sie | weil |
|---|---|---|
| bei jedem neuen Deal eine Nachricht in einen Slack-Channel schicken wollen | einen Webhook mit Body-Vorlage an einen Slack-Incoming-Webhook | kein Automatisierungstool nötig ist |
| gewonnene Deals an Ihre Buchhaltungssoftware übergeben wollen | n8n, Make oder Zapier auf das Ereignis `deal.updated` | diese Tools den Phasenwert prüfen und die API der Buchhaltung aufrufen |
| Kontakte aus Ihrem Website-Formular anlegen wollen | das Formular-Tool oder n8n mit `POST /api/v1/contacts` | Customermates kein eigenes einbettbares Formular hat |
| Datensätze in ein Data Warehouse spiegeln wollen | Webhooks, idempotent über `entityId` | Daten nahezu in Echtzeit ankommen, ohne Polling |
| nach einem Kundengespräch fünf Deals per KI aktualisieren wollen | MCP aus Claude, ChatGPT oder einem anderen Client | der Client die Tools selbst findet und aufruft |
| eine bestehende Kundenliste übernehmen wollen | den XLSX-Import, ein Datensatztyp nach dem anderen | das für einen einmaligen Umzug schneller ist als ein API-Skript |

## Webhooks

Einen Webhook legen Sie unter **Mein Unternehmen → Webhooks → Hinzufügen** an: Ziel-URL einfügen, Ereignisse wählen, speichern. Zur Auswahl stehen [[derived.webhooks.events.total]] Ereignisse: [[derived.webhooks.events.records]] Datensatz-Ereignisse (angelegt, geändert und gelöscht für Kontakte, Organisationen, Deals, Leistungen und Aufgaben) und [[derived.webhooks.events.messaging]] Messaging-Ereignisse, etwa eine eingegangene Nachricht oder E-Mail und eine Änderung in einem verbundenen Kalender.

Worauf es beim Aufbau ankommt:

- **Signaturen.** Mit einem **Secret** trägt jede Zustellung eine HMAC-SHA256-Signatur über den Request-Body. Der Empfänger kann gefälschte Aufrufe so abweisen.
- **Wiederholungen.** Timeouts, Netzwerkfehler, 5xx-Antworten sowie 408, 425 und 429 werden automatisch bis zu 5-mal wiederholt. Andere 4xx-Antworten nicht.
- **Zustellprotokoll.** **Mein Unternehmen → Letzte Zustellungen** zeigt jede Zustellung mit Statuscode und Payload. Von dort lässt sie sich erneut senden.
- **Eigene Header und Body-Vorlagen.** Header authentifizieren Sie beim Empfänger. Eine **Body-Vorlage** ersetzt den Standard-JSON-Umschlag durch das Format, das der Empfänger erwartet, mit Platzhaltern wie `{{event}}` und `{{data.payload.name}}`.
- **Nur echte Änderungen.** Ein `*.updated`-Ereignis enthält ein `changes`-Objekt mit altem und neuem Wert jedes geänderten Felds. Ein Speichervorgang ohne Änderung löst kein Ereignis aus.

Zustellungen kommen nicht streng geordnet an. Behandeln Sie sie als idempotente Nachrichten mit dem Schlüssel `entityId` und ordnen Sie sie über den `timestamp` der Payload. Den vollständigen Katalog finden Sie in der [Webhook-Dokumentation](/docs/webhooks).

## REST-API

Die API ist unter `/api/v1` versioniert, wird per Header `x-api-key` authentifiziert und durch ein OpenAPI-Dokument beschrieben. Kontakte, Organisationen, Deals, Leistungen und Aufgaben lassen sich jeweils anlegen, lesen, suchen, ändern und löschen. Für Stapel gibt es `/many`-Endpunkte mit bis zu 100 Datensätzen pro Anfrage. `GET /api/v1/<typ>/configuration` liefert die eigenen Spalten und Optionen Ihres Arbeitsbereichs. Das brauchen Sie, weil die Deal-Phase eine konfigurierbare Spalte vom Typ Einzelauswahl ist und kein festes Feld.

Ein API-Key erbt die Rechte des Nutzers, der ihn angelegt hat. Eine Einschränkung pro Key gibt es nicht. Legen Sie Keys deshalb mit einem Nutzer an, dessen Rolle zur Integration passt. Mehr dazu auf der [Seite zur API](/features/api).

## MCP für KI-Clients

MCP (Model Context Protocol) ist ein [offener Standard, um KI-Anwendungen mit externen Systemen zu verbinden](https://modelcontextprotocol.io/docs/getting-started/intro). Customermates betreibt einen MCP-Endpunkt unter `/api/v1/mcp` mit [[derived.mcp.tools.total]] Tools. Claude und ChatGPT verbinden sich als benutzerdefinierter Connector mit OAuth-Anmeldung, wie in der [Anleitung für Claude und ChatGPT](/docs/connect-custom-connector) beschrieben. Claude Code, Codex, Cursor und Gemini CLI verbinden sich per API-Key.

Client und Modell gehören Ihnen. Ihr KI-Anbieter rechnet seine Nutzung selbst ab, und MCP-Aufrufe verbrauchen keine gehosteten KI-Credits von Customermates. Messaging-, Kalender- und Social-Tools setzen einen Cloud-Tarif mit Posteingang voraus. Die [MCP-Referenz](/docs/mcp) listet alle Tools.

In Customermates Cloud gibt es zusätzlich Mate, den gehosteten Assistenten, der gehostete KI-Credits verbraucht. Mate kann Webhooks für Sie anlegen und ändern, und seine [Routinen](/docs/app-routines) führen eine gespeicherte Anweisung aus, wenn sich ein Datensatz ändert. Das deckt Arbeit ab, die Lesen und Abwägen verlangt. Feste Regeln gehören in Webhooks und n8n.

## n8n, Make oder Zapier

Keines dieser Tools ist in Customermates enthalten. Sie betreiben oder abonnieren sie separat, und sie bringen die großen Konnektor-Kataloge mit. Customermates dokumentiert die Muster für n8n und veröffentlicht eine [Community-Node](https://github.com/customermates/n8n-nodes-crm). Make und Zapier binden Sie über deren allgemeine Webhook- und HTTP-Schritte an. Diese Seite stammt von Customermates; die Tabelle gibt das Preismodell jedes Tools nach dessen eigener Preisseite wieder, Stand 8. Oktober 2026.

n8n ist Fair-Code unter der [Sustainable Use License](https://github.com/n8n-io/n8n). n8n beschreibt den Quellcode als einsehbar und selbst hostbar. Das ist eine andere Lizenz als die AGPL, unter der der Kern von Customermates steht.

Zahlen Sie bereits für eines der Tools, nehmen Sie dieses. Die [n8n-Anleitung](/docs/n8n) zeigt den Webhook-Trigger, die HTTP-Request-Aufrufe und das Credential für `x-api-key`.

## Slack: zwei Wege, keine native App

Customermates hat keine Slack-App, keinen Slack-Kanal im Posteingang und keine Slack-Einstellungen. Slack erreichen Sie über Webhooks oder n8n.

**Weg 1, nur mit Webhook.** Slacks [Incoming Webhooks](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/) nehmen einen JSON-POST wie `{"text": "Hallo"}` an und posten ihn in einen festgelegten Channel. Eine Body-Vorlage in Customermates erzeugt genau dieses Format:

<Steps>
  <Step title="Slack-Incoming-Webhook anlegen">Legen Sie in Slack eine App an, aktivieren Sie Incoming Webhooks, fügen Sie einen Webhook zum Workspace hinzu und wählen Sie den Channel. Kopieren Sie die URL und behandeln Sie sie wie ein Passwort.</Step>
  <Step title="Webhook in Customermates anlegen">Fügen Sie unter **Mein Unternehmen → Webhooks → Hinzufügen** die Slack-URL ein und wählen Sie `deal.created`.</Step>
  <Step title="Body-Vorlage schreiben">Tragen Sie `{"text": "Neuer Deal: {{data.payload.name}}"}` ein. Bei `deal.updated` liegt der Datensatz eine Ebene tiefer, dort lautet der Platzhalter `{{data.payload.deal.name}}`.</Step>
  <Step title="Testen und Protokoll prüfen">Legen Sie einen Test-Deal an und öffnen Sie **Letzte Zustellungen**. Ein 2xx-Statuscode heißt, dass Slack die Nachricht angenommen hat.</Step>
</Steps>

**Weg 2, mit n8n.** n8n brauchen Sie, sobald Logik ins Spiel kommt: nur melden, wenn die Phasen-Spalte einen bestimmten Wert erreicht, einmal pro Woche eine Pipeline-Übersicht aus einem geplanten `POST /api/v1/deals/search` posten, oder aus einem Slack-Shortcut per API einen neuen Kontakt anlegen. Slack-Gespräche erscheinen in beiden Fällen nicht im Customermates-Posteingang.

## Was nicht enthalten ist

<AcquisitionCallout title="Grenzen, die Sie vor der Planung kennen sollten" variant="boundary">
  Kein App-Marktplatz und keine Ein-Klick-Konnektoren. Keine native Integration für Slack, Microsoft Teams, Buchhaltung oder Terminbuchung. Kalender sind nur lesbar. Keine einbettbaren Webformulare. Dateiaustausch nur als XLSX, ein Datensatztyp nach dem anderen, ohne Export des gesamten Kontos. n8n, Make und Zapier sind eigene Produkte mit eigenen Kosten.
</AcquisitionCallout>

Braucht Ihr Team Hunderte fertige, vom Anbieter gepflegte Konnektoren, die jemand ohne Technikkenntnisse in einer Einstellungsseite einschaltet, passt ein CRM mit eigenem App-Marktplatz besser. Customermates passt zu Teams, die einen Webhook selbst einrichten oder die Aufrufe einem KI-Client überlassen, und die in der Cloud wie im eigenen Rechenzentrum dieselben Schnittstellen haben wollen. Die Anbindung an ein ERP folgt demselben Muster; der [Leitfaden zur CRM-ERP-Integration](/blog/crm-erp-integration) zeigt den Ablauf.

## Häufige Fragen

<Faq>
<FaqItem question="Was bedeutet CRM-Integration?">
Die Verbindung eines CRM mit anderer Software, sodass Daten oder Auslöser automatisch fließen. Ein neuer Deal legt zum Beispiel ein Projekt im Projekttool an, oder eine Formular-Anfrage wird zum Kontakt. Das läuft über eine API, Webhooks, ein Automatisierungstool oder einen fertigen Konnektor des Anbieters. Customermates bietet die ersten drei Wege und zusätzlich MCP für KI-Clients.
</FaqItem>

<FaqItem question="Hat Customermates eine offene API und Webhooks?">
Ja, in jedem Tarif und in selbst gehosteten Installationen. Die REST-API ist per OpenAPI dokumentiert und nutzt den Header `x-api-key`. Webhooks decken [[derived.webhooks.events.total]] Ereignisse ab, mit HMAC-Signatur, automatischen Wiederholungen und Zustellprotokoll.
</FaqItem>

<FaqItem question="Gibt es eine native Slack-Integration?">
Nein. CRM-Ereignisse schicken Sie per Webhook mit Body-Vorlage an einen Slack-Incoming-Webhook, oder Sie bauen den Ablauf in n8n. Auch das Anlegen von CRM-Datensätzen aus Slack heraus läuft über n8n und die REST-API.
</FaqItem>

<FaqItem question="Ist n8n im Abo enthalten?">
Nein. n8n ist ein eigenes Produkt. Sie hosten die kostenlose Community Edition selbst oder abonnieren die Cloud von n8n. Customermates liefert die Community-Node, die Webhooks und die API, mit denen n8n arbeitet.
</FaqItem>

<FaqItem question="Funktionieren auch Zapier oder Make statt n8n?">
Ja. Jedes Tool, das einen HTTP-POST empfangen und HTTP-Anfragen mit eigenem Header senden kann, funktioniert. Eine eigene Customermates-App gibt es in deren Katalogen nicht, Sie nutzen dort die allgemeinen Webhook- und HTTP-Schritte.
</FaqItem>

<FaqItem question="Lässt sich das CRM mit SAP oder einem anderen ERP verbinden?">
Ja, über dieselben Wege: Webhooks melden Änderungen an das ERP, die REST-API nimmt Daten von dort entgegen, meist mit n8n oder einer anderen Middleware dazwischen. Einen fertigen SAP-Konnektor liefert Customermates nicht.
</FaqItem>
</Faq>
