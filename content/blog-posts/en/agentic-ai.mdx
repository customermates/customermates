# Agentic AI Examples: Definition, How It Works and Real Use Cases

**Agentic AI** is AI that is given a goal instead of a question: it plans the steps, calls tools such as a CRM, a search or an API, checks what came back and acts, with limited supervision. Typical agentic AI examples are a coding agent that opens a pull request, a support agent that answers or escalates a ticket and a CRM agent that drafts the reply on a deal, each with a point where a person approves.

"Agentic" is the adjective of "agent": something that acts on someone's behalf. IBM's short definition is a good anchor. Agentic AI is "an artificial intelligence system that can accomplish a specific goal with limited supervision" ([IBM](https://www.ibm.com/think/topics/agentic-ai)). The two words that carry the meaning are *goal* and *limited*. Someone still sets the goal, and someone still decides how much the system may do without asking.

Disclosure: Customermates, an open-source CRM, publishes this guide. One section describes what our product does and does not do; the definitions, examples and risks apply to any agent.

## What does agentic AI mean?

Agentic AI means AI that acts toward a goal instead of only answering. The model is the same kind of language model behind a chatbot, but it is wired to tools and allowed to decide the next step. Google Cloud puts it as AI that "can set goals, plan, and execute tasks with minimal human intervention", unlike "traditional AI, which primarily responds to commands or analyzes data".

The main sources define agentic AI in slightly different words, and the differences show what each one cares about.

| Source | Definition | What it stresses |
|---|---|---|
| [IBM](https://www.ibm.com/think/topics/agentic-ai) | "an artificial intelligence system that can accomplish a specific goal with limited supervision" | The goal, and how much supervision remains |
| [AWS](https://aws.amazon.com/what-is/agentic-ai/) | "an autonomous AI system that can act independently to achieve pre-determined goals" | Independence from step-by-step prompting |
| [Google Cloud](https://cloud.google.com/discover/what-is-agentic-ai) | AI that "can set goals, plan, and execute tasks with minimal human intervention" | Planning and execution, not only responding |
| [MIT Sloan](https://mitsloan.mit.edu/ideas-made-to-matter/agentic-ai-explained), citing a paper by John Horton and co-authors | "autonomous software systems that perceive, reason, and act in digital environments to achieve goals on behalf of human principals" | Acting on behalf of a person |
| [Salesforce](https://www.salesforce.com/agentforce/what-is-agentic-ai/) | "an intelligent system that can act autonomously, reason through multi-step problems, and adapt its actions in real-time to achieve a specific business goal with minimal human supervision" | Business goals and adapting while running |
| [Anthropic](https://www.anthropic.com/research/building-effective-agents) | Agents are "systems where LLMs dynamically direct their own processes and tool usage" | Who controls the path: the model or the code |

The shared core is a goal, tools, and some freedom in how to get there. The disagreement is about how much freedom. MIT Sloan's article itself notes that there is no single agreed definition.

## What is the difference between a chatbot, an assistant, a workflow and an agent?

These four words are often used for the same product. They describe different amounts of control. Google Cloud separates bots, assistants and agents: bots are the least autonomous and typically follow pre-programmed rules, assistants respond to requests and "can recommend actions but decision-making is done by the user", and agents are the most autonomous, able to "operate and make decisions independently to achieve a goal". Anthropic adds the fourth: a workflow is a system where LLMs and tools are "orchestrated through predefined code paths", while in an agent the model directs its own process.

| Type | Who decides the next step | Tools | Example | Where it breaks |
|---|---|---|---|---|
| Chatbot (bot) | A script or fixed rules | None or a simple lookup | An FAQ widget on a website | Anything outside the script |
| AI assistant | You: it answers and recommends, you act | Optional | ChatGPT in an ordinary chat | The answer stays words until you act on it |
| Workflow automation | The path you wrote, with AI steps if you add them | APIs, webhooks | "When a deal moves to Won, create an onboarding task" | Input the path did not anticipate |
| AI agent | The model, within the tools and limits you set | Required | A coding agent that fixes a failing test and opens a pull request | A wrong action, runaway cost, an injected instruction |

**Is ChatGPT an agentic AI?** In an ordinary chat it behaves as an assistant: it answers and you act. It works agentically when it is allowed to use tools to act for you, for example in ChatGPT's agent mode, or when it is connected to business software through MCP and can read data there and, depending on the ChatGPT plan, change it. The label belongs to the setup, not to the product name.

## How does an agentic AI system work?

An agentic AI system is a language model plus four things around it: a goal, tools it may call, the permissions those tools run under, and a loop with a stop rule. Every such system runs a version of the same cycle:

1. **Goal.** A person, a schedule or an event hands the agent a goal, such as "prepare a reply to this email" or "fix the failing test".
2. **Plan.** A language model breaks the goal into steps and picks the first one.
3. **Act.** The agent calls a tool: a search, a database query, an API call, a file edit.
4. **Observe.** It reads the result and compares it with the goal.
5. **Continue or stop.** It takes the next step, asks a person, or ends when the goal is met or a limit is reached.

IBM spells the same cycle out in seven stages: perception, reasoning, goal setting, decision-making, execution, learning and adaptation, and orchestration. What sets an agent's reach is its tools: a model without tool access can describe an action but cannot take it. That is why the [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro), in its maintainers' words "an open-source standard for connecting AI applications to external systems", sits at the centre of so many agent setups. The [MCP server guide](/blog/what-is-an-mcp-server) explains how it works and what to check before connecting one.

### What is the difference between generative AI and agentic AI?

Generative AI produces content: text, images, code, a summary. You read it and decide what to do with it. Agentic AI uses a language model as what Google Cloud calls a "brain" that performs actions through tools. Google's own example: generative AI could create marketing materials, while agentic AI could then deploy them, track their performance and adjust the strategy based on the results.

| | Generative AI | Agentic AI |
|---|---|---|
| You give it | A prompt | A goal |
| It returns | Content | Actions, plus a report of what changed |
| Tools | Optional | Required |
| Who takes the next step | You | The agent, within its limits |
| A typical mistake | A wrong sentence in a draft | A wrong update, or a message to the wrong person |
| Where review happens | Before you use the output | Before the action, or in the run log afterwards |

The last two rows are the practical difference. A hallucination in a draft costs you an edit. The same hallucination inside an agent becomes a changed record or a sent email. So agents need permissions and approval rules that a text generator never needed.

## What are examples and applications of agentic AI?

The useful way to read examples is by the job, not the brand: what the agent does, which tools it needs, where a person must approve, and what can go wrong. The table below covers four business functions. The rows are patterns, not products.

### Agentic AI examples by business function

| Function | Example job | What the agent does | Tools it needs | Where a person approves | Main risk |
|---|---|---|---|---|---|
| Sales | Reply prep on an open deal | Reads the new email, the deal and its notes, adds the open question to the notes, saves a reply draft | CRM read and write, email thread access | The draft, before it is sent | A wrong fact in the draft, or a reply to the wrong contact |
| Sales | Account research before a call | Searches the web and the CRM, writes a one-page brief with its sources | Web search, CRM read | Reading the brief before the call | Outdated or invented facts that get copied into the CRM |
| Support | Answer or escalate a ticket | Reads the ticket, searches the knowledge base, answers when the answer is documented, otherwise hands the case to a person with a summary | Knowledge base search, ticket system, read access to account data | Refunds, account changes and any case the knowledge base does not cover | A confident wrong answer, or a promise nobody approved |
| Operations | First response to an IT incident | Reads alerts and logs, proposes or performs a rollback, writes the incident report, notifies the person on call | Monitoring and logs, deployment tooling, chat | Production changes and rollbacks | A hard-to-undo action taken on a misread alert |
| Finance | Invoice and transaction review | Compares incoming invoices with orders and bank lines, proposes matches, flags exceptions | Accounting system or export (read), file reading | Every posting and every payment | A wrong booking, a duplicate payment, exceptions nobody reviews |

Vendors describe the same jobs. Salesforce's explainer walks through a service agent that checks warranty status, searches the knowledge base, sends a return label and updates the CRM, and an account-health agent that sends a training email and schedules a follow-up for the account manager. [AWS](https://aws.amazon.com/what-is/agentic-ai/) lists customer service automation, incident response automation, shift scheduling and supply chain monitoring. [Google Cloud](https://cloud.google.com/discover/what-is-agentic-ai) adds financial services (fraud detection, risk assessment) and software development. [Anthropic](https://www.anthropic.com/research/building-effective-agents) calls customer support a natural fit because support "naturally follow[s] a conversation flow while requiring access to external information and actions".

Read the last two columns of the table before the first ones. The more reversible the action, the less approval it needs; payments, refunds, rollbacks and anything sent to a customer should always pass a person.

## What are the types of agentic AI?

Searchers often ask for "the four types of agentic AI". The sources checked here do not define exactly four. Google Cloud's [agent guide](https://cloud.google.com/discover/what-are-ai-agents) sorts agents in two ways: by interaction (interactive partners that answer a user's query, and background agents that are "generally driven by events") and by number (a single agent or a multi-agent system). AWS splits multi-agent systems further into horizontal ones, whose agents work side by side, and vertical ones, arranged in a hierarchy. Crossing interaction with number gives four combinations; that grid is my reading, not a standard.

A second way to sort is by who controls the path. Anthropic's engineering guide separates **workflows** from **agents** and names five workflow patterns. Its advice is blunt: find the simplest solution that works, which "might mean not building agentic systems at all". I agree with it. Most business tasks that people call "agents" are better built as workflows with one or two AI steps.

| Pattern | What it does | Business example |
|---|---|---|
| Prompt chaining | Fixed steps, each feeding the next, with checks in between | Summarize a call, extract the next steps, write them to the deal |
| Routing | Classifies the input and sends it to a specialised step | Sort incoming email into sales enquiries and everything else |
| Parallelization | Runs several model calls at once and combines the results | Two independent checks of one contract clause, compared |
| Orchestrator-workers | One model splits the job and delegates the parts | A lead agent hands account research to sub-agents |
| Evaluator-optimizer | One model drafts, another critiques until the draft passes | A reply draft revised against your tone guide |

**Agentic AI vs. AI agents.** Google Cloud calls AI agents "the building blocks of agentic AI": an agent focuses on a specific task, and agentic AI coordinates several agents on a complex workflow. In everyday use the terms are interchangeable.

This section describes our own product, so read it as vendor information. Customermates has three ways for an AI to work on CRM records, and they differ in who starts the work and who approves it.

| Route | Who starts it | What it can do | Approval | Who pays for the model |
|---|---|---|---|---|

### A worked example: one narrow agent in a CRM

CRM work suits a first agent well. It repeats every day, the context sits in one place, and most changes can be corrected. Here is a concrete setup, built as a routine: a saved instruction plus a trigger, run by Mate using hosted AI credits.

**What you need.** Customermates Cloud on Pro or higher, because the trigger is an inbox event and the [unified inbox](/features/unified-inbox) starts at Pro. One connected email account (Gmail, Outlook or IMAP).

<Steps>
  <Step title="Create the routine">
    Open **Routines**, click **Add** and give it a name, for example "Reply prep
    for active deals".
  </Step>
  <Step title="Choose the trigger">
    Select **When something changes** and the event **Email Received**.
  </Step>
  <Step title="Write the instructions">
    Paste the instruction below into **Instructions**. Keep the stop rule and
    the draft-only rule in it.
  </Step>
  <Step title="Read the first runs">
    Open each run's details to see what triggered it, what Mate read and
    changed, and the credits it used. Adjust the wording until the drafts are
    ones you would send.
  </Step>
</Steps>

```
A new email arrived. Find the sender among my contacts.
If the contact is linked to a deal that is not in a won or lost stage:
1. Read the thread and the deal.
2. Append three lines to the deal's notes: what the sender wants,
   any date or amount they mention, and the open question.
3. Save a reply draft in the thread that answers what you can from
   the deal and its notes. Mark anything you are unsure about.
Do not send any message. Do not change the deal stage or value.
If the sender is not linked to an open deal, do nothing.
```

Why it is written this way:

- **Draft-only has to be said.** Mate sends emails and chat messages without a fresh approval when an instruction asks it to. A routine that should only draft must say so.
- **Unattended runs cannot ask.** In a chat, deletions and a few admin actions wait for your approval. In a routine nobody is there to answer, so those actions are declined and the run records the refusal.
- **It runs as you.** A routine runs as its owner, with that owner's access, connected channels and credits. An email the owner cannot see never starts a run.
- **It cannot loop.** Changes made by a routine run never trigger routines.
- **Browsing and writing are kept apart.** A run can search the web or change data, not both: once a web search has returned results, every write in that run is refused. Text from a web page cannot turn into a changed record in the same run.
- **Spending is capped.** Each run has a credit cap and each routine an hourly run limit. The current numbers are in the [routines documentation](/docs/app-routines).

**What it costs.** A three-person team on Pro pays [[commercial.price.pro.monthly.seats.3]] per month, at [[commercial.price.pro.monthly]] per user. Each Pro user can keep [[commercial.entitlement.pro.includedRoutinesPerUser]] routines, and every active user gets monthly hosted AI credits; see [pricing](/pricing). A routine spends its owner's credits.

### Where Customermates is the wrong choice

- **You want an agent that prospects and sends on its own.** Customermates has no sequences, drip campaigns or mass outreach. Routines have no recipient lists or outreach steps, and outreach is draft-first and per message. The [AI sales agent guide](/blog/ai-sales-agent) covers what dedicated outreach agents do and how to test one.
- **You self-host.** A self-hosted installation has neither Mate nor routines. MCP works there, with your own AI client and provider.
- **You need scoped keys.** An API key carries the full permissions of the user who created it, with no per-key scoping, so give that user a role that covers only the task.
- **You need a server-enforced confirmation on MCP.** The server asks clients to confirm before deleting or sending, but that is guidance the client may ignore. Mate's approvals, by contrast, are enforced by the server.

If an AI-ready CRM is what you are choosing, the [AI CRM guide](/blog/ai-crm) lists what to compare.

## What are the risks of agentic AI, and which controls work?

OWASP lists "Excessive Agency" in its [Top 10 for LLM applications](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/) (LLM06:2025) and defines it as the vulnerability that enables damaging actions in response to "unexpected, ambiguous or manipulated outputs from an LLM". The trigger can be a hallucination, a prompt injection hidden in content the agent reads, or a compromised tool. OWASP names three root causes, and each has a direct control:

| Root cause (OWASP) | What it looks like | Control |
|---|---|---|
| Excessive functionality | The agent that writes notes can also delete records | Give it only the tools the task needs |
| Excessive permissions | It runs with an administrator's access | Run it as a user whose role covers the task and nothing more |
| Excessive autonomy | It sends, pays or deletes with nobody checking | Require approval for high-impact actions, or produce drafts only |

OWASP's own advice for the third row is to use human-in-the-loop control "to require a human to approve high-impact actions before they are taken". Anthropic makes the same point for coding agents: automated tests verify functionality, but "human review remains crucial for ensuring solutions align with broader system requirements".

Two more problems show up in practice. Errors cascade: if the first step misreads an email, every later step builds on the mistake. And cost grows with every step, which is why per-run limits exist. A quick test for any product sold as an agent: which tools can it call, with whose permissions, and what does it do without asking?

## How do I give an agent its first job?

<Steps>
  <Step title="Pick a task with a clear end">
    A good first task finishes in one run and has an obvious "done": a meeting
    brief, a reply draft, a cleaned-up record. Avoid open goals like "grow the
    pipeline".
  </Step>
  <Step title="Start with drafts and a narrow role">
    Let the agent prepare and a person decide, and run it as a user whose role
    covers the task. Allow direct actions only for steps that are cheap to
    undo.
  </Step>
  <Step title="Write the stop rule">
    Say what happens when a case does not fit: "If X, do nothing." Cases the
    instruction did not anticipate are where agents improvise.
  </Step>
  <Step title="Read every run at first">
    Check the log of each early run. Widen what the agent may do one action at
    a time.
  </Step>
</Steps>

## When is agentic AI the wrong tool?

If the steps never change, a fixed rule is cheaper and more predictable than an agent. "When a deal moves to Won, create an onboarding task" needs a webhook and a [workflow automation](/features/workflow-automation), not a language model. Agents earn their cost where the input varies: free-text emails, messy notes, questions that need several lookups. They are the wrong choice where a wrong action cannot be undone and nobody can review it in time, payments being the obvious case.

## Agentic AI and data protection

Agents read personal data: names, email addresses, the content of conversations. Under the GDPR, a provider that processes that data on your behalf is a processor and needs a data processing agreement, and the AI providers it relies on are its subprocessors. For Mate in Customermates Cloud, the model providers are named in the [subprocessors list](/subprocessors). If you want to choose the provider yourself, connect your own AI client through MCP, or self-host the open-source core so the CRM data stays on your own servers.
