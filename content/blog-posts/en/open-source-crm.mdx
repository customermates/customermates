# Open Source CRM: How to Compare Self-Hosted Options

The best **open-source CRM** is the one whose license, self-hosting path, operating effort and CRM scope match your team. “Source available,” “open core” and “open source” are not interchangeable, and a long feature checklist says little about what you can lawfully run or realistically maintain.

This guide uses a durable evaluation framework instead of ranking projects by changing prices, star counts or unsourced feature claims. Disclosure: Customermates publishes this comparison and is one of the products discussed below.

## Start with the license, not the homepage

Before comparing features, identify:

- the license attached to the exact server and client code you need;
- directories or modules governed by a separate commercial license;
- obligations triggered by modifying or providing the software over a network;
- trademark restrictions that are separate from the software license; and
- whether the repository is the complete runnable edition or only part of it.

A public repository does not automatically grant open-source rights to every file. Read the license files in the version you plan to deploy and ask counsel when the obligations matter to your organization.

## Seven criteria for comparing open-source CRM software

| Criterion        | What to verify                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| License boundary | Which code is open source, which is commercial, and which obligations apply?                   |
| Deployment       | Is there a maintained, documented path for the exact edition you need?                         |
| Operations       | Who owns upgrades, backups, restoration, monitoring, TLS and incident response?                |
| CRM model        | Does it cover the contacts, organizations, opportunities, services and tasks you actually use? |
| Interfaces       | Are REST, webhooks or agent interfaces available for your workflow?                            |
| Edition gap      | Which cloud or enterprise capabilities disappear when self-hosting?                            |
| Migration        | Is there a real import/export path, or must you design one through APIs or the database?       |

Treat an unmeasured or undocumented capability as unknown, not as included.

## A shortlist without a fake ranking

Open-source CRM searches surface projects with very different scopes. Customermates, SuiteCRM, EspoCRM and Twenty are useful starting points for a source-led shortlist. Odoo Community and CiviCRM can be relevant when a broader business-suite or membership context is part of the requirement. Verify the current official license, edition boundary, deployment documentation and maintenance state before deciding.

For side-by-side detail on two of them, see the [EspoCRM alternative](/compare/espocrm-alternative) and [Twenty alternative](/compare/twenty-alternative) comparisons, which list licence, stack, pricing, channels and MCP support from each project's official pages.

Their intended breadth differs. Some focus on CRM, some sit inside a broader business suite, and some are shaped around nonprofit or membership workflows. That makes a universal “number one” less useful than a shortlist scored against your own requirements.

## Where Customermates fits

Customermates is an open-core CRM for customer relationships and pipelines, made in Germany. First-party material outside `ee/` is AGPL-3.0-only. Inside `ee/`, material is commercially licensed except for the client material identified as AGPL-3.0-only in Section 6 of `ee/LICENSE.md`.

The official [self-hosted CRM](/features/self-hosted) deployment contains the application and PostgreSQL 16. The self-hosted edition has the Starter feature set.

| Customermates self-hosted capability               | Status                                              |
| -------------------------------------------------- | --------------------------------------------------- |
| Contacts, organizations, deals, services and tasks | Included                                            |
| Custom fields, table and Kanban views              | Included                                            |
| REST, webhooks and MCP                             | Included                                            |
| External AI clients through MCP                    | Included; customer supplies the client and provider |
| Unified inbox and messaging accounts               | Not included                                        |
| Cloud-only Mate assistant and hosted credits       | Not included                                        |
| Connected read-only calendar view                  | Not included                                        |
| Record import and export as XLSX workbooks         | Included, one record type at a time                 |

This makes Customermates a fit when you want a focused CRM, Docker/PostgreSQL deployment and an open MCP interface. It is not a fit when self-hosting must include the managed-cloud inbox, when you need custom object types, or when you need a PSA, invoicing or time-tracking suite.

## Open source is not the same as self-hosted

The two terms are often searched together but answer different questions. **Open source** is about rights: what the licence lets you inspect, change and redistribute. **Self-hosted** is about operations: whose servers run the application and database. A project can be open source and still be used mainly as a cloud service, and a self-hosted product can be proprietary. This guide covers the licence and shortlist questions; the [self-hosted CRM](/features/self-hosted) page covers the Customermates deployment itself, and the [agentic CRM guide](/blog/agentic-crm) covers how AI clients work with it through MCP.

## Self-hosting changes who operates the system

Open source gives you permissions defined by the license; self-hosting gives you infrastructure responsibility. Neither is an automatic promise of security, compliance, portability or low cost.

Your team must decide who will own:

- application and database updates;
- backups and tested restoration;
- network controls, TLS and secrets;
- monitoring and incident response;
- capacity and availability planning; and
- every connected provider and its data flow.

If you want Customermates-specific deployment detail, use the [self-hosting guide](/docs/self-hosting). Do not copy a generic Docker runbook from a comparison article into production.

## Cloud versus self-hosted CRM

Choose managed cloud when you want the vendor to operate the application and when cloud-only capabilities are essential. Choose self-hosting when the license, Starter feature boundary and operating responsibility fit your team.

For Customermates, the distinction is explicit: the core CRM, REST, webhooks and MCP can be self-hosted; the unified inbox, connected calendar view, hosted Mate capability and hosted credits cannot.

  <Step title="Define the job">

  </Step>
  <Step title="Inspect the legal boundary">
    Read the exact license and edition boundary for every finalist and version.
  </Step>
  <Step title="Run the official path">

  </Step>
  <Step title="Test operations">
    Verify authentication, permissions, backups, restoration and upgrades

  </Step>
  <Step title="Price the whole system">

  </Step>
  <Step title="Plan migration separately">
    Design and validate a migration procedure if the product has no dedicated
    import or export workflow.
  </Step>
</Steps>

## Frequently asked questions

<Faq>
<FaqItem question="What does open-source CRM mean?">
It means the CRM code is offered under an open-source license that grants defined rights to use, inspect, modify and redistribute it subject to that license. Check the exact files and edition: a repository may also contain separately licensed code.
</FaqItem>

<FaqItem question="Is every open-source CRM free to operate?">
  No. A license may not charge a software subscription, but infrastructure,
  backups, upgrades, monitoring, security work and external providers still cost
  money and operator time.
</FaqItem>

<FaqItem question="Does open source guarantee data control or GDPR compliance?">
  No. Self-hosting can give you control over the application and database
  location, but compliance and data flows depend on configuration, connected
  providers, contracts, policies and operations.
</FaqItem>

<FaqItem question="Is all Customermates code AGPL-3.0?">
  No. First-party material outside `ee/` is AGPL-3.0-only. Inside `ee/`, the
  client material identified in Section 6 of `ee/LICENSE.md` is also
  AGPL-3.0-only; the remaining first-party material uses the commercial license.
  Review both license files for the exact boundary.
</FaqItem>

<FaqItem question="Can I import or export CRM records in self-hosted Customermates?">
Yes. Records move in and out as XLSX workbooks, one record type at a time, scoped to the user's read access and the current view, with row limits in both directions. CSV is not accepted, so save CSV files as `.xlsx` first. For anything beyond that, such as attachments or a complete account transfer, design a migration through the REST API.
</FaqItem>
</Faq>
