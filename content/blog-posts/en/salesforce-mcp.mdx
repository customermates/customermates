# Salesforce MCP Explained: Which Server Does What and What It Costs

Yes, Salesforce has its own MCP servers, and when people say "Salesforce MCP" they usually mean **Salesforce Hosted MCP Servers**: endpoints run by Salesforce that let Claude, ChatGPT, Cursor or another MCP client read and change records in your org under each user's own permissions. They have been generally available since 29 April 2026 for Enterprise Edition orgs and above. An administrator has to switch them on, and Salesforce says they are intended for customers with Flex Credits.

Developers used to mean something else: the open-source Salesforce DX MCP server, which ran on their own machine as a [local MCP server](/blog/what-is-an-mcp-server). Salesforce ended it on 2 November 2026. Its repository is archived and its npm package is deprecated, so a new setup should not start with it. MuleSoft and Heroku have MCP offerings of their own. This guide separates the four, shows the setup and the billing rules as Salesforce documents them on 12 November 2026, and compares the approach with a CRM whose MCP server ships with the product. Disclosure: Customermates, the second CRM discussed here, publishes this guide.

## The four Salesforce MCP offerings

| Offering | Who it is for | Where it runs | What it does |
| --- | --- | --- | --- |
| Hosted MCP Servers | Sales, service and AI teams, set up by admins | Hosted by Salesforce | Read, create, update and delete records; query and search; custom tools from Apex, Flows and named queries |
| Salesforce DX MCP server (retired) | Salesforce developers, until 2 November 2026 | Locally, via `npx` | End of life on 2 November 2026: repository archived, npm package deprecated, no further releases |
| MuleSoft MCP Connector | Integration teams | Inside Mule apps | Turns Mule apps into MCP servers or clients, so existing APIs reach AI agents |
| Heroku MCP server | Heroku developers | Locally or deployed to Heroku | Manages Heroku apps, dynos, add-ons, databases and pipelines |

If you work in sales or service and want your AI assistant to see accounts and opportunities, only the first row matters to you. The DX server stays in the table because older guides and search results still present it as the Salesforce MCP server.

## Salesforce Hosted MCP Servers

A hosted MCP server is an endpoint Salesforce runs in front of your org. You don't install anything. Each person connects their AI client, signs in with OAuth, and every tool call runs as that person: object permissions, field-level security and sharing rules apply, and a record the agent changes shows that user's name in the audit trail.

**Standard servers.** Salesforce ships preconfigured servers with fixed tool sets. They are disabled by default, and an admin can enable them but not change their tools. The [standard servers reference](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/servers-reference.html) lists these:

| Server | Scope |
| --- | --- |
| SObject All | Create, read, update, delete, query and search across objects |
| SObject Reads | Read and query only |
| SObject Mutations | Create and update, no delete |
| SObject Deletes | Delete only |
| Data 360 | SQL queries on unified customer data |
| Tableau Next | Semantic models, KPIs and analytics questions |
| Content Read-Only, Content Write | Salesforce CMS workspaces, channels and content |
| Headless 360 (Beta) | Setup and platform capabilities, including Archive Connect tools |
| Metadata Grounding (Beta) | Discovering metadata of a connected org: objects, fields, flows, Apex classes, permission sets |
| Insurance Design Advisor | Validating insurance product setup, pricing configuration and permissions before runtime |
| CRM Analytics (Beta) | Read-only analytics metadata and SAQL; sandbox and scratch orgs only |

The split SObject servers are the practical control here. A pilot group can get SObject Reads first, and write or delete access later, per server rather than per prompt.

**Custom servers.** Beyond the standard set, admins can [build custom servers](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/products-supporting-mcp.html) whose tools are Apex invocable actions, `@AuraEnabled` methods, Apex REST methods, Flows, named queries and API Catalog endpoints. Prompt Builder templates can appear as MCP prompts, though not every client supports MCP prompts. This is where a Salesforce org with years of custom logic gets the most out of MCP: a validated "create renewal opportunity" Flow becomes one tool instead of five raw record writes.

**Change over time.** Salesforce states in its [end-of-life notice](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/end-of-life.html) that tools, prompts and resources may change from release to release and that servers can be retired with advance notice. Pin your expectations to the server reference, not to a blog post from last quarter.

## Is Salesforce MCP free?

Not in a way you can rely on. The [hosted MCP overview](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/hosted-mcp-servers-overview.html) says the servers are "intended only for customers with Flex Credits" and that "you may be billed for server usage".

A Salesforce Help article from 17 September 2026, [Understand AIforce Impact](https://help.salesforce.com/s/articleView?language=en_US&id=005360285&type=1), describes where this is going:

- Salesforce says it is targeting November for agent registration and a new billing model; the article still read that way on 12 November 2026. Each external agent gets its own identity and can get a narrower permission set than the human it works for.
- Every successful call a registered agent makes, over MCP or the direct API, is metered as a Headless Platform Interaction (HPI) against Flex Credits.
- The HPI multiplier is listed as "TBA", and agentic usage isn't metered yet. The [Flex Credits rate card dated 3 November 2026](https://www.salesforce.com/en-us/wp-content/uploads/sites/4/assets/pdf/agentforce/Flex-Credits-Rate-Card-11.3.2026.pdf) still shows "TBA" for the Headless Platform Interaction. Salesforce promises 30 days' notice before metering starts.
- Use of any Salesforce MCP server will require agent registration within three months of Salesforce's notice, for all customers. Existing customers that use agents with Salesforce APIs migrate those connections to the new billing model at renewal.
- Sandboxes, scratch orgs and Developer Edition orgs don't incur HPI metering.
- An org needs Flex Credit billing enabled, for example through Salesforce Foundations, which the article lists as currently available at $0 (checked on 12 November 2026).

So the honest answer on cost is: HPI metering was not active on 12 November 2026, Salesforce already reserves the right to bill for server usage, and the size of the announced per-call charge is unknown. If you plan a rollout to a whole sales team, ask your account executive for the HPI rate before you budget, and run the pilot in a sandbox, where calls are not metered.

## How to turn on Salesforce MCP

Salesforce's GA announcement puts the shortest path at under 30 minutes. The steps below follow the [setup overview](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/setup-overview.html), the guide to [creating an External Client App](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/create-external-client-app.html), Salesforce's [Claude setup page](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/claude.html) and the [GA announcement](https://developer.salesforce.com/blogs/2026/04/salesforce-hosted-mcp-servers-are-now-generally-available).

<Steps>
  <Step title="Check edition and permissions">
    You need an Enterprise Edition org or above (Salesforce's community wiki says Developer Edition orgs can use MCP servers too) and System Administrator (or equivalent) rights to create an External Client App. If the edition is right but no MCP servers appear, the wiki says to ask Salesforce Support to enable the MCPService permission.
  </Step>
  <Step title="Enable a server">
    In Setup, go to API Catalog, then MCP Servers, and enable one server. Start with SObject Reads (platform/sobject-reads) in a sandbox. Salesforce says activation can take up to two minutes.
  </Step>
  <Step title="Create an External Client App">
    In Setup, open External Client App Manager and create a new app; Connected Apps are not supported. Enable OAuth, enter your client's callback URL (for Claude, https://claude.ai/api/mcp/auth_callback), add the Access MCP servers (mcp_api) and Perform requests at any time (refresh_token) scopes, and under Security select the JWT-based access tokens for named users option. Salesforce's quick start also keeps PKCE on. The mcp_api scope grants MCP access only, not the existing REST APIs. The app can take up to 30 minutes to become usable; then copy its consumer key.
  </Step>
  <Step title="Connect the client">
    In Claude, open Customize, then Connectors, then Add custom connector, and enter the server URL: https://api.salesforce.com/platform/mcp/v1/platform/sobject-reads for a production org, or the same address with /sandbox after /v1 for a sandbox. Choose your own OAuth client, paste the consumer key, and leave the secret blank unless your authorization server requires one. An org that blocks logins from login.salesforce.com needs the My Domain URL form on Salesforce's page instead. Salesforce's guide lists callback URLs for ChatGPT, Cursor and Postman too. Sign in and ask a read question about an account you know well, so you can check the answer.
  </Step>
  <Step title="Widen access deliberately">
    Add SObject Mutations or custom servers for a named pilot group once reads behave as expected. Keep SObject Deletes off unless someone needs it.
  </Step>
</Steps>

## The Salesforce DX MCP server

The [Salesforce DX MCP server](https://github.com/salesforcecli/mcp) was an open-source developer tool under Apache 2.0 that ran locally with `npx @salesforce/mcp`, and it reached end of life on 2 November 2026. The repository banner and Salesforce's [end-of-life notice](https://github.com/forcedotcom/mcp/issues/46) say it is no longer maintained or supported and that no further releases will ship. On 12 November 2026 both repositories were archived and the npm package carried a deprecation message. The package stays installable, so a setup pinned to version 0.30.15 keeps running, but nothing will fix it if it breaks.

The notice tells developers to use skills instead and names Salesforce's [skills and plugins library](https://github.com/forcedotcom/sf-skills) as the public location. Its README lists installation for Claude Code, Codex, Cursor and others, and warns that skills may be renamed or removed between releases. Separately, the hosted Metadata Grounding server (beta) lets an AI client look up an org's metadata. The DX server was never the way for a sales rep to reach CRM data: that is the job of the hosted servers above.

## MuleSoft and Heroku MCP

The [MuleSoft MCP Connector](https://docs.mulesoft.com/mcp-connector/latest/) lets Mule apps act as MCP servers or MCP clients. That matters when an AI agent should reach an ERP or legacy system that has no MCP server of its own, with MuleSoft in between. Heroku publishes an [Apache 2.0 MCP server](https://github.com/heroku/heroku-mcp-server) that runs through the Heroku CLI or `npx`, or can be deployed to Heroku, and manages apps, dynos, add-ons and pipelines. Neither is a sales tool.

## Which one you need

| Your situation | Use |
| --- | --- |
| Reps should ask an AI client about accounts, contacts and opportunities | Hosted MCP Servers, starting with SObject Reads |
| An AI client should run your existing business logic | A custom hosted server built on your Flows or Apex actions |
| A coding assistant should work on metadata, tests and deployments | Not the DX MCP server (retired 2 November 2026); Salesforce points to its [skills library](https://github.com/forcedotcom/sf-skills) |
| Agents should reach systems outside Salesforce through existing integrations | MuleSoft MCP Connector |
| You manage apps on Heroku | Heroku MCP server |
| You want Salesforce's own agent inside the platform rather than an external client | Agentforce, covered in the [Agentforce guide](/blog/agentforce) |

## A CRM with a built-in MCP server

If you have not committed to Salesforce yet, there is a different model: a CRM whose MCP server is part of the product. Customermates is one. It is an open-source, AI-native CRM for small client-facing teams, and it exposes one MCP endpoint at `/api/v1/mcp` on every cloud plan and on self-hosted installations. A connected client discovers [[derived.mcp.tools.total]] tools for contacts, organizations, deals, services, tasks and your own lists, the data model, saved views, dashboards, routines and webhooks. On Pro and higher, in Customermates Cloud, the unified inbox tools for email, LinkedIn, WhatsApp, Instagram and Telegram are added.

Connection works two ways, as the [MCP documentation](/docs/mcp) describes. Claude and ChatGPT connect as a custom connector: paste the URL, sign in, approve. Claude Code, Codex, Cursor and Gemini CLI use an [API key](/docs/api-keys) that inherits its creator's permissions. To expose only part of the tool surface, append `?toolsets=` to the endpoint URL, for example `?toolsets=records`.

| Question | Salesforce Hosted MCP Servers | Customermates MCP |
| --- | --- | --- |
| Who sets it up | System Administrator: server activation and External Client App | Each user connects their own client; creating API keys needs the matching role permission |
| Editions or plans | Enterprise Edition and above | Every cloud plan and self-hosted |
| Usage cost | Flex Credits; per-call HPI metering announced, rate TBA | No per-call charge; your AI client uses your own AI provider |
| Scope control | Separate read, write and delete servers; field-level security | Role permissions per resource and action; toolset narrowing by URL; no field-level permissions |
| Custom tools | Apex, Flows, named queries, API Catalog, prompt templates | Fixed tool catalog; extend through REST and webhooks |
| Licence | Proprietary hosted service; Salesforce's community repository holds documentation, not the server | AGPL core, self-hostable |

The cost arithmetic is plain. A five-person team on Starter pays [[commercial.price.starter.monthly.seats.5]] per month and gets the full CRM tool set over MCP. The inbox tools need Pro, [[commercial.price.pro.monthly.seats.5]] per month for the same team. The AI client's own subscription comes on top, from Anthropic, OpenAI or whichever provider you use. Current prices are on the [pricing page](/pricing).

One control difference matters. The Customermates MCP server tells clients to get the user's confirmation before deleting or sending, but that confirmation happens in the client. Once an authorized client calls a tool, the server executes it. Check how your client handles approvals, and start with reads and drafts.

For a client-facing team, the point of MCP is follow-up: with LinkedIn and email connected on Customermates Cloud from Pro, your own Claude or ChatGPT reads the conversation on the client record and drafts the reply and the next step for you to review and send. To try it, [start your trial](/auth/signup?job=followup): [[commercial.trial.days]] days of Pro with no credit card.

**Where Customermates is the wrong choice.** If you already run Salesforce with custom objects, Apex logic, territory or sharing models and field-level security, stay on Salesforce and use the hosted servers: moving loses more than it gains. Customermates also has no custom tool definitions and no field-level permissions. It fits a consultancy, agency or founder-led team choosing its first real CRM, or leaving a large one. ## Frequently asked questions

<Faq>
<FaqItem question="What is Salesforce MCP?">
It is Salesforce's support for the Model Context Protocol, the open standard that lets AI clients call tools in other systems. In practice it means Salesforce Hosted MCP Servers for CRM data, plus MCP offerings for MuleSoft and Heroku. The local Salesforce DX MCP server for developers reached end of life on 2 November 2026.
</FaqItem>

<FaqItem question="Does Salesforce have its own MCP server?">
Yes. Salesforce runs Hosted MCP Servers itself, generally available since 29 April 2026. Its open-source DX MCP server, a local developer tool, ended on 2 November 2026. Third-party Salesforce MCP servers exist as well, but you don't need one to connect Claude or ChatGPT to Salesforce.
</FaqItem>

<FaqItem question="Is the Salesforce DX MCP server still supported?">
No. Salesforce's notice says it reached end of life on 2 November 2026 and is no longer maintained or supported, with no further releases. Both repositories are archived and the npm package is deprecated but still installable, so a pinned version keeps running. For new work, use the hosted servers for CRM data and Salesforce's skills library for development.
</FaqItem>

<FaqItem question="Is Salesforce MCP free?">
Not reliably. The hosted servers are intended for customers with Flex Credits, and Salesforce has announced per-call metering for registered agents. As of 12 November 2026 the rate is listed as TBA and not yet metered, and sandboxes, scratch orgs and Developer Edition orgs are exempt from that metering. The retired DX MCP server was free open-source software.
</FaqItem>

<FaqItem question="How do I turn on Salesforce MCP?">
A System Administrator enables a server in Setup under API Catalog, then MCP Servers, creates an External Client App with the mcp_api and refresh_token scopes and JWT-based access tokens, and adds the client's callback URL. Users then add the server URL as a custom connector in their AI client and sign in with OAuth.
</FaqItem>

<FaqItem question="Which Salesforce editions support hosted MCP servers?">
Salesforce describes them as available for every Enterprise Edition org and above, and its community wiki adds that Developer Edition orgs can use them. Some individual servers, such as Headless 360, Metadata Grounding and CRM Analytics, are still marked beta.
</FaqItem>

<FaqItem question="Does Salesforce MCP respect user permissions?">
Yes. Each call runs as the signed-in user, so object permissions, field-level security and sharing rules apply. If a user cannot do something in Salesforce, the agent cannot do it for them either.
</FaqItem>
</Faq>
