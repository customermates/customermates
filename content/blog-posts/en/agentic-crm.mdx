# Agentic and AI-Native CRM: MCP, Mate and Safe Actions

An **AI-native CRM** exposes structured customer data and typed actions that AI can use. An **agentic CRM** lets an AI client or assistant carry out supported work with those interfaces: reading context, creating or updating records, preparing a draft, or completing a workflow. The terms overlap, but one describes architecture while the other describes behavior.

Customermates supports this model through external AI clients connected by MCP. The product also contains a cloud-only in-app assistant capability called Mate, but its production availability depends on hosted configuration and release conditions. This page therefore describes the capability without claiming that Mate is generally available.

## What makes a CRM agentic?

A useful agentic CRM needs four things:

1. **Structured context:** contacts, organizations, deals, services and tasks the client can address reliably.
2. **Typed actions:** tools that create, read, update or otherwise operate supported records.
3. **Permissions:** every action remains constrained by the requesting user's access.
4. **Control boundaries:** the chosen client, server permissions and any assistant-specific approval gates must be understood separately.

That is different from a chatbot that only writes text. It is also different from promising autonomous lead scoring, enrichment, forecasting or outreach that the product does not provide.

## Two AI paths in Customermates

| Path | Where it runs | Model and credits | Availability boundary |
| --- | --- | --- | --- |
| External AI client through MCP | Cloud or self-hosted | The customer selects and funds the external provider | MCP is the current open integration surface |
| Mate in-app assistant capability | Customermates Cloud only | Hosted plan allowances apply to the capability | Live production state remains release-gated |

The [MCP documentation](/docs/mcp) is the source for setup and the changing tool catalog. Customermates currently registers [[derived.mcp.tools.total]] MCP tools; this page does not duplicate their names because the catalog evolves.

## What an AI client can work with

The MCP surface covers supported work across contacts, organizations, deals, services, tasks, custom fields, dashboards, webhooks and related CRM resources. An external client can combine those typed tools into a workflow while the CRM keeps record validation and permissions on the server.

On entitled cloud accounts, MCP also exposes supported messaging work for the [unified inbox](/features/unified-inbox), such as reading threads, saving drafts, triaging conversations and sending replies. The inbox supports email, LinkedIn, WhatsApp, Instagram and Telegram connections—not SMS or telephony.

## Approval boundaries differ between MCP and Mate

Agentic does not mean permissionless. The MCP server instructions tell clients to request explicit confirmation before every delete or outbound `send_*` action. That is client guidance, not a second server-side approval gate: once an authorized client calls the MCP tool, the server executes the permitted action. Verify that your chosen client shows the exact side effect and waits for approval.

The Mate capability has separate, enforced per-call approval gates for destructive actions, sends and resends, invitations, support escalation, and changes to external or social accounts. Those code-level safeguards describe how the capability is designed; they do not prove its production enablement.

## Cloud and self-hosted boundaries

| Capability | Customermates Cloud | Self-hosted Customermates |
| --- | --- | --- |
| Core CRM | Yes | Yes |
| MCP for external AI clients | Yes | Yes |
| Unified inbox | Pro and above | No |
| Hosted Mate capability | Cloud only, release-gated | No |
| Hosted AI credits | Plan-based capability | No |

Self-hosting uses Starter entitlements. It remains a strong option for teams that want an [open-source, self-hosted CRM](/features/self-hosted) and prefer to connect their own AI client and provider through MCP.

## Agentic CRM and AI-native CRM

“AI-native CRM” usually describes architecture: the CRM exposes structured data and actions that AI can use. “Agentic CRM” describes behavior: an AI system can carry out supported work. A product can be AI-operable without pretending that every process is autonomous.

For buyers, the practical questions matter more than the label:

- Which records and actions are exposed?
- Which permissions are checked on the server?
- Which actions need confirmation?
- Who selects the model provider and pays for usage?
- Which features differ between cloud and self-hosted editions?
- Can you inspect the exact tool documentation before granting access?

## How to start with MCP

1. Review the [MCP tool and connection guide](/docs/mcp).
2. Choose an AI client and provider appropriate for your data policy.
3. Grant only the CRM permissions needed for the workflow.
4. Start with reversible read and draft tasks.
5. Verify the client's confirmation behavior before enabling deletes or outbound sends.

[Read the MCP guide](/docs/mcp) to evaluate the current integration. If you also want to evaluate the managed CRM, [start a cloud trial](/auth/signup) without treating signup as proof that the release-gated Mate capability is live.

## Frequently asked questions

<Faq>
<FaqItem question="What is an agentic CRM?">
It is a CRM whose structured records and actions can be operated by an authorized AI client or assistant. A responsible implementation keeps server-side permissions and explicit approval boundaries for destructive or external actions.
</FaqItem>

<FaqItem question="Is Mate generally available in Customermates Cloud?">
This page does not make that claim. Product code contains the cloud-only Mate capability and a global kill switch, but the production configuration and release conditions are not proven here. External MCP clients remain the current documented integration path.
</FaqItem>

<FaqItem question="Can I use an external AI client with self-hosted Customermates?">
Yes. MCP is available in self-hosted deployments. You choose and fund the external client and model provider; hosted Mate and hosted AI credits are not included.
</FaqItem>

<FaqItem question="Where is confirmation enforced?">
MCP instructions tell compatible clients to request confirmation before sends and deletes, but the MCP server does not add a second approval gate after the client calls a permitted tool. Mate uses separate enforced per-call approval gates. Verify the behavior of the exact client and path you enable.
</FaqItem>

<FaqItem question="Does agentic CRM include predictive lead scoring or forecasting?">
Not in Customermates. The CRM can calculate deterministic weighted deal values from configured stage probabilities, but it does not ship predictive close scoring, enrichment or autonomous revenue forecasting.
</FaqItem>
</Faq>
