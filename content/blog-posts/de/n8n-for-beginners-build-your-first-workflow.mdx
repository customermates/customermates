# Von der leeren Arbeitsfläche zum veröffentlichten n8n-Workflow

n8n lernen Sie am schnellsten, indem Sie einen kleinen Workflow komplett durchbauen: ein Trigger, der Daten empfängt, ein Node, der etwas damit tut, ein Testlauf und zum Schluss **Publish**, damit der Workflow ohne Sie läuft. Alles Größere in n8n folgt demselben Muster, nur mit mehr Nodes. Diese Anleitung zeigt diesen ersten Workflow, die Verwechslung von Test- und Produktions-URL, an der viele Einsteiger hängen bleiben, die Fehlerbehandlung und einen zweiten Workflow, der Website-Anfragen in ein CRM schreibt.

Ein Hinweis vorab: Die offizielle Dokumentation von n8n ist englischsprachig und nennt Buttons und Nodes mit englischen Namen. Diese Anleitung übernimmt diese Namen, damit Sie sie im Editor und in der Dokumentation wiederfinden.

## Die sechs Begriffe, die Sie kennen müssen

Wer diese Begriffe einordnen kann, findet sich im Editor sofort zurecht.

| Begriff | Bedeutung | Wo Sie ihn sehen |
|---|---|---|
| Workflow | Eine Kette von Nodes, die von links nach rechts abläuft | Die Arbeitsfläche (Canvas) |
| Trigger | Der erste Node, der einen Lauf startet: Zeitplan, Webhook-Aufruf, App-Ereignis oder ein manueller Klick | Der erste Node auf der Arbeitsfläche |
| Node | Ein einzelner Schritt: Daten holen, Bedingung prüfen, Nachricht senden, API aufrufen | Alles auf der Arbeitsfläche |
| Expression | Ein Platzhalter, der Daten aus vorherigen Nodes einsetzt, etwa `{{ $json.email }}` | Jedes Feld, nachdem Sie es in den Expression-Modus geschaltet haben |
| Credential | Gespeicherte Zugangsdaten oder ein API-Key, den mehrere Nodes nutzen | Menü „Credentials“ oder „Create new credential“ im Node |
| Execution | Ein vollständiger Lauf eines Workflows, egal wie viele Nodes er hat | Der Tab „Executions“ |

Die letzte Zeile entscheidet über die Kosten. n8n definiert auf der Preisseite eine Execution als einen einzelnen Lauf des gesamten Workflows, unabhängig davon, wie viele Schritte er enthält oder wie viele Daten er verarbeitet. Ein Workflow mit zehn Nodes, der einmal läuft, ist eine Execution.

## Cloud oder selbst gehostet: Wo n8n laufen soll

Es gibt zwei Wege. n8n Cloud braucht nur ein Konto. Die Community Edition ist kostenlos und läuft auf Ihrem Rechner oder Server, den Sie dann selbst pflegen.

| Variante | Preis | Was Sie bekommen |
|---|---|---|
| n8n Cloud Starter | 20 € pro Monat bei jährlicher Zahlung | 2.500 Executions pro Monat, 5 gleichzeitige Executions, unbegrenzt viele Nutzer |
| n8n Cloud Pro | 50 € pro Monat bei jährlicher Zahlung | 10.000 Executions pro Monat, mehr gleichzeitige Executions, Admin-Rollen, längere Workflow-Historie |
| Community Edition (selbst gehostet) | Software kostenlos, Sie zahlen den Server | Läuft auf Ihrer Infrastruktur, unter der Sustainable Use License von n8n |

Preise am 8. Oktober 2026 auf der [Preisseite von n8n](https://n8n.io/pricing/) geprüft. Monatliche Zahlung ist ebenfalls möglich und teurer; die Seite bewirbt die jährliche Zahlung mit 17 % Ersparnis. Die Cloud-Testphase bietet Pro-Funktionen mit einer Grenze von 1.000 Executions und ohne Kreditkarte.

Zwei Unterschiede bestimmen, was Sie als Einsteiger tun können:

- **Community Nodes.** n8n Cloud installiert nur verifizierte Community Nodes. Nicht verifizierte brauchen laut [Dokumentation zu Community Nodes](https://docs.n8n.io/integrations/community-nodes/installation/) eine selbst gehostete Instanz.
- **Lizenz.** Die Community Edition steht unter der [Sustainable Use License](https://github.com/n8n-io/n8n/blob/master/LICENSE.md). Sie erlaubt die Nutzung für eigene interne Geschäftszwecke sowie nicht kommerzielle und private Zwecke. Die Automatisierung Ihres eigenen Unternehmens ist damit abgedeckt, der Weiterverkauf von n8n als gehosteter Dienst nicht.

**Nehmen Sie die Cloud,** wenn Sie heute anfangen wollen und niemand im Team einen Server betreuen möchte. **Hosten Sie selbst,** wenn Sie nicht verifizierte Community Nodes brauchen, die Daten auf eigener Infrastruktur halten wollen oder so viele Läufe erwarten, dass die Execution-Grenzen teurer wären als ein kleiner Server.

Für einen lokalen Test der Community Edition ist Docker der kürzeste Weg. Das ist eine verkürzte Fassung des Befehls aus der [Docker-Anleitung von n8n](https://docs.n8n.io/hosting/installation/docker/):

```bash
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 \
  -v n8n_data:/home/node/.n8n n8nio/n8n
```

Danach öffnen Sie `http://localhost:5678`. Die Anleitung ergänzt Zeitzonen-Einstellungen, und für einen dauerhaft laufenden Server verweist n8n auf das Setup mit Docker Compose und HTTPS. Zum Lernen genügt die lokale Instanz. Aus dem Internet ist sie allerdings nicht erreichbar, und das wird wichtig, sobald ein Cloud-Dienst Ihren Webhook aufrufen soll.

## Ihr erster Workflow: eine Anfrage, die Ihnen eine E-Mail schickt

Der Workflow empfängt JSON-Daten, wie ein Kontaktformular sie senden würde, prüft, ob eine E-Mail-Adresse enthalten ist, und schickt Ihnen die Angaben per E-Mail. Er besteht aus drei Nodes und deckt alle Grundbegriffe ab.

<Steps>
  <Step title="Workflow anlegen und Webhook-Trigger hinzufügen">
    Legen Sie einen neuen Workflow an und fügen Sie den **Webhook**-Node als Trigger hinzu. Stellen Sie die HTTP-Methode auf `POST` und geben Sie dem Pfad einen lesbaren Namen wie `anfrage`. Der Node zeigt zwei Adressen, eine Test-URL und eine Produktions-URL. Kopieren Sie die Test-URL.
  </Step>
  <Step title="Testdaten senden">
    Klicken Sie auf **Listen for test event**. n8n wartet jetzt auf einen Aufruf. Senden Sie aus dem Terminal eine Beispielanfrage an die Test-URL:

    ```bash
    curl -X POST "<ihre-test-url>" \
      -H "Content-Type: application/json" \
      -d '{"firstName":"Lisa","lastName":"Meyer","email":"lisa@example.com","message":"Können wir über eine Zusammenarbeit sprechen?"}'
    ```

    Im Ausgabebereich des Nodes erscheinen nun die vier Felder. Pinnen Sie diese Ausgabe, damit spätere Testläufe sie ohne neuen curl-Aufruf verwenden.
  </Step>
  <Step title="If-Node hinzufügen">
    Verbinden Sie einen **If**-Node und legen Sie eine Bedingung an: `{{ $json.body.email }}` ist nicht leer. Webhook-Daten kommen unter `body` an. An diesem Detail scheitern viele bei ihrer ersten Expression. Was die Bedingung erfüllt, läuft über den **true**-Zweig weiter.
  </Step>
  <Step title="E-Mail-Node an den true-Zweig hängen">
    Fügen Sie einen **Gmail**-Node hinzu (oder **Send Email** mit SMTP-Zugangsdaten) und legen Sie das Credential an, wenn der Node danach fragt. Schreiben Sie in den Betreff `Neue Anfrage von {{ $json.body.firstName }} {{ $json.body.lastName }}` und übernehmen Sie Nachricht und E-Mail-Adresse in den Text.
  </Step>
  <Step title="Den ganzen Workflow ausführen">
    Klicken Sie auf **Execute workflow** und senden Sie den curl-Aufruf erneut. Jeder Node, der gelaufen ist, zeigt die Anzahl seiner Items, und ein Klick auf den Node zeigt genau, was hinein- und was herausging. Kommt die E-Mail an, stimmt die Logik.
  </Step>
  <Step title="Veröffentlichen und auf die Produktions-URL wechseln">
    Klicken Sie auf **Publish**. Ab jetzt hört der Workflow auf die **Produktions-URL**, und genau diese Adresse muss Ihr Formular aufrufen. Produktive Läufe erscheinen nicht auf der Arbeitsfläche, Sie finden sie im Tab **Executions**.
  </Step>
</Steps>

### Test-URL oder Produktions-URL?

Die Verwechslung der beiden Adressen ist eine häufige Ursache für Fragen der Art „mein Webhook funktioniert nicht“. Die [Dokumentation des Webhook-Nodes](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/) trennt beide so:

| | Test-URL | Produktions-URL |
|---|---|---|
| Aktiv, wenn | Sie **Listen for test event** oder **Execute workflow** klicken | Der Workflow veröffentlicht ist |
| Daten auf der Arbeitsfläche sichtbar | Ja | Nein, prüfen Sie den Tab **Executions** |
| Wofür | Bauen und Fehlersuche | Das echte Formular, die App oder den CRM-Webhook |

Liefert ein Aufruf der Produktions-URL einen Fehler, prüfen Sie zuerst, ob der Workflow veröffentlicht ist, und danach, ob der Aufrufer die richtige Methode verwendet (hier `POST`).

## Fehlerbehandlung, bevor Sie sich auf den Workflow verlassen

Ein veröffentlichter Workflow meldet Fehler niemandem, solange Sie n8n nicht sagen, wohin Fehler gemeldet werden sollen. Zwei Einstellungen decken die meisten Fälle ab.

1. **Ein Error-Workflow.** Legen Sie einen eigenen Workflow an, der mit dem **Error Trigger**-Node beginnt und Ihnen eine E-Mail mit dem Namen des fehlgeschlagenen Workflows und der Fehlermeldung schickt. Öffnen Sie dann den ursprünglichen Workflow, gehen Sie auf **Options > Settings** und wählen Sie ihn unter **Error workflow** aus. Welche Daten der Error Trigger erhält, steht in der [Dokumentation zur Fehlerbehandlung](https://docs.n8n.io/flow-logic/error-handling/).
2. **Node-Einstellungen.** Jeder Node hat einen Tab mit Einstellungen. Für Aufrufe externer APIs schalten Sie **Retry On Fail** ein. Bei Schritten, deren Ausfall nicht schadet, etwa einer Protokollierung, stellen Sie **On Error** auf **Continue**, damit der Rest des Laufs durchläuft.

Vergeben Sie bei der Gelegenheit klare Namen. „Anfrage: Website-Formular ins CRM“ in einer Fehler-E-Mail zeigt Ihnen sofort, wo Sie suchen müssen. „My workflow 3“ nicht.

## Zweiter Workflow: Website-Anfrage ins CRM

Sinnvoll wird der erste Workflow, wenn die Anfrage dort landet, wo Ihr Team mit Kunden arbeitet. Das Muster ist für jedes CRM mit REST-API gleich: per API-Key anmelden, die Formularfelder den Feldnamen des CRM zuordnen, eine HTTP-Anfrage senden. Das Beispiel nutzt Customermates, das CRM, das diese Anleitung veröffentlicht, weil dessen API-Details öffentlich dokumentiert sind.

<Steps>
  <Step title="API-Key anlegen">
    Öffnen Sie in Customermates **Mein Profil → API & Konnektoren**, klicken Sie auf **Hinzufügen** und wählen Sie **Standard-API-Key**. Der Key hat dieselben Berechtigungen wie der Nutzer, der ihn angelegt hat. Legen Sie ihn also mit einem Nutzer an, der Kontakte erstellen darf. Details stehen unter [API-Keys](/docs/api-keys).
  </Step>
  <Step title="Als n8n-Credential speichern">
    Legen Sie in n8n ein **Header Auth**-Credential mit dem Header-Namen `x-api-key` und dem Key als Wert an. Alle Nodes, die mit dem CRM kommunizieren, nutzen es, sodass Sie einen neuen Key nur an einer Stelle eintragen.
  </Step>
  <Step title="E-Mail-Node durch einen HTTP-Request-Node ersetzen">
    Hängen Sie an den true-Zweig des If-Nodes einen **HTTP Request**-Node: Methode `POST`, URL `<ihre-customermates-adresse>/api/v1/contacts`, Authentifizierung über das Header-Auth-Credential und dieser JSON-Body:

    ```json
    {
      "firstName": "{{ $json.body.firstName }}",
      "lastName": "{{ $json.body.lastName }}",
      "identifiers": [{ "provider": "mail", "value": "{{ $json.body.email }}" }],
      "notes": "Website-Anfrage: {{ $json.body.message }}"
    }
    ```

    Vor- und Nachname sind Pflicht. Die E-Mail-Adresse gehört in `identifiers` mit dem Provider `mail`. So verknüpft Customermates einen Kontakt mit seinen E-Mail-Konversationen.
  </Step>
  <Step title="Benachrichtigung behalten">
    Lassen Sie hinter dem HTTP-Request-Node den E-Mail-Node stehen, damit jemand den neuen Kontakt bemerkt. Testen Sie mit den gepinnten Daten, prüfen Sie den Kontakt im CRM und veröffentlichen Sie den Workflow.
  </Step>
</Steps>

Die Gegenrichtung funktioniert ebenfalls. Unter **Mein Unternehmen → Webhooks → Hinzufügen** schickt Customermates einen POST an einen n8n-Webhook-Node, sobald ein abonniertes Ereignis eintritt, etwa `contact.created` oder `deal.updated`. Setzen Sie ein Secret, damit n8n die Signatur prüfen kann. Den Aufbau der Daten zeigt die [Webhook-Referenz](/docs/webhooks). Ein praktischer Haken: Customermates Cloud erreicht keine n8n-Instanz auf `localhost`. Für diese Richtung brauchen Sie n8n Cloud oder ein selbst gehostetes n8n mit öffentlicher HTTPS-Adresse.

Einige Details aus der [n8n-Anleitung von Customermates](/docs/n8n) sparen Fehlersuche:

- Wer `null` oder `[]` für ein Beziehungsfeld wie `organizationIds` sendet, entfernt alle bestehenden Verknüpfungen dieser Art. Lassen Sie das Feld weg, bleiben sie erhalten.
- Die `/many`-Endpunkte nehmen höchstens 100 Datensätze pro Anfrage an. Teilen Sie größere Mengen auf.
- Webhook-Zustellungen kommen nicht garantiert in Reihenfolge an. Sortieren Sie sie nach dem Feld `timestamp` in den gelieferten Daten.

Es gibt außerdem einen Community Node von Customermates, `@customermates/n8n-nodes-crm`, mit einem Aktions-Node für Kontakte, Organisationen, Deals, Leistungen und Aufgaben sowie einem Trigger-Node für Webhook-Ereignisse. Da n8n Cloud nur verifizierte Community Nodes installiert, planen Sie dort mit dem HTTP-Request-Weg und nutzen den Community Node auf einem selbst gehosteten n8n.

## Wo Customermates passt und wo nicht

n8n ist ein eigenständiges Produkt und in keinem Customermates-Tarif enthalten. Sie betreiben es selbst oder buchen n8n Cloud. REST-API, Webhooks und MCP funktionieren in jedem Tarif von Customermates Cloud, ab [[commercial.price.starter.monthly]] pro Nutzer und Monat (siehe [Preise](/pricing)), und in der selbst gehosteten Open-Source-Version.

Nicht jede CRM-Automatisierung braucht n8n. Lautet die Aufgabe „jeden Montag die Deals durchsehen, die sich nicht bewegt haben, und zu jedem eine Notiz entwerfen“, ist eher Urteilsvermögen gefragt als Verkabelung. In Customermates Cloud führt eine [Routine](/docs/app-routines) Mate, den Assistenten in der App, nach Zeitplan oder bei einem Datensatz-Ereignis mit einer gespeicherten Anweisung aus und verbraucht dabei gehostete KI-Credits. Soll lieber Ihr eigener KI-Client im CRM arbeiten, verbinden Sie ihn über [MCP](/docs/mcp). n8n ist die richtige Wahl, wenn die Aufgabe fest geregelt ist und mehrere Systeme berührt: Formular, CRM, Tabelle, Team-Chat.

Brauchen Sie nur eine Kontaktliste in einer Tabelle und eine E-Mail pro Anfrage, benötigen Sie für dieses Tutorial gar kein CRM. Ein Google-Sheets-Node am true-Zweig erledigt das.

## Häufige Fragen

<Faq>
<FaqItem question="Was macht n8n genau?">
n8n verbindet Anwendungen über ihre Schnittstellen und führt Abläufe nach dem Muster „wenn dies passiert, tue das“ aus: Formulareingaben im CRM speichern, neue Kontakte in eine Tabelle übernehmen, eine Team-Nachricht senden, wenn sich ein Deal ändert, oder per Zeitplan Daten abrufen und zusammenfassen. Mit KI-Nodes kann ein Workflow auch Sprachmodelle aufrufen.
</FaqItem>

<FaqItem question="Was kostet n8n im Monat?">
Die selbst gehostete Community Edition ist kostenlos, Sie zahlen nur den Server. n8n Cloud Starter kostet 20 € und Pro 50 € pro Monat, jeweils bei jährlicher Zahlung, mit 2.500 beziehungsweise 10.000 Executions pro Monat (am 8. Oktober 2026 auf der [Preisseite von n8n](https://n8n.io/pricing/) geprüft). Monatliche Zahlung ist teurer.
</FaqItem>

<FaqItem question="Wie schwer ist es, n8n zu lernen, und brauche ich Programmierkenntnisse?">
Die Grundlagen sind schnell gelernt: Der erste Workflow in dieser Anleitung kommt mit drei Nodes und einer Expression aus. Programmieren müssen Sie nicht, der Code-Node für JavaScript oder Python ist optional. JSON lesen sollten Sie können, denn jeder Node zeigt seine Daten so an. Die meiste Lernzeit verbringen Sie im Ausgabebereich und vergleichen, was ein Node bekommen und was er weitergegeben hat.
</FaqItem>

<FaqItem question="Ist n8n Open Source?">
Der Quellcode ist auf GitHub öffentlich, die Lizenz ist aber die Sustainable Use License und keine von der OSI anerkannte Open-Source-Lizenz. Sie erlaubt interne geschäftliche, nicht kommerzielle und private Nutzung. Dateien, die als Enterprise Edition gekennzeichnet sind, brauchen eine separate n8n Enterprise License.
</FaqItem>

<FaqItem question="Gibt es ein n8n-Tutorial auf Deutsch?">
Diese Anleitung ist eines. Die offizielle Dokumentation von n8n und die Kurse der n8n Academy sind auf Englisch, und die Dokumentation nennt Buttons wie **Execute workflow** oder **Publish** mit englischen Namen. Es lohnt sich deshalb, diese Begriffe zu kennen, auch wenn Sie mit deutschsprachigen Videos lernen.
</FaqItem>
