# Salesforce MCP spiegato: quale server fa cosa e quanto costa

Sì, Salesforce ha propri server MCP, e quando si parla di «Salesforce MCP» di solito si intendono i **Salesforce Hosted MCP Servers**: endpoint gestiti da Salesforce che permettono a Claude, ChatGPT, Cursor o a un altro client MCP di leggere e modificare i record della tua org con i permessi di ciascun utente. Sono disponibili in via generale dal 29 aprile 2026 per le org Enterprise Edition e superiori. Un amministratore deve attivarli e Salesforce dice che sono destinati ai clienti con Flex Credits.

Gli sviluppatori un tempo intendevano altro: il server MCP open source Salesforce DX, che girava sul loro computer come [server MCP locale](/blog/what-is-an-mcp-server). Salesforce l’ha chiuso il 2 novembre 2026: il repository è archiviato e il pacchetto npm è contrassegnato come deprecato, quindi una nuova configurazione non dovrebbe partire da lì. Anche MuleSoft e Heroku hanno offerte MCP proprie. Questa guida distingue le quattro, mostra la configurazione e le regole di fatturazione come Salesforce le documenta al 12 novembre 2026 e confronta l’approccio con un CRM il cui server MCP è incluso nel prodotto. Trasparenza: Customermates, il secondo CRM di cui si parla qui, pubblica questa guida.

## Le quattro offerte MCP di Salesforce

| Offerta | Per chi è | Dove gira | Cosa fa |
| --- | --- | --- | --- |
| Hosted MCP Servers | Team di vendita, assistenza e IA, configurati dagli admin | Ospitato da Salesforce | Leggere, creare, aggiornare ed eliminare record; interrogare e cercare; strumenti personalizzati da Apex, Flow e query con nome |
| Server MCP Salesforce DX (ritirato) | Sviluppatori Salesforce, fino al 2 novembre 2026 | In locale, tramite `npx` | Fine vita il 2 novembre 2026: repository archiviato, pacchetto npm deprecato, nessuna nuova release |
| MuleSoft MCP Connector | Team di integrazione | Dentro le app Mule | Trasforma le app Mule in server o client MCP, così le API esistenti raggiungono gli agenti IA |
| Server MCP Heroku | Sviluppatori Heroku | In locale o distribuito su Heroku | Gestisce app Heroku, dyno, add-on, database e pipeline |

Se lavori nelle vendite o nell’assistenza e vuoi che il tuo assistente IA veda account e opportunità, ti interessa solo la prima riga. Il server DX resta nella tabella perché guide più vecchie e risultati di ricerca lo presentano ancora come il server MCP di Salesforce.

## Salesforce Hosted MCP Servers

Un server MCP ospitato è un endpoint che Salesforce gestisce davanti alla tua org. Non installi nulla. Ogni persona collega il proprio client IA, accede con OAuth e ogni chiamata a uno strumento viene eseguita come quella persona: valgono i permessi sugli oggetti, la sicurezza a livello di campo e le regole di condivisione, e un record modificato dall’agente mostra il nome di quell’utente nel registro di audit.

**Server standard.** Salesforce fornisce server preconfigurati con insiemi di strumenti fissi. Sono disattivati per impostazione predefinita e un admin può abilitarli ma non cambiarne gli strumenti. Il [riferimento dei server standard](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/servers-reference.html) elenca questi:

| Server | Ambito |
| --- | --- |
| SObject All | Creare, leggere, aggiornare, eliminare, interrogare e cercare tra gli oggetti |
| SObject Reads | Solo lettura e interrogazione |
| SObject Mutations | Creare e aggiornare, senza eliminare |
| SObject Deletes | Solo eliminazione |
| Data 360 | Query SQL sui dati unificati dei clienti |
| Tableau Next | Modelli semantici, KPI e domande di analisi |
| Content Read-Only, Content Write | Spazi di lavoro, canali e contenuti di Salesforce CMS |
| Headless 360 (Beta) | Setup e funzionalità della piattaforma, compresi gli strumenti Archive Connect |
| Metadata Grounding (Beta) | Scoprire i metadati di un’org collegata: oggetti, campi, Flow, classi Apex, set di permessi |
| Insurance Design Advisor | Convalidare configurazione dei prodotti assicurativi, prezzi e permessi prima dell’esecuzione |
| CRM Analytics (Beta) | Metadati di analisi in sola lettura e SAQL; solo sandbox e scratch org |

I server SObject separati sono il controllo pratico. Un gruppo pilota può ricevere prima SObject Reads, e l’accesso in scrittura o di eliminazione dopo, per server e non per prompt.

**Server personalizzati.** Oltre all’insieme standard, gli admin possono [creare server personalizzati](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/products-supporting-mcp.html) i cui strumenti sono azioni invocabili Apex, metodi `@AuraEnabled`, metodi Apex REST, Flow, query con nome ed endpoint dell’API Catalog. I template di Prompt Builder possono comparire come prompt MCP, anche se non tutti i client supportano i prompt MCP. È qui che un’org Salesforce con anni di logica personalizzata ricava di più da MCP: un Flow convalidato «crea opportunità di rinnovo» diventa uno strumento invece di cinque scritture grezze di record.

**Cambiamenti nel tempo.** Salesforce afferma nel suo [avviso di fine vita](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/end-of-life.html) che strumenti, prompt e risorse possono cambiare da una release all’altra e che i server possono essere ritirati con preavviso. Basa le tue aspettative sul riferimento dei server, non su un articolo di blog del trimestre scorso.

## Salesforce MCP è gratuito?

Non in un modo su cui contare. La [panoramica dei server MCP ospitati](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/hosted-mcp-servers-overview.html) dice che i server sono «destinati solo ai clienti con Flex Credits» e che «l’utilizzo del server potrebbe esserti fatturato».

Un articolo di Salesforce Help del 17 settembre 2026, [Understand AIforce Impact](https://help.salesforce.com/s/articleView?language=en_US&id=005360285&type=1), descrive dove si sta andando:

- Salesforce dice di puntare a novembre per la registrazione degli agenti e un nuovo modello di fatturazione; l’articolo diceva ancora lo stesso il 12 novembre 2026. Ogni agente esterno ottiene la propria identità e può avere un insieme di permessi più ristretto della persona per cui lavora.
- Ogni chiamata riuscita di un agente registrato, via MCP o tramite l’API diretta, viene misurata come Headless Platform Interaction (HPI) rispetto ai Flex Credits.
- Il moltiplicatore HPI è indicato come «TBA», e l’uso agentico non viene ancora misurato. Il [tariffario dei Flex Credits del 3 novembre 2026](https://www.salesforce.com/en-us/wp-content/uploads/sites/4/assets/pdf/agentforce/Flex-Credits-Rate-Card-11.3.2026.pdf) indica ancora «TBA» per la Headless Platform Interaction. Salesforce promette 30 giorni di preavviso prima dell’inizio della misurazione.
- L’uso di qualsiasi server MCP di Salesforce richiederà la registrazione dell’agente entro tre mesi dall’avviso di Salesforce, per tutti i clienti. I clienti esistenti che usano agenti con le API di Salesforce migrano queste connessioni al nuovo modello di fatturazione al rinnovo.
- Sandbox, scratch org e org Developer Edition non comportano la misurazione HPI.
- Un’org deve avere attiva la fatturazione a Flex Credit, per esempio tramite Salesforce Foundations, che l’articolo indica come attualmente disponibile a 0 $ (verificato il 12 novembre 2026).

Quindi la risposta onesta sul costo è: la misurazione HPI non era attiva il 12 novembre 2026, Salesforce si riserva già il diritto di fatturare l’uso dei server e l’entità dell’addebito a chiamata annunciato è sconosciuta. Se pianifichi un’introduzione per un intero team di vendita, chiedi il tasso HPI al tuo account executive prima di fare il budget e svolgi il pilota in una sandbox, dove le chiamate non vengono misurate.

## Come attivare Salesforce MCP

L’annuncio della disponibilità generale di Salesforce indica il percorso più breve in meno di 30 minuti. I passi qui sotto seguono la [panoramica della configurazione](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/setup-overview.html), la guida per [creare una External Client App](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/create-external-client-app.html), la [pagina di Salesforce su Claude](https://developer.salesforce.com/docs/platform/hosted-mcp-servers/guide/claude.html) e l’[annuncio della disponibilità generale](https://developer.salesforce.com/blogs/2026/04/salesforce-hosted-mcp-servers-are-now-generally-available).

<Steps>
  <Step title="Controlla edizione e permessi">
    Ti serve un’org Enterprise Edition o superiore (il wiki della community di Salesforce dice che anche le org Developer Edition possono usare i server MCP) e i diritti di System Administrator (o equivalenti) per creare una External Client App. Se l’edizione è giusta ma non compare alcun server MCP, il wiki indica di chiedere al supporto Salesforce di attivare il permesso MCPService.
  </Step>
  <Step title="Abilita un server">
    In Setup vai su API Catalog, poi MCP Servers, e abilita un server. Parti da SObject Reads (platform/sobject-reads) in una sandbox. Salesforce dice che l’attivazione può richiedere fino a due minuti.
  </Step>
  <Step title="Crea una External Client App">
    In Setup apri External Client App Manager e crea una nuova app; le Connected App non sono supportate. Abilita OAuth, inserisci l’URL di callback del tuo client (per Claude: https://claude.ai/api/mcp/auth_callback), aggiungi gli scope Access MCP servers (mcp_api) e Perform requests at any time (refresh_token) e, sotto Security, seleziona l’opzione dei token di accesso JWT per utenti nominali. La guida rapida di Salesforce mantiene attivo anche PKCE. Lo scope mcp_api concede solo l’accesso MCP, non le API REST esistenti. L’app può impiegare fino a 30 minuti per diventare utilizzabile; poi copia la sua consumer key.
  </Step>
  <Step title="Collega il client">
    In Claude apri Customize, poi Connectors, poi Add custom connector, e inserisci l’URL del server: https://api.salesforce.com/platform/mcp/v1/platform/sobject-reads per un’org di produzione, oppure lo stesso indirizzo con /sandbox dopo /v1 per una sandbox. Scegli il tuo client OAuth, incolla la consumer key e lascia vuoto il secret, a meno che il tuo server di autorizzazione non ne richieda uno. Un’org che blocca gli accessi da login.salesforce.com ha bisogno della forma di URL My Domain descritta nella pagina di Salesforce, che indica anche gli URL di callback per ChatGPT, Cursor e Postman. Accedi e fai una domanda di lettura su un account che conosci bene, così puoi verificare la risposta.
  </Step>
  <Step title="Amplia l’accesso con criterio">
    Aggiungi SObject Mutations o server personalizzati per un gruppo pilota con nomi precisi quando le letture si comportano come previsto. Tieni disattivato SObject Deletes finché qualcuno non ne ha bisogno.
  </Step>
</Steps>

## Il Salesforce DX MCP server

Il [server MCP Salesforce DX](https://github.com/salesforcecli/mcp) era uno strumento open source per sviluppatori con licenza Apache 2.0, che girava in locale con `npx @salesforce/mcp`; è giunto a fine vita il 2 novembre 2026. Il banner del repository e l’[avviso di fine vita](https://github.com/forcedotcom/mcp/issues/46) di Salesforce dicono che non è più mantenuto né supportato e che non verranno pubblicate altre release. Al 12 novembre 2026 entrambi i repository erano archiviati e il pacchetto npm riportava un messaggio di deprecazione. Il pacchetto resta installabile, quindi una configurazione bloccata sulla versione 0.30.15 continua a funzionare, ma nessuno la correggerà se si rompe.

L’avviso invita gli sviluppatori a usare le skill e indica come posizione pubblica la [libreria di skill e plugin di Salesforce](https://github.com/forcedotcom/sf-skills). Il suo README elenca l’installazione per Claude Code, Codex, Cursor e altri e avverte che le skill possono essere rinominate o rimosse da una release all’altra. Separatamente, il server ospitato Metadata Grounding (beta) permette a un client IA di consultare i metadati di un’org. Il server DX non è mai stato il modo in cui un venditore raggiunge i dati CRM: quello è il compito dei server ospitati descritti sopra.

## MuleSoft e Heroku MCP

Il [MuleSoft MCP Connector](https://docs.mulesoft.com/mcp-connector/latest/) permette alle app Mule di agire come server MCP o client MCP. Conta quando un agente IA deve raggiungere un ERP o un sistema legacy che non ha un proprio server MCP, con MuleSoft nel mezzo. Heroku pubblica un [server MCP Apache 2.0](https://github.com/heroku/heroku-mcp-server) che gira tramite la Heroku CLI o `npx`, oppure può essere distribuito su Heroku, e gestisce app, dyno, add-on e pipeline. Nessuno dei due è uno strumento di vendita.

## Un CRM con un server MCP integrato

Se non ti sei ancora impegnato con Salesforce, esiste un modello diverso: un CRM il cui server MCP fa parte del prodotto. Customermates è uno di questi. È un CRM open source e nativo per l’IA per piccoli team a contatto con i clienti, ed espone un endpoint MCP a `/api/v1/mcp` su ogni piano cloud e sulle installazioni self-hosted. Un client collegato scopre [[derived.mcp.tools.total]] strumenti per contatti, organizzazioni, trattative, servizi, attività e i tuoi elenchi, il modello dati, le viste salvate, le dashboard, le routine e i webhook. Da Pro in su, in Customermates Cloud, si aggiungono gli strumenti della Posta in arrivo unificata per e-mail, LinkedIn, WhatsApp, Instagram e Telegram.

La connessione funziona in due modi, come descrive la [documentazione MCP](/docs/mcp). Claude e ChatGPT si collegano come connettore personalizzato: incolla l’URL, accedi, approva. Claude Code, Codex, Cursor e Gemini CLI usano una [chiave API](/docs/api-keys) che eredita i permessi di chi l’ha creata. Per esporre solo una parte degli strumenti, aggiungi `?toolsets=` all’URL dell’endpoint, per esempio `?toolsets=records`.

| Domanda | Salesforce Hosted MCP Servers | Customermates MCP |
| --- | --- | --- |
| Chi lo configura | System Administrator: attivazione del server ed External Client App | Ogni utente collega il proprio client; per creare chiavi API serve il relativo permesso di ruolo |
| Edizioni o piani | Enterprise Edition e superiori | Ogni piano cloud e self-hosted |
| Costo d’uso | Flex Credits; misurazione HPI a chiamata annunciata, tariffa TBA | Nessun addebito a chiamata; il tuo client IA usa il tuo fornitore di IA |
| Controllo dell’ambito | Server separati per lettura, scrittura ed eliminazione; sicurezza a livello di campo | Permessi di ruolo per risorsa e azione; restrizione dei toolset tramite URL; nessun permesso a livello di campo |
| Strumenti personalizzati | Apex, Flow, query con nome, API Catalog, template di prompt | Catalogo di strumenti fisso; si estende tramite REST e webhook |
| Licenza | Servizio ospitato proprietario; il repository della community di Salesforce contiene documentazione, non il server | Core AGPL, installabile in self-hosting |

Il conto dei costi è semplice. Un team di cinque persone su Starter paga [[commercial.price.starter.monthly.seats.5]] al mese e ottiene tutto l’insieme di strumenti CRM via MCP. Gli strumenti della Posta in arrivo richiedono Pro, [[commercial.price.pro.monthly.seats.5]] al mese per lo stesso team. L’abbonamento del client IA si aggiunge, presso Anthropic, OpenAI o qualunque fornitore usi. I prezzi attuali sono nella [pagina dei prezzi](/pricing).

Una differenza di controllo conta. Il server MCP di Customermates indica ai client di ottenere la conferma dell’utente prima di eliminare o inviare, ma quella conferma avviene nel client. Quando un client autorizzato chiama uno strumento, il server lo esegue. Controlla come il tuo client gestisce le approvazioni e parti da letture e bozze.

Per un team a contatto con i clienti, il senso di MCP è il follow-up: con LinkedIn ed e-mail collegati su Customermates Cloud da Pro, il tuo Claude o ChatGPT legge la conversazione sul record del cliente e prepara la bozza di risposta e il passo successivo, che tu rivedi e invii. Per provarlo, [avvia la prova](/auth/signup?job=followup): [[commercial.trial.days]] giorni di Pro senza carta di credito.

**Dove Customermates è la scelta sbagliata.** Se usi già Salesforce con oggetti personalizzati, logica Apex, modelli di territorio o condivisione e sicurezza a livello di campo, resta su Salesforce e usa i server ospitati: il passaggio fa perdere più di quanto dia. Customermates inoltre non ha definizioni di strumenti personalizzati né permessi a livello di campo. Si adatta a una società di consulenza, a un’agenzia o a un team guidato dal founder che sceglie il suo primo vero CRM, o ne lascia uno grande. Il [confronto con le alternative a Salesforce](/compare/salesforce-alternative) tratta questa decisione e la [guida a HubSpot MCP](/blog/hubspot-mcp) tratta il server remoto di HubSpot. Per Salesforce accanto a HubSpot, Pipedrive, Attio e ai server di posta, vedi la [classifica dei migliori server MCP per le vendite](/blog/best-mcp-servers-for-sales).

## Domande frequenti

<Faq>
<FaqItem question="Che cos’è Salesforce MCP?">
È il supporto di Salesforce al Model Context Protocol, lo standard aperto che permette ai client IA di chiamare strumenti in altri sistemi. In pratica significa Salesforce Hosted MCP Servers per i dati CRM e le offerte MCP per MuleSoft e Heroku. Il server MCP locale Salesforce DX per gli sviluppatori è giunto a fine vita il 2 novembre 2026.
</FaqItem>

<FaqItem question="Salesforce ha un proprio server MCP?">
Sì. Salesforce gestisce direttamente gli Hosted MCP Servers, disponibili in via generale dal 29 aprile 2026. Il suo server MCP open source DX, uno strumento locale per sviluppatori, è terminato il 2 novembre 2026. Esistono anche server MCP Salesforce di terze parti, ma non ne hai bisogno per collegare Claude o ChatGPT a Salesforce.
</FaqItem>

<FaqItem question="Salesforce MCP è gratuito?">
Non in modo affidabile. I server ospitati sono destinati ai clienti con Flex Credits e Salesforce ha annunciato una misurazione a chiamata per gli agenti registrati. Al 12 novembre 2026 la tariffa è indicata come TBA e non ancora misurata, e sandbox, scratch org e org Developer Edition sono esentate da quella misurazione. Il server MCP DX, ora ritirato, era software open source gratuito.
</FaqItem>

<FaqItem question="Il server MCP Salesforce DX è ancora supportato?">
No. L’avviso di Salesforce dice che è giunto a fine vita il 2 novembre 2026 e non è più mantenuto né supportato, senza nuove release. Entrambi i repository sono archiviati e il pacchetto npm è deprecato ma ancora installabile, quindi una versione bloccata continua a funzionare. Per nuovi lavori usa i server ospitati per i dati CRM e la libreria di skill di Salesforce per lo sviluppo.
</FaqItem>

<FaqItem question="Come si attiva Salesforce MCP?">
Un System Administrator abilita un server in Setup sotto API Catalog, poi MCP Servers, crea una External Client App con gli scope mcp_api e refresh_token e token di accesso JWT e aggiunge l’URL di callback del client. Gli utenti aggiungono poi l’URL del server come connettore personalizzato nel proprio client IA e accedono con OAuth.
</FaqItem>

<FaqItem question="Quali edizioni di Salesforce supportano i server MCP ospitati?">
Salesforce li descrive come disponibili per ogni org Enterprise Edition e superiore e il suo wiki della community aggiunge che le org Developer Edition possono usarli. Alcuni singoli server, come Headless 360, Metadata Grounding e CRM Analytics, sono ancora indicati come beta.
</FaqItem>

<FaqItem question="Salesforce MCP rispetta i permessi degli utenti?">
Sì. Ogni chiamata viene eseguita come l’utente connesso, quindi valgono i permessi sugli oggetti, la sicurezza a livello di campo e le regole di condivisione. Se un utente non può fare qualcosa in Salesforce, nemmeno l’agente può farlo per lui.
</FaqItem>
</Faq>
