# Mejor CRM open source: cómo comparar opciones autoalojadas

El **mejor CRM open source** es el que tiene una licencia, una vía de autoalojamiento, un esfuerzo de operación y un alcance de CRM que encajan con tu equipo. «Source available», «open core» y «open source» no son intercambiables, y una lista larga de funciones dice poco sobre lo que puedes ejecutar legalmente o mantener de forma realista.

Esta guía usa un marco de evaluación duradero en lugar de ordenar proyectos según precios cambiantes, números de estrellas o afirmaciones sin fuente sobre funciones. Transparencia: Customermates publica esta comparación y es uno de los productos que se tratan abajo.

## Empieza por la licencia, no por la página de inicio

Antes de comparar funciones, identifica:

- la licencia que se aplica al código exacto de servidor y de cliente que necesitas;
- los directorios o módulos regidos por una licencia comercial aparte;
- las obligaciones que se activan al modificar el software o al ofrecerlo a través de una red;
- las restricciones de marca registrada, que son independientes de la licencia del software; y
- si el repositorio es la edición completa que se puede ejecutar o solo una parte.

Un repositorio público no concede automáticamente derechos de código abierto sobre todos sus archivos. Lee los archivos de licencia de la versión que piensas desplegar y consulta con un abogado cuando las obligaciones importen para tu organización.

## Siete criterios para una comparativa de CRM open source

| Criterio | Qué verificar |
| --- | --- |
| Límite de la licencia | ¿Qué código es open source, cuál es comercial y qué obligaciones se aplican? |
| Despliegue | ¿Hay una vía documentada y mantenida para la edición exacta que necesitas? |
| Operación | ¿Quién se encarga de las actualizaciones, las copias de seguridad, la restauración, la monitorización, TLS y la respuesta a incidentes? |
| Modelo del CRM | ¿Cubre los contactos, las organizaciones, las oportunidades, los servicios y las tareas que realmente usas? |
| Interfaces | ¿Hay REST, webhooks o interfaces para agentes disponibles para tu flujo de trabajo? |
| Brecha de edición | ¿Qué capacidades de la nube o de la edición enterprise desaparecen al autoalojar? |
| Migración | ¿Existe una vía real de importación y exportación, o tienes que diseñar una con las API o la base de datos? |

Trata una capacidad sin medir o sin documentar como desconocida, no como incluida.

## Una lista corta sin un ranking falso

Las búsquedas de los mejores CRM open source muestran proyectos con alcances muy distintos. Customermates, SuiteCRM, EspoCRM y Twenty son buenos puntos de partida para una lista corta basada en las fuentes. Odoo Community y CiviCRM pueden ser relevantes cuando el requisito incluye una suite de negocio más amplia o un contexto de membresías. Verifica la licencia oficial vigente, el límite de la edición, la documentación de despliegue y el estado de mantenimiento antes de decidir. Comparativas lado a lado: [SuiteCRM](/compare/suitecrm-alternative), [EspoCRM](/compare/espocrm-alternative) y [Twenty](/compare/twenty-alternative).

Para ver con detalle dos de ellos, consulta las comparativas de [alternativa a EspoCRM](/compare/espocrm-alternative) y [alternativa a Twenty](/compare/twenty-alternative), que enumeran licencia, stack, precios, canales y compatibilidad con MCP según las páginas oficiales de cada proyecto.

Su amplitud prevista es distinta. Algunos se centran en el CRM, otros forman parte de una suite de negocio más amplia y otros están pensados para flujos de organizaciones sin ánimo de lucro o de membresías. Por eso un «número uno» universal sirve menos que una lista corta puntuada según tus propios requisitos.

## Dónde encaja Customermates

Customermates es un CRM open core para relaciones con clientes y pipelines, hecho en Alemania. El material propio fuera de `ee/` es AGPL-3.0-only. Dentro de `ee/`, el material tiene licencia comercial, salvo el material de cliente que la sección 6 de `ee/LICENSE.md` identifica como AGPL-3.0-only.

El despliegue oficial del [CRM autoalojado](/features/self-hosted) contiene la aplicación y PostgreSQL 16. La edición autoalojada tiene las funciones de Starter.

| Capacidad de Customermates autoalojado | Estado |
| --- | --- |
| Contactos, organizaciones, oportunidades, servicios y tareas | Incluido |
| Campos personalizados, vistas de tabla y Kanban | Incluido |
| REST, webhooks y MCP | Incluido |
| Clientes de IA externos mediante MCP | Incluido; tú aportas el cliente y el proveedor |
| Bandeja de entrada unificada y cuentas de mensajería | No incluido |
| Asistente Mate solo en la nube y créditos alojados | No incluido |
| Vista de calendario conectado de solo lectura | No incluido |
| Importación de registros desde Excel o CSV, exportación como XLSX | Incluido, una lista cada vez |

Por eso Customermates encaja cuando quieres un CRM enfocado, un despliegue con Docker y PostgreSQL y una interfaz MCP abierta. No encaja cuando el autoalojamiento debe incluir la bandeja de entrada de la nube gestionada, o cuando necesitas una suite de PSA, facturación o control de tiempos.

Si el trabajo es dar seguimiento a las conversaciones con clientes, la nube gestionada añade lo que el autoalojamiento deja fuera: desde Pro, los hilos de LinkedIn y de correo viven en el registro del cliente, y Mate o tu propio agente de IA redacta la respuesta y el siguiente paso para que los revises y los envíes. El autoalojamiento conserva el CRM y MCP para tu propio cliente de IA.

Para probar Customermates por tu cuenta, [empieza tu prueba](/auth/signup?job=followup) en la nube gestionada ([[commercial.trial.days]] días de Pro, sin tarjeta de crédito) o autoalójalo con Docker; consulta la página del producto [CRM de código abierto: nube o autoalojado](/features/open-source-crm).

## Open source no es lo mismo que autoalojado

Los dos términos suelen buscarse juntos, pero responden a preguntas distintas. **Open source** habla de derechos: qué te permite inspeccionar, cambiar y redistribuir la licencia. **Autoalojado** habla de operación: en los servidores de quién funcionan la aplicación y la base de datos. Un proyecto puede ser open source y aun así usarse sobre todo como un servicio en la nube, y un producto autoalojado puede ser propietario. Esta guía trata las cuestiones de licencia y de lista corta; la página del [CRM autoalojado](/features/self-hosted) trata el propio despliegue de Customermates, y la [guía del CRM agéntico](/blog/agentic-crm) explica cómo trabajan con él los clientes de IA a través de MCP.

## Autoalojar cambia quién opera el sistema

El open source te da los permisos que define la licencia; autoalojar te da la responsabilidad de la infraestructura. Ninguno de los dos es una promesa automática de seguridad, cumplimiento normativo, portabilidad o bajo costo.

Tu equipo debe decidir quién se encargará de:

- las actualizaciones de la aplicación y de la base de datos;
- las copias de seguridad y la restauración probada;
- los controles de red, TLS y los secretos;
- la monitorización y la respuesta a incidentes;
- la planificación de capacidad y de disponibilidad; y
- cada proveedor conectado y su flujo de datos.

Si quieres detalles de despliegue específicos de Customermates, usa la [guía de autoalojamiento](/docs/self-hosting). No copies a producción un manual genérico de Docker sacado de un artículo comparativo.

## CRM en la nube o autoalojado

Elige la nube gestionada cuando quieras que el proveedor opere la aplicación y cuando las capacidades exclusivas de la nube sean esenciales. Elige el autoalojamiento cuando la licencia, el límite de funciones de Starter y la responsabilidad de operación encajen con tu equipo.

En Customermates la distinción es explícita: el CRM básico, REST, los webhooks y MCP se pueden autoalojar; la bandeja de entrada unificada, la vista de calendario conectado, la capacidad de Mate alojado y los créditos alojados, no.

## Preguntas frecuentes

<Faq>
<FaqItem question="¿Qué significa CRM open source?">
Significa que el código del CRM se ofrece con una licencia de código abierto que concede derechos definidos para usarlo, inspeccionarlo, modificarlo y redistribuirlo, sujetos a esa licencia. Revisa los archivos y la edición exactos: un repositorio también puede contener código con otra licencia.
</FaqItem>

<FaqItem question="¿Todo CRM open source es gratis de operar?">
  No. Puede que una licencia no cobre una suscripción por el software, pero la
  infraestructura, las copias de seguridad, las actualizaciones, la
  monitorización, el trabajo de seguridad y los proveedores externos siguen
  costando dinero y tiempo de quien opera el sistema.
</FaqItem>

<FaqItem question="¿El open source garantiza el control de los datos o el cumplimiento del RGPD?">
  No. Autoalojar puede darte control sobre dónde están la aplicación y la base
  de datos, pero el cumplimiento y los flujos de datos dependen de la
  configuración, los proveedores conectados, los contratos, las políticas y la
  operación.
</FaqItem>

<FaqItem question="¿Todo el código de Customermates es AGPL-3.0?">
  No. El material propio fuera de `ee/` es AGPL-3.0-only. Dentro de `ee/`, el
  material de cliente que identifica la sección 6 de `ee/LICENSE.md` también es
  AGPL-3.0-only; el resto del material propio usa la licencia comercial. Revisa
  los dos archivos de licencia para ver el límite exacto.
</FaqItem>

<FaqItem question="¿Puedo importar o exportar registros del CRM en Customermates autoalojado?">
Sí. Los registros entran como libros de Excel o archivos CSV y salen como libros XLSX, una lista cada vez, limitados al acceso de lectura del usuario y a la vista actual, con límites de filas en ambos sentidos. Para cualquier cosa más allá de eso, como archivos adjuntos o una transferencia completa de la cuenta, diseña una migración con la API REST.
</FaqItem>
</Faq>
