Customermates is an open-source CRM with a built-in MCP server. This page documents the **Company** screen of the web app for humans and for AI agents that drive the UI.

## What lives on the Company screen?

Workspace-wide administration: the subscription (Cloud only), the workspace currency, the team and its permissions, outbound webhooks with their delivery history, and the audit trail. Everything that affects the whole workspace, not a single record, lives here. All app routes are locale-prefixed (example: https://customermates.com/en/company/members), and each tab has its own route. The sidebar entry `#nav-company` opens `/company/subscription` on Cloud and `/company/settings` on a self-hosted install.

## Subscription tab

Route `/company/subscription`, sidebar id `#nav-company-subscription`, Cloud only. Shows the plan, the trial status and the plan picker. Plan prices and allowances are listed under [Plans and credits](/docs/app-assistant#plans-and-credits).

## Settings tab

Route `/company/settings`, sidebar id `#nav-company-settings`. Holds the workspace currency for all money values. Save or discard with `#company-settings-save` and `#company-settings-reset`.

## Members tab

Route `/company/members`, sidebar id `#nav-company-members`.

| Action | Where | Anchor id | What happens |
|---|---|---|---|
| Invite member | Members toolbar | `#company-members-add` | Opens the invite modal |
| Send invite | Invite modal footer | `#member-modal-save` / `#member-modal-reset` | Sends the invitation email |
| Search, filter, display options | Members toolbar | `#company-members-search` / `#company-members-filter` / `#company-members-display-options` | List controls |
| Layout | Display-options popover | `#company-members-layout-table` / `#company-members-layout-board` | Table is the only usable layout; the board control is present but disabled because members have nothing to group by |

People who register through an invitation link appear as **Waiting for Approval** until an admin assigns a role and activates them. Sending an invitation always asks the assistant's user for approval, because it emails a real person.

## Roles tab

Route `/company/roles`, sidebar id `#nav-company-roles`. Roles are permission sets: for every resource (the five record types, users, roles, audit log, API, routines and so on) they grant read, create, update and delete rights.

| Action | Where | Anchor id | What happens |
|---|---|---|---|
| Add role | Roles toolbar | `#company-roles-add` | Opens the role editor |
| Search, display options | Roles toolbar | `#company-roles-search` / `#company-roles-display-options` | Roles have no filterable fields, so no filter control renders |
| Layout | Display-options popover | `#company-roles-layout-table` / `#company-roles-layout-board` | Table only; the board control is disabled |

## Audit logs tab

Route `/company/audit-logs`, sidebar id `#nav-company-audit-logs`. Every record write with who, what, when and the changed fields; messaging events are not logged, and webhook secrets and header values are redacted. Reading it needs the audit-log permission on your role. There is no export; the [dashboard](/docs/app-dashboard) activity timeline shows the same changes as a feed.

| Action | Where | Anchor id | What happens |
|---|---|---|---|
| Search, filter, display options | Audit toolbar | `#company-audit-logs-search` / `#company-audit-logs-filter` / `#company-audit-logs-display-options` | List controls |
| Layout | Display-options popover | `#company-audit-logs-layout-table` / `#company-audit-logs-layout-board` | Table only; the board control is disabled |

## Tips for agents

- The hosted assistant can navigate to every tab and highlight every id above; it cannot click a row or submit a modal.
- Rows never carry ids. Navigate to a tab via its URL (for example `/company/webhooks`) and open a row by clicking it. Edits happen in modals, not in a drawer.
- Prefer [MCP](/docs/mcp) tools over clicking when a tool exists: `manage_team` invites and updates members, `manage_webhooks` manages subscriptions and deliveries, and `get_workspace_context` lists roles.
