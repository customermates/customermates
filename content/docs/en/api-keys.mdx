---
title: "API Keys for MCP and REST Clients"
description: "How to create an API key in your profile, send it in the x-api-key header, set an expiration, delete a key, and rotate it safely."
---

API keys authenticate Model Context Protocol (MCP) and REST clients against your Customermates CRM. Create one key per client, store it in an environment variable, and delete it when the device or the teammate that held it goes away.

## How do I create an API key?

Open **My Profile**, then the **API & Connectors** tab (`/profile/api-keys`), and press **Add**. The dialog offers two routes:

- **Standard API key**: give it a name that says where it is used, for example `Claude Desktop, personal laptop`, and optionally an expiration date. The key is shown once; copy it before you close the dialog.
- **Quick connections**: pick Claude, ChatGPT and Codex, Cursor, or Gemini and the dialog creates the key and shows that client's setup snippet.

Keys belong to the user who created them and inherit that user's permissions.

## How do I use a key?

Send it in the `x-api-key` header on every request:

```bash
curl -H "x-api-key: $CUSTOMERMATES_API_KEY" \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     https://customermates.com/api/v1/mcp \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

The `Accept: application/json, text/event-stream` header is required by the MCP streamable HTTP transport; without it the endpoint returns `406 Not Acceptable`. For MCP clients the key goes into the client's configuration, see [CLI and editor clients](/docs/connect-cli) and [ChatGPT with an API key](/docs/connect-custom-connector#chatgpt).

## Do keys expire?

Only if you set an expiration date. A key without one never expires. When you set one, it must lie between 1 and 365 days ahead. The key card shows the creation date, the expiration date ("Never" when unset) and when the key was last used.

## How do I revoke, delete or rotate a key?

Open the key from its card and choose **Delete**; a confirmation follows and the key stops working immediately. There is no separate rotate or revoke action: to rotate, create a new key, update every client that used the old one, then delete the old key.

Rotate when a device that held the key is lost or compromised, when a teammate with access leaves, or when you suspect the key leaked. One key per client keeps audit entries readable and lets you delete a single client without breaking the others. Keep keys in an environment variable or a password manager, never in a config file you commit.

## What is the key format?

Keys are 64 characters of ASCII letters (`a-z A-Z`), generated by the better-auth API key plugin and stored hashed. The full key is shown only at creation and cannot be displayed again.

## What permissions does a key have?

Everything its owner can do, and nothing more. If a user is demoted from Admin to Member, their keys lose admin capabilities on the next call. There is no per-key permission scoping.
