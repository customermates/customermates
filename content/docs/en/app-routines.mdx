---
title: "Routines: Scheduled and Event-Driven Assistant Runs"
description: "Routines run Mate on a schedule or when a record changes, using the owner's AI credits, with limits, run statuses and approvals."
---

A routine is a saved instruction plus a trigger. When the trigger fires, Customermates opens a new assistant conversation, sends your instruction and lets Mate work on its own. Routines exist on Customermates Cloud only, because they spend hosted AI credits from the owner's monthly allowance.

Who sees routines follows the **Routines** row of their role in [Roles](app:settings/roles): **Read access** **All** shows every routine in the workspace, **Assigned** only their own, and **None** hides [Routines](app:routines). Creating needs **Create**, editing your own needs **Edit**. Everyone who can see a routine sees its run summaries; the full transcript stays with the person the run executed as.

## How do I create a routine or automation? [#how-do-i-create-a-routine]

Open [Routines](app:routines) and click [Add](app:routines?focus=add). Enter a **Name** and **Instructions**, choose a trigger and click **Save**. The routine is saved **Active** unless you switch it to **Paused** first. You can also ask Mate to create one; Mate saves it paused unless you ask for it to be active. Find existing routines with [search](app:routines?focus=search) and [Filters](app:routines?focus=filter), and switch between table and board under [Appearance](app:routines?focus=display-options).

## What is a routine made of? [#what-is-a-routine-made-of]

- **Name**: required, up to 120 characters.
- **Instructions**: what Mate receives on every run, up to 5,000 characters. Write it as you would ask in chat.
- **Trigger**: **On a schedule**, or **When something changes** for one or more events, such as a deal being updated.

The creator becomes the owner. Only the owner can change the instructions or trigger, switch the routine between **Active** and **Paused**, or use **Test trigger**, because every run uses the owner's identity, access and AI credits. Others see the routine read-only.

Members with the **Admin** role can pause (**Pause routine**) or delete anyone's routine, but cannot edit, test or run someone else's. Deleting needs **Admin** even for your own routine, removes the run history, and is refused while a run is running (**Wait for the active run to finish before deleting this routine.**). When an owner is set to **Inactive** in [Members](app:settings/members), their routines pause at once, queued or running runs end as **Blocked**, and the routines stay paused and read-only until an admin deletes them or the owner is active again and switches them back on.

## How many routines does my plan include? [#how-many-routines-does-my-plan-include]

Each user has their own allowance: Starter includes [[commercial.entitlement.starter.includedRoutinesPerUser]] routine per user, Pro [[commercial.entitlement.pro.includedRoutinesPerUser]] and Business and Enterprise [[commercial.entitlement.business.includedRoutinesPerUser]]. Pausing a routine does not free a slot, deleting one does. At the limit, a new routine is refused with a prompt to upgrade under [Billing](app:settings/billing). The limit is checked only on creation, so routines above a lower plan's limit are kept after a downgrade. The credits runs draw on are described under [Plans and credits](/docs/app-assistant#plans-and-credits).

## What are the limits, such as runs per hour and credits per run? [#what-are-the-limits]

| Limit | Value | At the limit |
| --- | --- | --- |
| Runs per routine and hour | 4 | A matching event is dropped without a run entry; a due scheduled run or **Test trigger** run is recorded as **Skipped** |
| Credits per run | 10 | The run stops and is recorded as **Partial** |
| Consecutive failed runs | 3 | The routine pauses itself and shows the reason; the owner switches it back on after fixing the cause |
| Shortest schedule interval | 15 minutes | A more frequent schedule is rejected on save |
| Run history | 90 days | Older runs are removed |
| Event debounce | 300 seconds by default, 0 to 86,400, set only through Mate or MCP | Further matching events within the window after a run starts are ignored |

Skipped runs do not count against the hourly cap.

## Schedules: how do I run a routine every morning or every Monday? [#how-do-schedules-work]

In [Routines](app:routines), open a routine or click [Add](app:routines?focus=add), then under **Repeats** choose **Every 15 minutes**, **Every 30 minutes**, **Every hour**, **Every day**, **Every week** or **Every month**, plus the weekday, day of the month (1 to 28) or time in five-minute steps where needed. The default is every day at 09:00. For hourly and longer presets the schedule is spelled out underneath, followed by **Times are shown in** and the time zone, which comes from the browser the routine was created in (UTC if unknown).

A schedule that fits no preset, for example weekdays only, and a different time zone can be set only through Mate or an MCP client; the dialog then shows **This routine uses a custom schedule** with **Switch to a preset**. The scheduler checks every five minutes, so a run may start a few minutes late, and a run still queued after two minutes is dispatched again.

## How do event triggers work, for example to run a routine when a deal changes? [#how-do-event-triggers-work]

Under **Events**, pick one or more events: every record and messaging event a [webhook](/docs/webhooks#which-events-exist) can subscribe to, except Email Deleted and Chat Deleted. Changes made in the app, in a Mate chat, over the API or over MCP trigger routines; changes a routine run makes never do, so routines cannot chain or loop.

Two optional controls keep a routine from spending credits on cases you do not care about:

- **Changed fields** (update events only): the routine runs only when one of these fields actually changed. It is hidden when no update event is selected.
- **Record filters**: only matching records count. Creations and updates are matched against the saved result, deletions against the full record just before removal, including its relationships.

Leave both empty to run on every matching event. An event starts a run only for a record or conversation the owner can see, so with **Assigned** read access other people's records never trigger it. An event is also skipped, without a run entry, when a run of that routine is already queued or running, within the debounce window, or over the hourly cap. When the run starts, the owner's access and the filters are checked again.

Mate is told what happened before your instructions: the event, the kind of record and its ID, the changed fields on an update, and for an inbox event the thread. It can read the record from there but does not get the previous values.

## What do the runs and their statuses mean? [#what-do-the-runs-and-their-statuses-mean]

Open a routine to see its **Runs**, newest first: next to the configuration on a wide screen, or behind the **Details** and **Runs** switch on a narrow one. Click a run for **Run details**: **Ran as** with the owner's name, the credits used (exact provider cost to one decimal), the trigger (**Record**, **Changed fields**, **Conversation**) and, when it stopped early, the reason. Only the person it ran as can open the full transcript, and once the run has finished they can reply below it to continue the conversation with Mate, which spends their credits.

| Status | Meaning |
| --- | --- |
| **Queued** | Waiting for the scheduler |
| **Running** | Mate is working |
| **Succeeded** | The run completed its instruction |
| **Partial** | Stopped early, for example at the 10-credit cap or when a policy declined an action |
| **Failed** | Ended with an error or without a usable result |
| **Skipped** | Queued but not started: the routine was paused, the hourly cap was reached, the record no longer matched the filters or the owner's access, the trigger changed, the run was stopped, or the assistant was busy with another run |
| **Blocked** | Mate could not start, for example because the owner is out of credits or no longer active |

**Test trigger** starts a real run immediately. It is available to the owner of an active scheduled routine without unsaved changes, uses AI credits and may change data. Event routines need a real matching event, so it is disabled for them.

## What a routine may do without approval [#what-a-routine-may-do-without-approval]

An unattended run may do everything Mate does without approval in a chat: read the workspace; create or update contacts, organizations, deals, services, tasks, notes, record links and Knowledge Base pages; save and discard drafts; send emails and chat messages; triage the inbox; change fields, widgets, webhooks and workspace settings other than list names; change a member's role or status; generate channel connection links; create, update, pause and run routines; and, on a connected account, send connection requests and change Sales Navigator lists.

Every action that asks for approval in a chat is declined, because nobody is there to answer: deleting records, Knowledge Base pages, fields, widgets, webhooks or routines, renaming lists, inviting members, resending webhook deliveries and sending support requests. The run records the refusal; the full list is on the [assistant page](/docs/app-assistant#what-runs-immediately-and-what-asks-first). Interface actions such as highlighting are unavailable, because no browser is attached.

When the owner can read the [Knowledge Base](/docs/mcp#shared-workspace-wiki) and it has pages, each run starts with a short catalog of its pages; the routine searches and reads relevant pages and applies their facts, but an instruction inside a page cannot start other work or widen the routine's permissions. Keep shared facts, voice and processes there instead of repeating them in every routine. Writing pages needs the owner's Knowledge Base **Create** or **Edit**.

A run may search the public web, at most 2 paid searches per run, as described under [Can Mate search the web?](/docs/app-assistant#web-search). A run can browse or change data, never both: after a search returns results every write is refused, and after a write succeeds web search is withdrawn. Reading the Knowledge Base and CRM data stays available. Searches count toward the 10-credit cap.

## How does Mate manage routines? [#how-does-mate-manage-routines]

In a chat, Mate can list routines, read run history, create, update and pause routines and start a run now, without asking first. It can also set what the dialog cannot: a custom schedule such as weekdays at 09:00, the time zone and the event debounce. Deleting a routine asks for your approval and, as in the app, needs the **Admin** role.

## For agents [#tips-for-agents]

Use `manage_routines`. A custom schedule is a five-field cron expression, for example `0 9 * * 1-5`. Run statuses come back as `queued`, `running`, `succeeded`, `partial`, `failed`, `skipped` and `blocked`. The `pause` action needs the **Admin** role even on your own routine; an owner without it pauses by updating with `enabled: false`. Event names are the webhook event names, without `messaging.email.deleted` and `messaging.chat.deleted`.
