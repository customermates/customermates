Customermates is an open-source, AI-native CRM. This page documents the **My Profile** screen of the web app for humans and for AI agents that drive the UI.

## What lives on the Profile screen?

Everything scoped to you as a user rather than to the company: your settings (name, country, avatar, theme, language), the API keys for MCP and REST clients, and the messaging accounts that feed the Inbox. Changes here affect only your own account. URLs are locale-prefixed, for example `https://customermates.com/en/profile/settings`; each tab has its own route; the sidebar entry **My Profile** (`#nav-profile`) expands the profile group, and its sub-entry `#nav-profile-settings` opens `/profile/settings`.

## Settings tab

Route `/profile/settings`, sidebar id `#nav-profile-settings`. One form covers identity (name, country, avatar) and preferences (theme, language). Save or discard with `#profile-settings-save` and `#profile-settings-reset`; both buttons appear only once the form has unsaved changes. Over MCP, `update_workspace_settings` with `target: "profile"` changes first name, last name, country and avatar URL only; theme and language are set in the UI.

## API keys tab (API & Connectors)

Route `/profile/api-keys`, sidebar id `#nav-profile-api-keys`. Keys for MCP and REST clients; the rules are on [API keys](/docs/api-keys).

| Action | Where | Anchor id | What happens |
|---|---|---|---|
| Add a key | Page header | `#profile-api-keys-generate` | Opens the add dialog with two routes |
| Create a standard key | Standard route | `#api-key-save` | Name plus optional expiration date; the key is shown once, so copy it immediately |
| Quick connections | Quick route | none | Four tiles: Claude, ChatGPT and Codex, Cursor, Gemini; the local setups (Claude Code or Claude Desktop, Codex, Cursor, Gemini) create the key and show that client's setup snippet, while the Claude account and ChatGPT app methods connect through the hosted connector without a key |
| Open a key | Key card | none | Shows the creation date; the expiration and last-used rows appear only when set |
| Delete a key | Key dialog | none | Button labeled Delete, with a confirmation |

There is no rotate or revoke button: create a new key, update the client, then delete the old one.

## Connected accounts tab

Route `/profile/connected-accounts`, sidebar id `#nav-profile-connected-accounts`, Cloud only. **Connect channel** (`#profile-connected-accounts-connect`) opens a channel picker (email, LinkedIn, WhatsApp, Instagram, Telegram); choosing a channel navigates the current tab to the hosted-auth page, and the connected account then feeds the [Inbox](/docs/app-inbox). Connecting WhatsApp means scanning the QR code on that page.

| Action | Where | Anchor id | What happens |
|---|---|---|---|
| Connect an account | Card header | `#profile-connected-accounts-connect` | Opens the channel picker; picking a channel navigates to the hosted-auth page |
| Connect from an empty profile | Centered empty state | `#profile-connected-accounts-connect-empty` | The same picker, rendered when no account exists and you may connect; when the assistant is enabled the empty state shows assistant starter prompts instead of this button |
| Manage an account | Account row click | none | Opens the account modal on its Details tab |
| Details tab | Account modal | `#connected-account-tab-details` | Provider, status, visibility, owner, folder count and sync times |
| Email tab | Account modal | `#connected-account-tab-email` | Email appearance and signature; only for an email account you own |
| Folders tab | Account modal | `#connected-account-tab-folders` | Choose which provider folders sync; only when the account exposes folders |

Connecting navigates the current tab to the hosted-auth page: expect a full-page navigation, not a popup, and a return to the app when the provider finishes. How many accounts a user may connect depends on the plan: Starter [[commercial.entitlement.starter.includedAccountsPerUser]], Pro [[commercial.entitlement.pro.includedAccountsPerUser]], Business [[commercial.entitlement.business.includedAccountsPerUser]], Enterprise [[commercial.entitlement.enterprise.includedAccountsPerUser]] per user.

### Email appearance and signature

The **Email** tab sets how every message sent from that account looks. Appearance covers the font family, base font size, link colour and link style, and applies to the whole email. The link colour takes a six-digit hex value with a colour picker beside it, validates as you type, and warns about low contrast without blocking you.

The signature below it is a single Markdown block with an on/off toggle, so switching it off keeps the saved text for later. Pick a layout of text only, logo above or logo beside, give a public HTTPS logo URL, and adjust logo size, divider and spacing under **Layout options**. A live preview shows the result. Saved appearance and signature apply to every email sent from that account, whether it is sent from the Inbox, the REST API or an MCP tool, so agents must not repeat the signature in the message body.

## Tips for agents

- The hosted assistant can navigate to the three tabs and highlight `#nav-profile-connected-accounts` and `#profile-connected-accounts-connect`; it cannot press them. Ask it for a tour of connecting an account and it walks you there.
- Rows never carry ids. Open a key or an account by clicking its card or row; the tabs are plain routes.
- Prefer MCP tools when a tool exists: `connect_messaging_account` creates the authentication link for a new channel, and `get_workspace_context` lists the connected accounts. Creating an API key has no tool; use the dialog above.
- A generated API key is shown exactly once, whether created as a standard key or through a quick connection's local setup. Copy it in the same step.
