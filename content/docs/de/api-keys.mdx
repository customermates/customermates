API-Keys authentifizieren Clients für das Model Context Protocol (MCP) und die REST-API gegen Ihr Customermates-CRM. Legen Sie einen Key pro Client an, speichern Sie ihn in einer Umgebungsvariable und löschen Sie ihn, wenn das Gerät oder das Teammitglied, das ihn hatte, wegfällt.

## Wie lege ich einen API-Key an?

Öffnen Sie **Mein Profil**, dann den Tab **API & Konnektoren** (`/profile/api-keys`), und klicken Sie auf **Hinzufügen**. Der Dialog bietet zwei Wege:

- **Standard-API-Key**: Geben Sie einen Namen, der den Einsatzort benennt, zum Beispiel `Claude Desktop, privater Laptop`, und optional ein Ablaufdatum. Der Key wird einmal angezeigt; kopieren Sie ihn, bevor Sie den Dialog schließen.
- **Schnellverbindungen**: Wählen Sie Claude, ChatGPT und Codex, Cursor oder Gemini; der Dialog legt den Key an und zeigt das Setup-Snippet dieses Clients.

Keys gehören dem User, der sie angelegt hat, und erben dessen Berechtigungen.

## Wie kann ich einen Key nutzen?

Senden Sie ihn bei jeder Anfrage im Header `x-api-key`:

```bash
curl -H "x-api-key: $CUSTOMERMATES_API_KEY" \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     https://customermates.com/api/v1/mcp \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Der Header `Accept: application/json, text/event-stream` wird vom MCP-Streamable-HTTP-Transport verlangt; ohne ihn liefert der Endpoint `406 Not Acceptable`. Bei MCP-Clients gehört der Key in die Konfiguration des Clients, siehe [CLI- und Editor-Clients](/docs/connect-cli) und [ChatGPT mit einem API-Key](/docs/connect-custom-connector#chatgpt).

## Laufen Keys ab?

Nur, wenn Sie ein Ablaufdatum setzen. Ein Key ohne Ablaufdatum läuft nie ab. Wenn Sie eines setzen, muss es zwischen 1 und 365 Tagen in der Zukunft liegen. Die Key-Karte zeigt das Erstellungsdatum, das Ablaufdatum ("Nie", wenn keins gesetzt ist) und wann der Key zuletzt verwendet wurde.

## Wie kann ich einen Key widerrufen, löschen oder rotieren?

Öffnen Sie den Key über seine Karte und wählen Sie **Löschen**; eine Bestätigung folgt, und der Key funktioniert sofort nicht mehr. Eine separate Rotate- oder Revoke-Aktion gibt es nicht: Zum Rotieren legen Sie einen neuen Key an, aktualisieren jeden Client, der den alten genutzt hat, und löschen dann den alten Key.

Rotieren Sie, wenn ein Gerät mit dem Key verloren geht oder kompromittiert ist, wenn ein Teammitglied mit Zugriff das Team verlässt oder wenn Sie einen Leak vermuten. Ein Key pro Client hält Audit-Einträge lesbar und erlaubt es, einen einzelnen Client zu löschen, ohne die anderen zu brechen. Bewahren Sie Keys in einer Umgebungsvariable oder einem Passwort-Manager auf, nie in einer Config-Datei, die Sie committen.

## Welches Format hat ein Key?

Keys bestehen aus 64 ASCII-Buchstaben (`a-z A-Z`), erzeugt vom better-auth-API-Key-Plugin und gehasht gespeichert. Der vollständige Key wird nur bei der Erstellung angezeigt und lässt sich danach nicht mehr abrufen.

## Welche Berechtigungen hat ein Key?

Alles, was sein Owner darf, und nicht mehr. Wird ein User von Admin auf Member herabgestuft, verlieren seine Keys die Admin-Fähigkeiten beim nächsten Aufruf. Ein Berechtigungs-Scoping pro Key gibt es nicht.
