Customermates-Filter (genutzt von den Model-Context-Protocol-Tools (MCP), der REST-API und der App-UI) sind Arrays aus Feld-Operator-Wert-Regeln. Siebzehn Operatoren decken Gleichheit, Textabgleich, Vergleich, Mengenzugehörigkeit, Bereich, Aktualität, Null-Prüfungen und Relationship-Zugehörigkeit ab.

## Wo greifen Filter?

- Das MCP-Tool `list_records` und die Messaging-Filter auf `get_messaging_threads` und `get_activities`.
- `entityFilters` und `dealFilters` auf Widgets.
- `timelineFilters` auf Aktivitäts-Widgets. Aktivitätsfilter erlauben höchstens eine Regel pro Feld; ODER-Alternativen gehören in das Werte-Array einer einzigen `in`-Regel.
- Gespeicherte Ansichten in der UI (intern in dieselbe Form umgewandelt).

## Wie sieht eine Filterregel aus?

```json
[
  { "field": "firstName", "operator": "startsWith", "value": "An" },
  { "field": "createdAt", "operator": "gte",        "value": "2024-01-01" }
]
```

Regeln sind UND-verknüpft. Für ODER-Logik lassen Sie zwei Abfragen laufen und mergen client-seitig, oder Sie nutzen den `in`-Operator, wenn Sie gegen eine Liste vergleichen.

## Welche Operatoren gibt es?

| Operator | Erwartet | Wirkt auf | Beispielwert |
|---|---|---|---|
| `equals` | einen Wert | Textfelder (`name`, `firstName`, `lastName`, `url`) sowie Custom Columns der Typen Währung, E-Mail, Telefon, Text und Link; exakt und mit Beachtung der Groß- und Kleinschreibung | `"Acme"` |
| `contains` | einen Wert | Textfelder (`name`, `firstName`, `lastName`, `url`), Custom Columns der Typen E-Mail, Telefon, Text und Link sowie Datumsbereich-Custom-Columns; ohne Beachtung der Groß- und Kleinschreibung | `"acme"` |
| `startsWith` | einen Wert | `name`, `firstName`, `lastName`; ohne Beachtung der Groß- und Kleinschreibung | `"An"` |
| `gt` | einen Wert | Zahlen, Daten | `"2024-01-01"` |
| `gte` | einen Wert | Zahlen, Daten | `100` |
| `lt` | einen Wert | Zahlen, Daten | `"2024-12-31"` |
| `lte` | einen Wert | Zahlen, Daten | `"2024-12-31"` |
| `in` | Array | Relationship-Arrays, ID-, Enum- und Auswahlfelder sowie singleSelect-Custom-Columns | `["id1", "id2"]` |
| `notIn` | Array | Relationship-Arrays, ID-, Enum- und Auswahlfelder sowie singleSelect-Custom-Columns | `["id1"]` |
| `between` | Array aus 2 | Zahlen, Daten | `["2024-01-01", "2024-12-31"]` |
| `inLastDays` | einen Wert (positive Ganzzahl) | Daten | `30` |
| `isNull` | keinen Wert | nur Custom Columns | (keiner) |
| `isNotNull` | keinen Wert | nur Custom Columns | (keiner) |
| `hasNone` | keinen Wert | Relationship-Arrays, Draft-Status von Messaging-Threads | (keiner) |
| `hasSome` | keinen Wert | Relationship-Arrays, Draft-Status von Messaging-Threads | (keiner) |
| `hasUnset` | keinen Wert | Teilnehmer von Messaging-Threads | (keiner) |
| `allSet` | keinen Wert | Teilnehmer von Messaging-Threads | (keiner) |

### Welche Datums-Operatoren gibt es?

Datumsfelder wie `createdAt` und `updatedAt` akzeptieren `gt`, `gte`, `lt`, `lte`, `between` und `inLastDays`. Nutzen Sie `inLastDays` mit einer positiven ganzzahligen Anzahl von Tagen für ein rollierendes Aktualitätsfenster, zum Beispiel `{ "field": "createdAt", "operator": "inLastDays", "value": 7 }` für Datensätze, die in der letzten Woche erstellt wurden.

### Welche Operatoren wirken auf Textfelder?

Textfelder wie `firstName` und `lastName` eines Kontakts oder `name` einer Organisation akzeptieren `equals`, `startsWith` und `contains`. `contains` und `startsWith` vergleichen ohne Beachtung der Groß- und Kleinschreibung; `equals` ist ein exakter Abgleich mit Beachtung der Groß- und Kleinschreibung.

### Welche Relationship-Operatoren gibt es?

Relationship-Arrays (`organizationIds`, `dealIds`, `userIds`, `contactIds`, `serviceIds`, `taskIds`) akzeptieren `in`, `notIn`, `hasNone` und `hasSome`. Das Feld für den Verknüpfungsstatus der Teilnehmer auf `get_messaging_threads` nutzt `hasUnset` und `allSet`, um Threads danach zu filtern, ob ihre Teilnehmer mit Datensätzen verknüpft sind. Das Feld `draft` desselben Tools akzeptiert die wertlosen Operatoren `hasSome` (der Thread enthält einen ungesendeten Entwurf) und `hasNone` (er enthält keinen), womit Sie Entwürfe auflisten oder ausschließen.

## Welche Feldnamen kann ich nutzen?

Der Wert von `field` ist, was `get_record_schema` unter `filterableFields` für diese Entity zurückgibt, samt der Operatoren, die jedes Feld erlaubt. Dazu gehören:

- Standard-Skalarfelder (zum Beispiel `createdAt`, `updatedAt` und bei Kontakten `firstName` und `lastName`).
- Relationship-Arrays (`organizationIds`, `dealIds`, `userIds`, `contactIds`). Kombinieren Sie sie mit `in`, `notIn`, `hasNone`, `hasSome`. Manche Relationsfelder brauchen Leseberechtigung auf den verknüpften Datensatztyp.
- Custom-Column-IDs. Nutzen Sie die UUID der Spalte als Feld; eine singleSelect-Spalte akzeptiert nur `in`, `notIn`, `isNull` und `isNotNull` und filtert auf ihre Optionswerte.

Rufen Sie immer zuerst `get_record_schema` auf, wenn Sie unsicher sind, was filterbar ist. Die Fehlermeldung bei einem unbekannten Feld listet jedes verfügbare Feld mit seinen erlaubten Operatoren.

## Beispiele

Kontakte in einer von drei Organisationen:

```json
{ "field": "organizationIds", "operator": "in", "value": ["org_1","org_2","org_3"] }
```

Deals aus 2024, deren Custom-singleSelect-Spalte (identifiziert über ihre UUID) auf einen gewählten Optionswert gesetzt ist:

```json
[
  { "field": "createdAt", "operator": "between", "value": ["2024-01-01","2024-12-31"] },
  { "field": "col_uuid",  "operator": "in",      "value": ["option_value"] }
]
```

Kontakte ohne verknüpfte Organisation:

```json
{ "field": "organizationIds", "operator": "hasNone" }
```

Datensätze der letzten 30 Tage:

```json
{ "field": "createdAt", "operator": "inLastDays", "value": 30 }
```

## Freitextsuche oder Filter?

`list_records` akzeptiert auch `searchTerm`, eine Freitextsuche über die Namensfelder der Entity plus verwandte Felder: bei Kontakten `firstName`, `lastName`, Werte der Kanal-Identifikatoren und Namen verknüpfter Organisationen; bei Organisationen `name` plus Vor- und Nachnamen verknüpfter Kontakte; bei Deals, Services und Aufgaben `name`. Nutzen Sie `searchTerm` für "Kontakte, deren Name acme enthält", wenn es Ihnen egal ist, welches Namensfeld getroffen hat; nutzen Sie eine Filterregel auf `firstName` oder `lastName` mit `contains`, `startsWith` oder `equals`, wenn das Feld eine Rolle spielt oder wenn Sie sie mit anderen Regeln kombinieren.
