Verbinden Sie n8n mit Customermates, indem Sie einen Webhook-Node auf CRM-Events abonnieren und die REST-API aus HTTP-Request-Nodes aufrufen. Dafür ist kein Custom-Node nötig; die REST- und MCP-Oberflächen funktionieren direkt. Es gibt zusätzlich einen Customermates-Community-Node unter [github.com/customermates/n8n-nodes-crm](https://github.com/customermates/n8n-nodes-crm), falls Sie dedizierte CRM-Nodes den generischen HTTP-Request-Nodes vorziehen.

## Wann n8n passt

- Ihr Team bevorzugt visuelle Flows gegenüber Code.
- Sie wollen Events verzweigen und transformieren, bevor Sie sie an ein anderes System weiterleiten, etwa Slack, HubSpot, Google Sheets oder ein Data Warehouse.
- Sie betreiben n8n ohnehin für andere Automationen.

Wenn eine KI das CRM im Gespräch steuern soll, nutzen Sie [MCP](/docs/mcp) stattdessen oder parallel.

## Pattern 1: n8n aus CRM-Änderungen triggern

1. Fügen Sie in n8n einen **Webhook**-Node hinzu und kopieren Sie die generierte URL.
2. Gehen Sie in Customermates zu **Unternehmen → Webhooks → Neu**, fügen Sie die URL ein und wählen Sie die gewünschten Events.
3. Ergänzen Sie nach dem Webhook-Node Schritte zum Transformieren und Weiterleiten des Payloads.

Die Payload-Struktur ist unter [Webhooks](/docs/webhooks) dokumentiert. Typische nächste Schritte:

- **Slack**: eine Nachricht in einen Channel posten, wenn ein Deal erstellt wird.
- **Google Sheets**: bei jedem neuen Contact eine Zeile anhängen.
- **HubSpot**: den Contact spiegeln.

## Pattern 2: aus n8n nach Customermates pushen

Nutzen Sie den **HTTP-Request**-Node:

- Method: `POST` für Creates, `PATCH` für Updates.
- URL: `https://customermates.com/api/v1/<endpoint>`, wobei `<endpoint>` gleich `contacts`, `organizations`, `deals`, `services` oder `tasks` ist.
- Headers: `x-api-key` auf Ihren API-Key gesetzt, als n8n-Credential gespeichert.
- Body: JSON gemäß [OpenAPI-Spec](/docs/openapi).

Um MCP-Tool-Calls aus n8n abzusetzen, senden Sie eine Anfrage an `/api/v1/mcp` mit `method: "tools/call"`. Damit laufen Writes durch dieselben Guardrails, die die MCP-Ebene ergänzt, etwa das Ablehnen von `null` auf einem Relationship-Array.

## Pattern 3: geplante Jobs

Der Cron-Trigger von n8n plus die Customermates-REST-API deckt wiederkehrende Aufgaben ab:

- Täglich: Contacts ohne Organization finden und einen Reminder posten.
- Wöchentlich: Records, die auf einen Filter passen, in ein Google Sheet exportieren.
- Monatlich: Records archivieren, deren Custom-Status-Spalte einen bestimmten Wert hält.

Lifecycle-Werte von Deals und Tasks wie Status oder Priorität sind pro Workspace konfigurierbare singleSelect-Custom-Columns, keine festen Felder. Rufen Sie `get_record_schema` auf oder lesen Sie die OpenAPI-Spec, um zu sehen, welche Spalten und Optionen in Ihrem Workspace existieren, bevor Sie danach filtern.

## Authentifizierung

Speichern Sie den API-Key als n8n-**Header-Auth**-Credential mit dem Header-Namen `x-api-key`. Verwenden Sie ihn über Nodes hinweg wieder, damit Sie ihn an einer Stelle rotieren. Keys sind 64 Zeichen lange Base62-Strings und erben die Berechtigungen des besitzenden Users; ein Scoping pro Key gibt es nicht.

## Typische Fallstricke

- **Relationship-Arrays**: `null` auf einem Relationship-Array wird abgelehnt. Senden Sie `[]` zum Leeren oder nutzen Sie das Tool `manage_record_links`, um Links hinzuzufügen oder zu entfernen.
- **Rate-Limits**: High-Frequency-Loops können in API-Limits laufen. Wenn möglich batchen.
- **Webhook-Ordering**: Deliveries sind nicht strikt geordnet. Behandeln Sie sie als idempotente Messages mit Schlüssel `entityId`.
