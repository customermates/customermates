Customermates est un CRM source-available et IA native que votre IA pilote directement via MCP. Le connecteur personnalisé est la façon la plus simple de se connecter : collez une URL, connectez-vous à Customermates et approuvez l’accès. Aucune clé API à copier, aucun fichier de configuration à modifier, aucun shim à installer. Vous autorisez une fois, et la connexion persiste.

C’est la voie recommandée pour **Claude** (web, bureau et mobile) et **ChatGPT**. Sur une ligne de commande ou un éditeur (Claude Code, Codex, Cursor, Gemini CLI), utilisez plutôt [la méthode par clé API](/docs/connect-cli).

> Claude propose les connecteurs personnalisés dans toutes ses formules (Free, Pro, Max, Ultra, Team, Enterprise) ; la formule Free en autorise un (aide Anthropic, vérifiée le 3 novembre 2026). Dans ChatGPT, les règles du compte et de l’espace de travail décident si vous pouvez ajouter un serveur MCP personnalisé (aide OpenAI, vérifiée le 24 novembre 2026).

## Quelle URL dois-je coller ? [#the-url]

Il y a une seule URL pour tout votre compte :

```
<BASE_URL>/api/v1/mcp
```

`<BASE_URL>` est l’adresse à laquelle vous ouvrez Customermates, dans le cloud ou sur votre propre instance. Vous n’avez pas à l’assembler : Customermates l’affiche avec un bouton de copie sous [Clés API et connecteurs](app:settings/api-keys) quand vous cliquez sur [Ajouter](app:settings/api-keys?focus=generate) et choisissez **Claude** puis **Compte Claude** (ou **ChatGPT & Codex** puis **Application ChatGPT**), et dans l’étape d’accueil **Connectez l’IA que vous utilisez déjà**.

Un seul connecteur couvre tous les espaces de travail auxquels vous appartenez. Vous l’approuvez une fois pour votre compte, et votre IA nomme l’espace de travail à chaque appel, ou vous demande lequel vous voulez dire quand vous en avez plusieurs. Un espace de travail que vous rejoignez ou créez plus tard fonctionne sans reconnexion. Les connecteurs que vous avez ajoutés plus tôt avec l’adresse propre d’un espace de travail continuent de fonctionner et restent fixés à cet espace de travail.

Le connecteur fonctionne sur toutes les formules Customermates et sur les instances auto-hébergées ; seuls les outils de messagerie, de calendrier et de réseaux sociaux demandent une formule avec messagerie, Pro ou supérieure dans le cloud.

## Comment connecter Claude au CRM Customermates ? [#claude]

Pour connecter Claude à votre CRM, ajoutez Customermates comme connecteur personnalisé dans Claude :

<Steps>
<Step title="Ouvrir le formulaire du connecteur">
**Claude → Customize → Connectors → Add → Add custom connector.** Sur Team et Enterprise, un propriétaire l’ajoute d’abord sous **Organization settings → Connectors → Add → Custom → Web**.
</Step>
<Step title="Coller l’URL">
Laissez l’authentification sur la valeur par défaut (OAuth). Pas d’en-tête, pas de clé.
</Step>
<Step title="Se connecter et approuver">
Une fenêtre Customermates s’ouvre. Connectez-vous, puis cliquez sur **Approuver** sur l’écran de consentement.
</Step>
<Step title="Vérifier que les outils sont arrivés">
De retour dans Claude, Customermates apparaît avec la liste de ses outils.
</Step>
</Steps>

Ajoutez-le une fois et il se synchronise avec Claude sur le web, le bureau et le mobile. La connexion est liée à votre compte Claude, pas à un appareil, et se renouvelle en arrière-plan.

En un clic : dans Customermates, ouvrez [Clés API et connecteurs](app:settings/api-keys), cliquez sur [Ajouter](app:settings/api-keys?focus=generate), choisissez **Claude** sous **Connexions rapides**, puis **Compte Claude**, et cliquez sur **Ajouter à Claude**. Cela ouvre la boîte de dialogue d’ajout de connecteur de Claude, préremplie avec l’URL et le nom de connecteur **Customermates** (Claude web et Teams uniquement). L’étape d’accueil **Connectez l’IA que vous utilisez déjà** propose le même bouton. **Ajouter** demande **Créer** sur **API et webhooks** ; sans ce droit, collez l’URL comme ci-dessus.

## Comment connecter ChatGPT ? [#chatgpt]

Sur chatgpt.com, ouvrez **[Plugins](https://chatgpt.com/plugins) → + → Add custom MCP server** :

- **Nom :** Customermates
- **Connexion :** le point de terminaison public `<BASE_URL>/api/v1/mcp` ([quelle URL](#the-url))
- **Authentification :** OAuth

Confirmez l’avertissement de risque avec **I understand and want to continue**, puis **Create as a plugin**. ChatGPT ouvre une fenêtre Customermates. Connectez-vous, puis cliquez sur **Approuver** sur l’écran de consentement. Chaque outil Customermates est listé, sans clé à stocker ni à renouveler.

Dans l’application de bureau ChatGPT, ouvrez **Settings → MCP servers → Add server**, choisissez **Streamable HTTP**, collez la même URL, enregistrez et sélectionnez **Restart**, puis **Authenticate** à côté de Customermates et approuvez l’accès (aide OpenAI, vérifiée le 24 novembre 2026).

### ChatGPT peut-il utiliser une clé API à la place d’OAuth ? [#chatgpt-with-an-api-key]

Oui. Ajoutez le connecteur de la même façon, mais authentifiez-vous avec un en-tête :

<Steps>
<Step title="Créer une clé">
Dans Customermates, ouvrez [Clés API et connecteurs](app:settings/api-keys), cliquez sur **Ajouter** et choisissez **Clé API standard**. Copiez aussitôt la chaîne de 64 caractères. Elle n’est affichée qu’une fois. Créer une clé demande **Créer** sur la ligne **API et webhooks** de votre rôle, et la page elle-même demande **Accès en lecture** **Tous** sur cette ligne ; le rôle intégré **Administrateur** a les deux. Voir [Clés API](/docs/api-keys).
</Step>
<Step title="S’authentifier avec un en-tête">
Dans le formulaire du connecteur, réglez **Authentication: Header**, **Header name: `x-api-key`**, **Header value :** votre clé.
</Step>
</Steps>

Enregistrez. ChatGPT atteint le serveur et liste chaque outil. Customermates vérifie la clé à chaque requête : avec une clé erronée, tronquée, expirée ou supprimée, le serveur répond HTTP `401` avec un en-tête `WWW-Authenticate` et rien n’est listé, créez donc une nouvelle clé.

## Que montre l’écran de consentement ? [#sign-in-and-approve]

Le connecteur ouvre une fenêtre Customermates :

<Steps>
<Step title="Se connecter">
Ou vous êtes déjà connecté.
</Step>
<Step title="Lire ce qui est autorisé">
L’écran de consentement, intitulé **Autoriser … à utiliser votre compte Customermates**, nomme l’application qui se connecte, liste ce qu’elle demande (comme **Confirmer votre identité**, **Lire votre profil de base**, **Lire votre adresse e-mail** et **Rester connecté en votre absence**) et affiche **Destination de la connexion** avec l’hôte auquel l’accès sera envoyé. Il liste aussi les espaces de travail que l’application peut utiliser, chacun avec son nom et votre rôle dans cet espace, et une dernière ligne, **Nouveaux espaces de travail qu’elle crée pour vous**. Il n’y a aucun espace de travail à choisir : la connexion les couvre tous.
</Step>
<Step title="Approuver">
Cliquez sur **Approuver**, ou sur **Refuser** pour refuser.
</Step>
</Steps>

Vous revenez à votre IA, connectée, avec la liste des outils Customermates.

Un espace de travail que l’application ne peut pas utiliser est listé avec la raison à la place : votre demande pour le rejoindre attend une approbation, votre accès est désactivé, votre rôle n’a pas **Accès en lecture** **Tous** sur **API et webhooks**, l’espace de travail n’a pas d’abonnement actif, ou des conditions mises à jour doivent être acceptées. Approuver fonctionne alors quand même, et aussi quand vous n’avez pas encore d’espace de travail : une connexion sans aucun espace de travail peut aussi approuver et, sur le cloud, accepte les conditions sur l’écran de consentement. Sur le cloud, votre IA peut ensuite créer le premier espace de travail pour vous.

Le connecteur accepte n’importe quel client : l’écran de consentement est donc la barrière. N’approuvez qu’une connexion que vous avez lancée vous-même, et cliquez sur **Refuser** pour tout ce que vous n’avez pas lancé. Se connecter via OAuth ne demande pas de clé API, mais dans chaque espace de travail votre rôle doit avoir **Accès en lecture** **Tous** sur **API et webhooks**, comme pour toute connexion MCP ; un espace de travail où ce droit manque est listé comme un espace que l’application ne peut pas utiliser.

## Combien de temps la connexion reste-t-elle valide ? [#it-syncs-and-stays-connected]

- Ajoutez-la une fois sur Claude web et elle apparaît aussi sur **le bureau et le mobile**. La connexion est liée à votre compte Claude, pas à un appareil.
- Elle se renouvelle en arrière-plan. Utilisez-la dans n’importe quelle fenêtre de 30 jours et vous ne réautorisez jamais ; restez inactif plus longtemps et vous approuvez à nouveau une fois.
- Chaque appel s’exécute au nom de l’utilisateur Customermates qui a approuvé, avec les permissions de son rôle dans l’espace de travail que l’appel nomme. Les clés API fonctionnent de la même façon : elles héritent des permissions de l’utilisateur propriétaire dans l’espace de travail où elles ont été créées, et il n’y a pas de portée par clé.
- L’espace de travail est choisi à chaque appel, pas une fois pour toutes. Chaque outil accepte un argument facultatif `workspace`, le slug ou l’id de l’espace de travail. Avec un seul espace de travail que la connexion peut utiliser, un appel sans cet argument utilise celui-là. Avec plusieurs, un appel sans lui est refusé avec la liste de vos espaces de travail et la demande de passer `workspace`, de sorte que rien n’atterrit par défaut dans le mauvais espace de travail. Voir [comment un agent choisit l’espace de travail](/docs/mcp#choosing-the-workspace) et [Espaces de travail](/docs/app-workspaces#which-workspace-do-api-keys-and-connections-use).
- Si cet utilisateur est réglé sur **Inactif** dans un espace de travail, chaque appel qui le nomme et lit ou modifie des données de l’espace de travail échoue avec « Your user account is inactive. Contact a workspace administrator. » jusqu’à ce qu’un membre ayant **Modifier** sur **Utilisateurs et rôles** le remette sur **Actif**.

## Que tester en premier ? [#try-your-first-prompt]

Le serveur envoie ses instructions à votre IA lors de la connexion : le client dispose donc déjà du flux de travail et des règles de sécurité. Dans les clients qui prennent en charge les prompts MCP (comme Claude), vous pouvez aussi lancer le prompt intégré `get-started` pour un démarrage personnalisé : votre nom, votre rôle et un premier résumé de votre espace de travail.

- *« Affichez les dix derniers contacts que j’ai créés. Y en a-t-il sans adresse e-mail ? »*
- *« Créez un contact pour Jane Doe chez Initech, reliez-le à l’organisation Initech et ouvrez une affaire pour 12 heures de conseil. »*
- *« Réglez le champ Statut de l’affaire Acme sur Gagnée et ajoutez une note indiquant que le contrat a été signé aujourd’hui. »*
- *« Quelles conversations clients attendent ma réponse ? Rédigez une réponse à la plus ancienne et enregistrez-la comme brouillon. »*

Le prompt de réponse demande un canal connecté sur Customermates Cloud à partir de Pro ; le brouillon attend dans la conversation que vous le relisiez et l’envoyiez.

Chaque espace de travail définit ses propres types d’enregistrements, comme les contacts, les affaires ou les tâches, et des champs comme l’étape d’une affaire ou la priorité d’une tâche sont aussi configurés par espace de travail. Demandez à votre IA d’appeler `discover_record_types` et `get_record_model` pour voir les champs concernés et les valeurs autorisées avant d’écrire.

## Confirmer les appels d’outils : lesquels puis-je toujours autoriser ? [#confirming-tool-calls]

Customermates n’interrompt jamais un appel d’outil pour demander une confirmation ; c’est votre client qui le fait, et vous le contrôlez à cet endroit. Dans Claude : **Customize → Connectors → Customermates**, puis réglez chaque outil (ou le groupe en lecture seule) sur *Always allow* ou *Ask*.

- Les lectures (`get_*`, `list_*`, `search_*`) portent l’indicateur de lecture seule, vous pouvez donc les autoriser sans risque.
- Les outils qui peuvent supprimer portent l’indicateur destructif et indiquent `IRREVERSIBLE`.
- Les outils qui ne font que créer, modifier ou envoyer ne portent aucun des deux indicateurs ; les outils fusionnés avec une action de suppression, comme `manage_webhooks`, portent l’indicateur destructif, tout comme `manage_team`, dont `remove_member` révoque l’accès d’un membre. Parmi les outils sans indicateur figurent `send_email`, `send_chat_message`, `request_support`, `manage_social_relations`, `publish_social_post` et `comment_on_social_post`, qui atteignent de vraies personnes, et `move_email_thread`, qui déplace du courrier dans la vraie messagerie.

Laissez sur *Ask* tout outil qui n’est pas en lecture seule. La liste complète figure dans le [catalogue d’outils MCP](/docs/mcp#tool-catalog).

## Que faire si la connexion échoue ? [#troubleshooting]

| Symptôme | Cause | Solution |
|---|---|---|
| « Couldn’t register with the sign-in service » (Claude) ou « Connector verification failed » (ChatGPT) | URL du serveur erronée ou inaccessible | Copiez à nouveau l’URL depuis Customermates ([quelle URL](#the-url)) ; c’est exactement `<BASE_URL>/api/v1/mcp`, avec l’adresse à laquelle vous ouvrez Customermates comme `<BASE_URL>` |
| L’IA dit qu’il lui faut un `workspace` | Vous appartenez à plusieurs espaces de travail et l’appel n’en a nommé aucun | Nommez l’espace de travail dans votre message, ou demandez à l’IA d’appeler `list_workspaces` et d’en choisir un |
| Un espace de travail est refusé comme inutilisable | Votre demande pour le rejoindre attend, votre accès est désactivé, votre rôle n’a pas **Accès en lecture** **Tous** sur **API et webhooks**, l’espace de travail n’a pas d’abonnement actif, ou des conditions mises à jour attendent | Corrigez la raison que montre `list_workspaces`, par exemple en demandant à un administrateur de vous approuver ou d’accorder la permission ; aucune reconnexion n’est nécessaire |
| Une clé API est refusée pour un autre `workspace` | Une clé API reste liée à l’espace de travail où elle a été créée | Créez une clé dans l’espace de travail où vous voulez travailler ; une clé n’atteint jamais deux espaces de travail |
| Le connecteur ne liste aucun outil et le serveur répond HTTP `401` (ChatGPT avec un en-tête) | La valeur de `x-api-key` est erronée, tronquée, expirée ou supprimée | Créez une nouvelle clé sous [Clés API et connecteurs](app:settings/api-keys) et collez les 64 caractères en entier |
| Chaque appel qui lit ou modifie des données de l’espace de travail indique « Your user account is inactive. Contact a workspace administrator. » | Votre utilisateur Customermates a été réglé sur **Inactif** | Un membre ayant **Modifier** sur **Utilisateurs et rôles** vous remet sur **Actif** sous [Membres](app:settings/members) |
| Pas d’option « Add custom connector » | Formule gratuite | ChatGPT demande une formule payante ; Claude Free autorise un connecteur personnalisé, supprimez donc d’abord l’autre. Voir [la méthode CLI](/docs/connect-cli) |
| Approuvé mais rien ne se connecte | Vous avez approuvé depuis un autre compte | Connectez-vous au bon compte Customermates, puis réessayez |
| « Tool not found » | Cache du connecteur périmé | Supprimez le connecteur et ajoutez-le de nouveau |
| Le serveur rejette la mise à jour d’une relation | L’ID ou le point d’accès de la relation est manquant ou inaccessible | Demandez à l’agent de lire `get_record_model`, puis d’utiliser `mutate_crm_record` avec `link` ou `unlink` |
| Champ de sélection rejeté | Valeur absente de la liste d’options du champ | Demandez à l’agent d’appeler d’abord `get_record_model` |
| Un outil de messagerie, de calendrier ou de réseaux sociaux est refusé avec un message de formule | L’espace de travail n’a pas de formule avec messagerie (Starter, auto-hébergé, ou ni abonnement actif ni essai) | Sur le cloud, un membre ayant **Modifier** sur **Entreprise** choisit Pro ou supérieur sous [Facturation](app:settings/billing). Les instances auto-hébergées n’ont pas de messagerie ; utilisez Customermates Cloud pour ces outils |

## Sur une formule gratuite ou en ligne de commande ? [#on-a-free-plan-or-in-a-cli]

Dans ChatGPT, les règles du compte et de l’espace de travail décident des serveurs MCP personnalisés (Claude Free en autorise un), et les clients en ligne de commande et les éditeurs n’utilisent pas du tout le flux du connecteur. Les deux s’authentifient plutôt avec une clé API : voir [CLI et éditeurs](/docs/connect-cli). Claude Desktop sur une formule gratuite peut utiliser la [solution de repli par fichier de configuration](/docs/connect-cli#claude-desktop-config-file).

## Grok et Grok Bot [#grok-bot]

**Conversation Grok :** ouvrez [grok.com/connectors](https://grok.com/connectors), cliquez sur **New Connector**, choisissez **Custom** et collez l’URL ([quelle URL](#the-url)). Grok ouvre une fenêtre Customermates : connectez-vous et cliquez sur **Approuver**. Sur Grok Business et Enterprise, un administrateur de l’équipe ajoute d’abord le connecteur dans la console xAI.

**Grok Bot :** dans **Connect apps**, choisissez **Add a custom connector**, saisissez le nom Customermates, choisissez le type **Remote HTTPS** et collez l’URL comme **Server URL**. Ajoutez l’en-tête HTTP `x-api-key` avec une clé API standard ([clés API](/docs/api-keys)), puis choisissez **Add plugin**. Si vous préférez, Grok Bot peut aussi travailler dans Customermates via son navigateur.

Dans Customermates, [Clés API et connecteurs](app:settings/api-keys) → **Ajouter** → **Grok** affiche l’URL avec un bouton de copie. Sources : le [guide officiel des connecteurs Grok](https://docs.x.ai/grok/connectors) et le [guide officiel de Grok Bot](https://docs.x.ai/grok-bot/computer-and-apps), vérifiés le 24 novembre 2026.

## Langdock [#langdock]

Dans Langdock, ajoutez une intégration MCP et collez l’URL ([quelle URL](#the-url)). Comme méthode d’authentification, choisissez **OAuth 2.0 (Dynamic Client Registration)**, enregistrez et connectez. Une fenêtre Customermates s’ouvre : connectez-vous et cliquez sur **Approuver**. Langdock liste les outils Customermates, et vous choisissez ceux qu’il peut utiliser.

Langdock bloque par défaut les adresses réseau privées et internes, donc une instance auto-hébergée a besoin d’une adresse HTTPS publique. Dans Customermates, [Clés API et connecteurs](app:settings/api-keys) → **Ajouter** → **Langdock** affiche l’URL avec un bouton de copie. Source : le [guide MCP officiel de Langdock](https://docs.langdock.com/en/using-langdock/guides/integrations/mcp/mcp), vérifié le 24 novembre 2026.
