Met een runner draaien jouw agentstappen met je eigen Claude Code, Codex of Gemini CLI op je eigen machine. Het is een klein programma, `customermates-runner`, dat je werkruimte om jouw agenttaken vraagt, de CLI start waarin je bent ingelogd, terugstuurt wat de CLI doet als transcript en het resultaat meldt. Je CLI-login blijft op je machine: Customermates ontvangt hem nooit. Runners werken op Customermates Cloud en op zelfgehoste instanties.

Je beheert runners onder **Instellingen**, **Agents**, in de kaart **Runners**. Voor het toevoegen en intrekken van een runner heb je dezelfde rolrechten nodig als voor [API-sleutels](/docs/api-keys).

## Wat doet een runner? [#what-does-a-runner-do]

Elke 60 seconden meldt hij de werkruimte de naam van zijn machine en welke CLI's hij kan starten, met hun versies. Daartussen houdt hij maximaal 25 seconden een verzoek open om de volgende wachtende taak op te halen, en vraagt daarna meteen opnieuw. Een runner voert alleen de taken uit van het lid dat hem heeft toegevoegd: de agentstappen van de automatiseringen waarvan dat lid de eigenaar is. Hij bevestigt elke taak aan de werkruimte voordat hij de CLI start. Voor een taak schrijft hij een tijdelijke MCP-configuratie met het endpoint `<BASE_URL>/api/v1/mcp` en de sleutel van die taak, start hij de CLI met de prompt van de taak in een lege tijdelijke map, stuurt hij elke stap van het werk van de CLI terug als transcriptgebeurtenis en verwijdert hij de configuratie zodra de CLI klaar is. Daarna wacht hij op de volgende taak.

De CLI werkt als jij, het lid dat de runner heeft toegevoegd, met jouw rechten in deze werkruimte. Ze gebruikt de tools van je werkruimte via [MCP](/docs/mcp) met een sleutel die bij die ene taak hoort. De sleutel werkt alleen in je werkruimte, via het MCP-endpoint `<BASE_URL>/api/v1/mcp`, en alleen zolang de taak loopt. Hij staat hooguit 25 toolaanroepen toe en weigert de aanroepen waarvoor in de chat jouw goedkeuring nodig zou zijn, zoals records verwijderen of rollen wijzigen. Hij weigert ook pagina's van de kennisbank aan te maken, te wijzigen of te verwijderen. Bevat de opdracht van de stap tekst van buiten de werkruimte, dan weigert hij ook e-mails of chatberichten te versturen, connectieverzoeken te versturen en webhooks en routines aan te maken, te wijzigen of te starten, zoals beschreven onder [Wat mag een agentstap doen?](/docs/app-agents#what-may-an-agent-step-do).

## Wat heeft hij nodig? [#what-does-it-need]

- Node 24, of Docker.
- Claude Code, Codex of Gemini CLI, geïnstalleerd en ingelogd op die machine. Zonder CLI meldt de runner er geen en neemt hij geen taken aan. Zolang geen van jouw runners een CLI heeft gemeld, wacht een agentstap die op je eigen runner draait niet: hij mislukt meteen met "Je hebt nog geen runner die klaar is. Runners zijn persoonlijk: elk lid voegt een eigen runner toe."
- Een netwerkverbinding van die machine naar het adres van je Customermates. De runner doet alleen uitgaande verzoeken: hij werkt achter een firewall en heeft geen open poort nodig.

## Hoe voeg ik een runner toe en start ik hem? [#how-do-i-add-a-runner]

1. Open **Instellingen**, **Agents** en klik op **Runner toevoegen**. Geef hem een naam waaraan je de machine herkent.
2. Kopieer het token. Het wordt één keer getoond en begint met `cmr_`. Behandel het als een wachtwoord: wie het heeft, kan jouw runnertaken in deze werkruimte ophalen.
3. Start de runner op die machine, met Node:

```bash
CUSTOMERMATES_RUNNER_TOKEN=cmr_... npx customermates-runner --url https://crm.example.com
```

of met Docker, waarbij je de loginmap van je CLI koppelt zodat die ingelogd blijft:

```bash
docker run -d --restart unless-stopped \
  -e CUSTOMERMATES_URL=https://crm.example.com \
  -e CUSTOMERMATES_RUNNER_TOKEN=cmr_... \
  -v "$HOME/.claude:/home/node/.claude" \
  -v "$HOME/.claude.json:/home/node/.claude.json" \
  ghcr.io/customermates/runner
```

Het adres is dat waarop je Customermates opent; op een zelfgehoste instantie is het je eigen `BASE_URL`. Het kan ook uit `CUSTOMERMATES_URL` komen. Geef de runner zijn token in de variabele `CUSTOMERMATES_RUNNER_TOKEN`, of in een bestand dat alleen jouw account kan lezen, opgegeven met `--token-file` of `CUSTOMERMATES_RUNNER_TOKEN_FILE`. Geef het niet mee als argument: een opdrachtregel is zichtbaar voor elke gebruiker van de machine. Op macOS bewaart Claude Code de login in de Sleutelhanger, dus de gekoppelde map brengt geen login in de container: geef `ANTHROPIC_API_KEY` mee, of een token uit `claude setup-token` in `CLAUDE_CODE_OAUTH_TOKEN`. Handige opties:

- `--client claude`, `codex` of `gemini` kiest de CLI die de taken uitvoert. Standaard is dat de eerste die hij vindt.
- `--workdir <map>` voert de CLI in die map uit. Standaard krijgt elke taak een lege tijdelijke map.
- `--permission-mode <modus>`, `--allowed-tools <tools>` en `--setting-sources <lijst>` bepalen wat Claude Code zonder te vragen mag doen. Standaard zijn alleen de tools van je werkruimte toegestaan en worden je eigen Claude Code-instellingen niet geladen.
- `--allow-shell` laat Codex shellopdrachten uitvoeren in zijn alleen-lezen sandbox. Standaard heeft Codex geen shell.

De runner schrijft zijn logs naar de standaarduitvoer en drukt zijn token nooit af.

## Wat stuurt de server, en wat stuurt hij nooit? [#what-is-sent]

De server stuurt de prompt van de taak, of buitenstaanders die prompt kunnen beïnvloeden, het MCP-endpoint `<BASE_URL>/api/v1/mcp` en de sleutel van de taak. Wanneer de runner de taak bevestigt, laat de server weten hoe lang de taak mag lopen. Hij stuurt nooit een geheim van de werkruimte, een providersleutel of een taak van een ander lid. De sleutel bereikt alleen deze werkruimte, alleen als jij, en alleen zolang de taak loopt: de server weigert hem voordat de runner de taak heeft bevestigd en vanaf het moment dat de taak klaar, verlopen of geannuleerd is.

De runner stuurt nooit je CLI-login, je bestanden of je omgeving. Hij stuurt de machinenaam, de CLI's die hij kan starten, de transcriptgebeurtenissen (wat de agent schreef, elke toolaanroep met een korte samenvatting van de argumenten en elk toolresultaat, zonder tokens) en het resultaat. Transcripten worden bij de taak bewaard: laat een CLI dus geen geheimen afdrukken die niet zichtbaar mogen zijn. De werkruimte bewaart de laatste 200 gebeurtenissen van een taak, dus een langere uitvoering toont haar meest recente stappen.

Een prompt die buitenstaanders kunnen beïnvloeden, bijvoorbeeld een met een formulierinzending, een binnenkomende webhook of de naam van een record, is in de taak gemarkeerd. De runner hult hem in dezelfde omlijsting als de MCP-server: de tekst is data, geen instructie, en een verzoek erin om het gedrag van de agent te veranderen wordt gemeld, niet opgevolgd.

## Waar kan de CLI op mijn machine bij? [#what-can-it-reach]

De CLI draait onder het account dat de runner heeft gestart. Een tekst als data presenteren verkleint de kans dat een model hem opvolgt, maar neemt die kans niet weg. Wat een misleide CLI zou kunnen doen, wordt begrensd door de sleutel van de taak, hierboven beschreven, en door deze standaardinstellingen:

- Claude Code mag alleen de tools van je werkruimte aanroepen, laadt alleen de MCP-server van de taak en laadt je eigen instellingen niet. Zijn bestandstools blijven in de lege map van de taak.
- Codex draait zonder je eigen configuratie en zonder shell. Start je de runner met `--allow-shell`, dan draaien opdrachten in de alleen-lezen sandbox van Codex, die schrijven tegenhoudt maar lezen niet: een opdracht kan elk bestand lezen dat jouw account kan lezen, en de tools van je werkruimte kunnen die inhoud daarna in een record schrijven. Gebruik dit alleen op een machine, in een container of onder een account waar verder niets op staat.
- Gemini CLI wordt gestart met alleen de MCP-server van je werkruimte toegestaan. Zijn ingebouwde tools volgen je eigen Gemini-instellingen.
- Het runnertoken en je CLI-logins staan in jouw account op die machine. Een CLI die je opdrachten laat uitvoeren, kan ze lezen. Draai de runner voor een strikte scheiding met Docker of onder een eigen gebruikersaccount.

## Wat gebeurt er met een taak? [#what-happens-to-a-job]

Een taak wacht in de wachtrij tot een runner van de eigenaar hem oppakt. Een opgepakte taak die de runner niet binnen een minuut bevestigt, bijvoorbeeld omdat hij op dat moment werd gestopt, gaat binnen enkele minuten terug naar de wachtrij. Een taak die geen runner binnen 15 minuten ophaalt, eindigt als verlopen. Een bevestigde taak mag net geen tien minuten lopen; dan stopt de runner de CLI en alles wat die heeft gestart, en eindigt de taak als verlopen. Een bevestigde taak wordt nooit een tweede keer uitgevoerd: verdwijnt de runner terwijl de taak loopt, dan eindigt de taak als verlopen enkele minuten nadat zijn tien minuten voorbij zijn. Faalt de CLI, dan eindigt de taak als mislukt, met de reden. Wordt een runner ingetrokken, dan eindigen zijn taken als geannuleerd. Een taak die al klaar, verlopen of geannuleerd is, kan niet meer worden gewijzigd door een late melding van een runner, en de runner stopt zijn CLI wanneer de werkruimte dat zegt.

In één werkruimte kunnen meerdere runners werken. De taken van een lid gaan naar de runners van dat lid, en elke taak naar precies één ervan. Een agentstap die een runner noemt, wacht op die runner.

## Hoe zie ik of een runner online is? [#is-it-online]

De kaart **Runners** toont per runner de machine, de CLI's die hij kan starten en wanneer hij voor het laatst is gezien, met een van vier statussen: **Online** als hij in de laatste twee minuten is gezien, **Offline** als eerder, **Nooit verbonden** als hij zich nog niet heeft gemeld, en **Ingetrokken**. De kaart werkt zichzelf elke 30 seconden bij.

Wachten jouw agenttaken en is er al 10 minuten geen runner van jou gezien die ze kan oppakken, dan krijg je een melding van het soort **Automatiseringsmeldingen**, één keer voor elke keer dat de runner wegviel, met een link naar de kaart **Runners**.

## Hoe trek ik een runner in? [#how-do-i-revoke-a-runner]

Klik bij de runner op **Intrekken** en bevestig. De runner kan dan geen taken meer ophalen: zijn volgende verzoek wordt geweigerd en het programma stopt. De taken die hij uitvoert, en de taken die op precies deze runner wachten, eindigen als geannuleerd, en hun sleutels werken meteen niet meer. Intrekken kan niet ongedaan worden gemaakt. Wil je de machine opnieuw gebruiken, voeg dan een nieuwe runner toe en start hem met het nieuwe token. Trek een runner meteen in als zijn token uitlekt. Een runner wordt ook ingetrokken wanneer het lid dat hem heeft toegevoegd de werkruimte verlaat of wordt gedeactiveerd. Een lid dat door het Free-abonnement is gepauzeerd, houdt zijn runners: tijdens de pauze worden de verzoeken van de runner geweigerd en stopt het programma, en zodra een betaald abonnement het lid terugbrengt, werkt hetzelfde token weer.

## Voor agents [#for-agents]

Runners praten met de werkruimte via REST met `Authorization: Bearer cmr_...`, het token dat bij het toevoegen van de runner werd getoond. Een runnertoken bereikt alleen deze vijf eindpunten, beschreven in de [API-referentie](/docs/openapi):

- `POST /api/v1/runner/heartbeat` meldt de machine en de CLI's die de runner kan starten.
- `POST /api/v1/runner/jobs/claim` wacht maximaal 25 seconden en antwoordt 200 met een taak van het lid van de runner, het pogingnummer en de MCP-toegang, of 204 als er geen kwam.
- `POST /api/v1/runner/jobs/{id}/start` bevestigt de opgepakte poging, start de taak en antwoordt hoeveel seconden ze mag lopen.
- `POST /api/v1/runner/jobs/{id}/events` voegt transcriptgebeurtenissen van die poging toe en antwoordt 409 zodra de taak gesloten is.
- `POST /api/v1/runner/jobs/{id}/result` meldt `succeeded`, `failed` of `timedOut` voor die poging met het eindantwoord en, als de CLI ze meldt, de verbruikte tokens.

Een ingetrokken token, een runner waarvan het lid de werkruimte heeft verlaten, is gedeactiveerd of door het Free-abonnement is gepauzeerd, en een werkruimte die wordt verwijderd antwoorden 401.

## Veelgestelde vragen [#frequently-asked-questions]

<Faq>
<FaqItem question="Krijgt Customermates mijn login van Claude Code, Codex of Gemini?">
Nee. De runner start de CLI die je zelf hebt geïnstalleerd en waarin je zelf bent ingelogd, op je machine. De werkruimte stuurt er alleen de prompt en een sleutel voor die ene taak naartoe. De sleutel werkt alleen in je werkruimte, via het MCP-endpoint `<BASE_URL>/api/v1/mcp`.
</FaqItem>
<FaqItem question="Kan iemand buiten mijn team mijn runner iets laten doen?">
Alleen via een prompt die jij hebt ingesteld. Bevat een prompt tekst van buitenstaanders of uit een record, dan markeert de taak dat en presenteert de runner hem als data, niet als instructie. Een model kan zich door zulke tekst toch laten misleiden. Wat het dan zou kunnen doen, is beperkt: de sleutel van de taak handelt als jij, staat hooguit 25 toolaanroepen toe, weigert wat jouw goedkeuring nodig heeft en werkt niet meer zodra de taak eindigt. Standaard mag Claude Code alleen de tools van je werkruimte gebruiken en heeft Codex geen shell: verruim dat alleen op een machine die je vertrouwt.
</FaqItem>
<FaqItem question="Kan de runner van een collega mijn taken uitvoeren?">
Nee. Een runner voert alleen de taken uit van het lid dat hem heeft toegevoegd, dus de machine van een ander lid krijgt nooit een sleutel die als jij handelt. Voeg je eigen runner toe om jouw agentstappen op een runner te laten draaien.
</FaqItem>
<FaqItem question="Wat als mijn machine uitstaat?">
Jouw taken wachten tot 15 minuten in de wachtrij en eindigen dan als verlopen. Na 10 minuten zonder een runner van jou krijg je een melding.
</FaqItem>
<FaqItem question="Kan ik de runner op een server draaien?">
Ja. Elke machine met Node 24 of Docker, één ingelogde CLI en een verbinding met het adres van je Customermates werkt, bijvoorbeeld een virtuele machine die altijd aanstaat.
</FaqItem>
</Faq>
