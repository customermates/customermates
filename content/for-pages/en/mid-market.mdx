## What a mid-market CRM has to do

A **mid-market CRM** (often written *midmarket CRM*) serves companies that are too large for a single shared pipeline and too lean for an enterprise implementation program: typically several teams, dozens to a few hundred CRM users, an ERP or accounting system that must stay the system of record for money, and no dedicated CRM administration department.

Those companies need a specific set of things from a CRM:

- **Separation between teams** without building a permission project.
- **Traceability**: who changed which record and when.
- **Numbers leadership trusts**: pipeline value by stage and owner, weighted by realistic probabilities.
- **Integration** with the ERP, accounting, email and data tools that already run the business.
- **Room to grow** without renegotiating licences for every new feature.

If you are still deciding whether a CRM is the right step, start with [what a CRM is](/blog/what-is-crm). This page explains how Customermates covers the mid-market list above and where it deliberately stops.

## How Customermates fits mid-market teams

### Roles per team and resource

Roles define read and manage access per resource: contacts, organizations, deals, services, tasks, inbox messages, API and webhooks, and more. Read access can be limited to records a person is assigned to, so sales, account management and service each see what they own. Permissions are per resource and action; there is no field-level permission model, which keeps configuration understandable for a small operations team.

### Audit log included in every plan

Changes to CRM records and the workspace configuration around them are recorded in the audit log, visible to roles with audit permission. It is part of the open-source core, so every cloud plan and the self-hosted edition include it. The audit log is not an immutable archive, and it does not cover inbox content, authentication or API keys.

### Pipelines and weighted values leadership can read

Deal stage is a configurable single-select field, and each option can carry a weight. Customermates uses those weights to calculate weighted deal values and weighted pipeline totals, and dashboards show counts, values and weighted totals. Group any list by owner, organization, stage or a custom field to break the pipeline down per team. These are deterministic calculations from your own weights, not predictive forecasts; for deeper analysis, read the data through REST into your BI tool. See [pipeline management](/features/pipeline).

### Integration with ERP and accounting

The REST API is versioned under `/api/v1` with an OpenAPI document, and [webhooks](/features/workflow-automation) cover [[derived.webhooks.events.total]] event types across records and messaging. Common mid-market patterns: an accepted deal creates an order in the ERP, invoice status flows back into a custom field, and customer master data stays aligned in both directions. You run those flows in your own integration service or through the n8n community node. The [CRM and ERP integration guide](/blog/crm-erp-integration) covers the patterns.

### Records in and out as Excel workbooks

Import and export run per record type as XLSX workbooks, scoped to what the user may read and to the current view. That covers the initial migration of contacts, organizations and deals and regular hand-offs to finance or management, alongside the API.

### One inbox across teams

On Customermates Cloud from Pro, the [unified inbox](/features/unified-inbox) brings email, LinkedIn, WhatsApp, Instagram and Telegram into the CRM. Business adds shared accounts, so a team mailbox can be visible to everyone who needs it, and [[commercial.entitlement.business.includedAccountsPerUser]] connected accounts per user. See [customer communication management](/blog/customer-communication-management) for how teams organize states and ownership.

### AI through MCP and the Mate assistant

External AI clients such as Claude or ChatGPT connect through [MCP](/docs/mcp) and use [[derived.mcp.tools.total]] tools within the permissions of the connected user. On Customermates Cloud, the Mate assistant works inside the app and asks for a fresh approval before destructive actions and sends; routines let it run saved instructions on a schedule or when a record changes.

## Where Customermates stops

Mid-market buyers should know the boundaries before a pilot:

- no SSO or SAML today; single sign-on is a contracted Enterprise item that is not built yet;
- no field-level permissions and no shared team views; saved views are personal;
- no predictive forecasting, lead scoring or data enrichment;
- no quotes, invoicing or telephony;
- self-hosted installations use the Starter feature set without the inbox or Mate.

If single sign-on or field-level security is mandatory today, an enterprise suite is the safer choice. See the [Salesforce](/compare/salesforce-alternative), [Microsoft Dynamics](/compare/microsoft-dynamics-alternative) and [HubSpot](/compare/hubspot-alternative) comparisons for those trade-offs.

## A mid-market rollout in five steps

1. **[Create a trial workspace](/auth/signup)** with the first [[commercial.trial.days]] days free.
2. **Model roles** for each team and decide who reads all records and who only reads assigned ones.
3. **Import a real slice of data** from XLSX: one team's organizations, contacts and open deals.
4. **Connect one integration**, for example deal won to ERP order, through webhooks and the REST API.
5. **Review the audit log and dashboards** with the people who will depend on them, then extend to the next team.

## Frequently asked questions

<Faq>
<FaqItem question="What is a mid-market CRM?">
A mid-market or midmarket CRM is built for companies with several teams and dozens to hundreds of users that need separation between teams, traceable changes, reliable pipeline numbers and integration with existing systems, without the implementation effort of an enterprise suite.
</FaqItem>

<FaqItem question="Does Customermates have an audit log?">
Yes. Changes to CRM records and the surrounding workspace configuration are recorded and visible to roles with audit permission, on every cloud plan and in the self-hosted edition. It does not cover inbox content, authentication, API keys or saved views.
</FaqItem>

<FaqItem question="Does Customermates support SSO?">
Not yet. Single sign-on is a contracted Enterprise item that has not been built. If SSO is a hard requirement today, plan for it before a rollout.
</FaqItem>

<FaqItem question="Can Customermates integrate with our ERP?">
Yes, through the REST API and webhooks, operated by your integration service or the n8n community node. Typical flows create ERP orders from won deals and write invoice status back to the CRM.
</FaqItem>

<FaqItem question="How do we migrate from our current CRM?">
Export your records to Excel and import them as XLSX workbooks, one record type at a time, or move them through the REST API. Test with one team's data first.
</FaqItem>

<FaqItem question="Can we self-host a mid-market CRM?">
Yes. The open-source core runs as the application and PostgreSQL with Docker Compose. Self-hosted installations use the Starter feature set, without the unified inbox or Mate. See the [self-hosted CRM](/features/self-hosted) page.
</FaqItem>
</Faq>
